# mtval
A supplement to mcause
In the RISC-V architecture, `mtval` is short for the Machine Trap Value register; it is part of the RISC-V architecture definition and is used in the exception handling mechanism.

When a hardware-triggered exception occurs, such as a load access fault, store access fault, illegal instruction, etc., the `mtval` register is set to the relevant error value. Specifically:

- For load or AMO (atomic operation) access faults, `mtval` holds the address that caused the fault.
- For store access faults, `mtval` likewise holds the address of the attempted illegal store operation.
- For instruction-related exceptions (such as illegal instructions), `mtval` stores the address of the instruction that triggered the exception.

Programmers or the operating system can determine the specific cause of an exception by examining the contents of the `mtval` register, which is very important for debugging and exception handlers. In the privileged modes of the RISC-V architecture, different exception levels (such as Machine, Supervisor, User, etc.) have corresponding trap value registers; for example, in Supervisor mode, the similar registers might be `scause` and `sbadaddr`.

#  mstatus
xPIE holds the current xIE from before the trap executed; after the trap finishes, it is restored back to xIE
xPP holds the privilege level value before trapping into the current privilege x. The privilege before trapping into M can be M, U, or S, so two bits are used to represent these three states. The privilege before trapping into S can be U or S, so one bit is used; trapping into U can only come from U, so there is no need to save it, because what is restored after the trap finishes is the same as when the trap executed.
WPRI: when reading this register, ignore the value of this part; when writing this register, preserve the original value of this part (do not change it)

# Trap Initialization
Set the mtvec address to the entry address of your own exception handler

In the RISC-V architecture, `mtvec` is short for Machine Trap Vector Base Address Register. This register plays a core role in RISC-V processors; it determines where the processor should jump to execute the corresponding handler code when a hardware exception or interrupt occurs.

The structure of the `mtvec` register usually consists of two parts:
1. **Base Address**: stores a physical address; when an exception or interrupt occurs, the processor jumps to this address to execute the first instruction of the exception handler.

2. **Mode**:
   - **Direct Mode**: in this mode, the base address field directly points to the entry address of the exception handler.
   - **Vectored Mode**: in this mode, the base address field points to a fixed vector table, where each entry corresponds to a specific exception type. When an exception occurs, the processor indexes the corresponding handler address from the vector table based on the exception type.

# Trap Top Half (Completed by Hardware)
1. MIE is copied to MPIE, and MIE is cleared to 0
2. Set mepc, and set pc to mtvec (exception: after the exception handler finishes, the faulting instruction needs to be re-executed; interrupt: after the interrupt is handled, the next instruction is executed)
3. Set mcause and mtval
4. Set MPP, and the privilege enters M (no matter what trap it is, it first switches to machine mode)
. ![Image](/images/csdn/2024/csdn-137557314/image-009-4bb2fb89c9.png)
# Trap Bottom Half (Completed by Software)
1. Switch context
2. Call the corresponding handler function
3. Restore context
4. mret
