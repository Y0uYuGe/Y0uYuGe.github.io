#  volatile
int volatile vInt; When the value of a variable declared with volatile is required, the system always re-reads the data from its memory location, even if the instruction immediately before it just read data from that same location. And the data that is read is saved immediately

#  Leaking _environ to attack the stack
In libc there is a global variable called _environ, which stores the address of the current process's environment variables, i.e., some address on the stack.


# Vulnerability
_free_hook is disabled. malloc sizes range from 0x200 to 0x800, and the index is limited to within 15

# Exploitation
The sandbox disables execve

On Linux systems, the system("/bin/sh") function call leads to a series of system calls. system() is a C standard library function used to execute a command string — in this case, launching a shell. This function typically performs the following steps:

1. fork(): system() first calls fork() to create a new process. This is done through the fork() system call, which duplicates the current process, creating an almost identical child process.

2. execve(): In the child process, system() then calls execve() or another function from the exec family to execute the specified command. The execve() system call replaces the current process's image, data, and stack with the new program (in this case /bin/sh).

3. waitpid(): In the parent process, system() calls the waitpid() system call to wait for the child process to finish. waitpid() allows the parent process to collect the child process's exit status.

4. exit(): Once /bin/sh finishes executing, the child process terminates via the exit() system call, which sends a signal to the parent process indicating that the child process has ended.

# malloc and calloc
`calloc` and `malloc` are both functions in C for dynamic memory allocation, but there are some key differences between them:

1. **Initialization difference**:
   - `calloc` automatically initializes every bit of the allocated memory region to zero after allocation, meaning the allocated memory space is clean and all elements have an initial value of 0.
   - `malloc` only allocates memory without performing any initialization; the data in the allocated memory is undefined and may be random previous values (so-called "garbage data").

2. **Parameters and usage**:
   - `calloc` takes two parameters: the first is the number of elements to allocate, and the second is the size of each element (in bytes). This makes `calloc` well suited for allocating arrays, since it can allocate directly based on the element count and the size of a single element.
   - `malloc` takes only one parameter, the total memory size needed (in bytes). When using `malloc`, you need to manually calculate the total number of bytes required, and after allocation you may also need an extra initialization step (if you need zero-initialization or some other specific value).

# Approach (attacking _environ)
1. First allocate a 0x630-sized chunk0 and a 0x210-sized chunk1, then free the 0x630-sized chunk0, and use show to leak the libc address
2. Then consecutively allocate three 0x210-sized chunks 2, 3, and 4, which exactly occupy the location of the previous 0x630-sized chunk0
3. Then free 3 and 1, use edit after free to modify chunk0 to indirectly change chunk3's fd pointer to _environ, then allocate 0x210 twice (3 and 1) to get a heap chunk starting at the environ address; then show chunk1 to get the contents inside the environ address, which is the address of environ on the stack
4. Then free chunk 3 and 4 again, use edit after free to modify chunk0 to indirectly change chunk3's fd pointer to the stack address, then allocate 0x210 twice (3 and 4) to get a heap chunk starting at the stack address, and edit its contents to implement the ROP chain orw
