## Reverse engineering

```c
int __cdecl executeBrainfuck(char *code)
{
  struct instruction c; // [rsp+13h] [rbp-5h]

  HIBYTE(c.current_op_ptr) = 0;
  *(_DWORD *)&c.op = (unsigned __int8)*code;
  while ( c.current_op_ptr <= 255 )
  {
    if ( c.op == 'q' )
      return 0;
    if ( c.op <= 'q' )
    {
      if ( c.op == '@' )
      {
        data_ptr += *(unsigned int *)&code[c.current_op_ptr + 1];
        c.current_op_ptr += 5;
      }
      else if ( c.op <= '@' )
      {
        if ( c.op == '>' )
        {
          ++data_ptr;
          ++c.current_op_ptr;
        }
        else if ( c.op <= '>' )
        {
          if ( c.op == '+' )
          {
            data_ptr += 8;
            ++c.current_op_ptr;
          }
          else if ( c.op == '.' )
          {
            *data_ptr = code[c.current_op_ptr + 1];
            c.current_op_ptr += 2;
          }
        }
      }
    }
    c.op = code[c.current_op_ptr];
  }
  return 0;
}
```

A simplified Brainfuck interpreter implementation. Brainfuck is a minimalist programming language with only 8 instructions. This function `executeBrainfuck` takes a string as input, and the string contains Brainfuck code. Here is an explanation of the code:

1. The function uses a struct `instruction` to track the current instruction and its argument.

2. The main loop iterates over the input code string, processing one instruction at a time.

3. The supported instructions are:
   - 'q': exit the program
   - '@': move the data pointer by the specified offset
   - '>': move the data pointer one cell to the right
   - '+': increase the value of the current data cell by 8
   - '.': write the ASCII value of the next character into the current data cell

4. After each instruction executes, the instruction pointer `c.arg` moves accordingly.

5. The loop continues until it encounters a 'q' instruction or `c.arg` exceeds 255.

## Vulnerability
- data_ptr can be underflowed downward (it should also be possible to overflow it upward, but that would require an integer overflow first; since it is eight bytes and can be increased by at most an `unsigned int` each time, and the code size is limited, it is far from reaching an integer overflow)

Then there is an arbitrary high-address heap write primitive via data_ptr: `*data_ptr = code[c.current_op_ptr + 1];`

##  __errno_location and __throw_out_of_range


```cpp
v8 = __errno_location();
……
v10 = v8;
……
if ( *v10 == 0x22 || (unsigned __int64)(convert_bytes + 0x80000000LL) > 0xFFFFFFFF )
    std::__throw_out_of_range("stoi");
```

### Detailed explanation:

1. **`v8 = __errno_location();`**:
   - `__errno_location()` is a function that returns a pointer to the `errno` variable in Thread-Local Storage (TLS).
   - `errno` is a global variable used to indicate the error status of the last function call. Different threads have their own independent `errno`; `__errno_location()` can safely obtain the current thread's `errno` location in a multi-threaded environment.



2. **`if ( *v10 == 0x22 || (unsigned __int64)(convert_bytes + 0x80000000LL) > 0xFFFFFFFF )`**:
   - This line contains an `if` condition check with two conditions:
     1. **`*v10 == 0x22`**:
        - `*v10` dereferences the pointer `v10` to get the value of `errno`.
        - `0x22` is hexadecimal notation, equal to decimal `34`. Usually, `34` indicates an `ERANGE` error, meaning the value is out of range.
     2. **`(unsigned __int64)(convert_bytes + 0x80000000LL) > 0xFFFFFFFF`**:
        - `convert_bytes` is a variable. Assume it is an integer value.
        - `0x80000000LL` is a hexadecimal constant representing `2147483648` (a value of type `long long`).
        - After adding `0x80000000LL` to `convert_bytes`, the result is converted to an unsigned `__int64` type.
        - Check whether the result is greater than `0xFFFFFFFF` (i.e. `4294967295`), which is the maximum value of the `unsigned int` type.
  
3. **`std::__throw_out_of_range("stoi");`**:
   - If any of the above `if` conditions is true, `std::__throw_out_of_range("stoi");` is called.
   - `std::__throw_out_of_range` is a C++ standard library function used to throw a `std::out_of_range` exception, indicating the value is out of the allowed range.
   - `"stoi"` is the exception message, indicating the error occurred during the string-to-integer conversion (`stoi`).

## __errno_location-related operations


### Detailed analysis

1. **Save the original `errno` value**:
   ```cpp
   v8 = __errno_location();
   ```
   `__errno_location()` returns a pointer to `errno` and assigns it to `v8`. At this point `v8` is a pointer to the current thread's `errno` variable.

2. **Prepare to save the original `errno` value**:
   ```cpp
   v10 = v8;
   ```
   Assign the value of `v8` to `v10`, so that `v10` also points to `errno`.

3. **Save the low 32 bits of the `errno` value**:
   ```cpp
   LODWORD(v8) = *v8;
   ```
   `LODWORD` is usually a macro or inline function used to get the low 32 bits of a `long` or `long long` value. Here, it assigns `*v8` (i.e. the current value of `errno`) to the low 32 bits of `v8`.

4. **Reset `errno`**:
   ```cpp
   *v10 = 0;
   ```
   Set `errno` to `0` so that new errors can be detected when calling `strtol`.

5. **Save the original `errno` value**:
   ```cpp
   v17 = (int)v8;
   ```
   Convert `v8` (the low 32 bits of the original `errno`) to `int` and assign it to `v17`. At this point, `v17` holds the `errno` value from before the `strtol` call.

### Why is the above code executed?

- **Detect and handle `strtol` errors**:
  By setting `errno` to `0`, we can detect whether a new error occurred after calling `strtol`. If an error occurs during `strtol`, `errno` will be set to the appropriate error code.

- **Restore the original value of `errno`**:
  After checking the result of `strtol` and handling any possible errors, restore the original value of `errno` if no new error occurred. This is to ensure that the `errno` state from before the `strtol` call is not lost.

### Explanation of the example code

This code implements the call to `strtol` and its error handling through the following steps:

1. Save the current thread's `errno` value.
2. Set `errno` to `0` in order to detect new errors from `strtol`.
3. Call `strtol` to convert the string to a long integer.
4. Check the result of `strtol`:
   - If no characters could be converted, throw a `std::__throw_invalid_argument` exception.
   - If the conversion result is out of range or an `ERANGE` error occurred, throw a `std::__throw_out_of_range` exception.
5. Restore the original `errno` value (if no new error occurred).

Through these steps, the code ensures that after calling `strtol`, any errors can be correctly detected and handled, while the `errno` state from before the `strtol` call is not lost.

##  How the eBPF virtual machine works

The complete workflow of the eBPF virtual machine:

1. Write an eBPF program
2. Compile it into eBPF bytecode
3. Load the bytecode into the kernel
4. Verify the bytecode
5. JIT compilation
6. Execution


Example: a simple eBPF program that counts TCP SYN packets

1. Write the eBPF program (in C):

```c
#include <linux/bpf.h>
#include <linux/if_ether.h>
#include <linux/ip.h>
#include <linux/tcp.h>

SEC("socket")
int count_tcp_syn(struct __sk_buff *skb) {
    void *data = (void *)(long)skb->data;
    void *data_end = (void *)(long)skb->data_end;
    
    struct ethhdr *eth = data;
    if ((void *)eth + sizeof(*eth) > data_end)
        return 0;
    
    struct iphdr *ip = (void *)eth + sizeof(*eth);
    if ((void *)ip + sizeof(*ip) > data_end)
        return 0;
    
    if (ip->protocol != IPPROTO_TCP)
        return 0;
    
    struct tcphdr *tcp = (void *)ip + sizeof(*ip);
    if ((void *)tcp + sizeof(*tcp) > data_end)
        return 0;
    
    if (tcp->syn) {
        // 增加计数器
        // 这里简化了，实际应该使用 BPF_MAP 来存储计数
        __sync_fetch_and_add(&syn_count, 1);
    }
    
    return 0;
}
```

2. Compile it into eBPF bytecode:

Use the LLVM compiler to compile the C code into eBPF bytecode:

```
clang -O2 -target bpf -c syn_counter.c -o syn_counter.o
```

3. Load the bytecode into the kernel:

Use the bpf() system call or a higher-level library (such as libbpf) to load the bytecode into the kernel.

4. Verify the bytecode:

The kernel's eBPF verifier checks the bytecode to ensure:
- There are no infinite loops
- Memory accesses are safe
- It does not access uninitialized stack memory
- The program terminates normally

5. JIT compilation:

After verification passes, the eBPF JIT compiler converts the bytecode into native machine code. For example, on the x86_64 architecture, it might generate machine code like the following:

```
0:   55                      push   rbp
1:   48 89 e5                mov    rbp,rsp
4:   48 83 ec 08             sub    rsp,0x8
8:   48 8b 77 10             mov    rsi,QWORD PTR [rdi+0x10]
c:   48 8b 47 18             mov    rax,QWORD PTR [rdi+0x18]
...
```

6. Execution:

When a network packet arrives, the kernel calls this compiled machine code. It quickly checks each TCP packet, and if it is a SYN packet, increments the counter.
