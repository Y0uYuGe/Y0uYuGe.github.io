# Register msip
  ![ ](/images/csdn/2024/csdn-137965983/image-006-dfedc7a6e1.png)
  The RISC-V specification defines multiple processor modes, one of which is Machine mode, the highest privilege mode, used to implement core functions such as operating system kernels or hypervisors. In Machine mode, the processor provides a series of Memory-Mapped Control and Status Registers (CSRs), which can be accessed directly through memory addresses, just like ordinary memory regions.

`mip` is the Machine Interrupt Pending register, a CSR used to indicate which interrupt events are currently in the pending state. Among them, `mip.MSIP` is the Machine Software Interrupt Pending bit, specifically used to indicate whether a machine-level software interrupt request is waiting to be handled.

In the RISC-V architecture, when a hart (hardware thread) needs to send a software interrupt to another hart, it can initiate the interrupt request by writing 1 to the other hart's MSIP bit. MSIP maps to a bit on the MSIP register, and this register is mapped to memory, i.e., MSIP is memory-mapped, which means this bit can be read and written through memory access instructions (such as load/store instructions), thereby triggering or clearing the interrupt.

Specifically, when `mip.MSIP = 1`, it means there is a machine-level software interrupt pending; when `mip.MSIP = 0`, it means there is no such interrupt pending. In this way, the processor can support efficient interrupt communication and management at the hardware level.
