# Workflow
The files for qemu pwn challenges are similar to those of Linux kernel challenges: a launch script, a Linux kernel, a filesystem, and a patched qemu file are provided. Run the launch script to start the virtual machine using the qemu file given in the challenge attachment

The launch script usually adds a PCI device with a built-in vulnerability, also similar to kernel challenges, but the code implementing the device read/write operations is in the patched qemu file; you can search for function names in IDA to quickly locate the device read/write functions

The goal is to exploit a vulnerability in the device's operation functions to obtain a shell on the host machine of the docker environment and get the flag on the host

There's a TEA encryption ~~asked GPT~~, which encrypts the high 32 bits and low 32 bits of opaque->blocks[opaque->seek + (unsigned int)(addr >> 3)]

When opaque->mmio_read_part is 1, it returns the high 32 bits
When opaque->mmio_read_part is 0, it returns the low 32 bits
![Image](/images/csdn/2024/csdn-134677907/image-015-60b5c9483b.png)
v4 = opaque->seek + (unsigned int)(addr >> 3); if opaque->mmio_write_part is 0, it modifies opaque->blocks[v4] = (unsigned int)val;

![Image](/images/csdn/2024/csdn-134677907/image-016-b2f105decb.png)
Returns the values of different fields of opaque based on addr
![Image](/images/csdn/2024/csdn-134677907/image-017-b23a2e5dd2.png)
When addr == 8 and val <= 0x100, it sets opaque->seek = val; when addr > 8 and addr == 28, it sets opaque->r_seed = val and then calls `((__int64 (__fastcall *)(uint32_t *, __int64, uint64_t, _QWORD))opaque->rand_r)(
                   &opaque->r_seed,
                   28LL,
                   val,
                   *(_QWORD *)&size);` otherwise, if addr is not zero, it zeroes opaque->key



1.  d3dev_mmio_write and d3dev_mmio_read can write and read opaque->blocks[opaque->seek + (unsigned int)(addr >> 3)]
2. d3dev_pmio_write can assign opaque->seek, call opaque->rand_r (  &opaque->r_seed), zero opaque->key, and set opaque->memory_mode = val

void mmio_write(uint32_t addr, uint32_t value) {
    *((uint32_t*)(mmio_mem + addr)) = value;
}

uint64_t mmio_read(uint64_t addr) {
    return *((uint32_t *)(mmio_mem + addr));
}


uint32_t pmio_base = 0xc040;

void setup_pmio() {
    iopl(3);
}

void pmio_write(uint32_t addr, uint32_t value)
{
    outl(value, pmio_base + addr);

uint64_t pmio_read(uint32_t addr)

    return (uint64_t)inl(pmio_base + addr);

uint64_t encode(uint32_t high, uint32_t low) {

    uint32_t addr = 0xC6EF3720;

    for (int i = 0; i < 32; ++i) {
        high = high - ((low + addr) ^ (low >> 5) ^ (16 * low));
        low = low - (((high + addr) ^ (high >> 5) ^ (16 * high)));
        addr += 0x61C88647;
    }

    return (uint64_t)high * 0x100000000 + low;
}

        high += ((low + addr) ^ (low >> 5) ^ (16 * low));
    }
    return (uint64_t)high * 0x100000000 + low;
}
