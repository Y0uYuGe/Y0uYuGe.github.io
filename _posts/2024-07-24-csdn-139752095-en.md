# rsa
An RSA key pair usually consists of two parts: a public key and a private key. The public key can be safely distributed to anyone and is used to encrypt data or verify signatures. The private key must be kept secret and is used to decrypt data or generate signatures. In some cases, you may have a key object that contains only the public key, or one that contains both the public key and the private key.
# Handshake
The process of "decoding" a signature with the public key is actually the process of digital signature verification, which relies on the mathematical principles of public-key cryptographic algorithms. Here is why decoding a signature with the public key produces a result that matches the output of the hash algorithm:

1. **Generating the digital signature**:
   - When the client generates a digital signature, it first uses a secure hash function (such as SHA-256) to produce a hash of the data (for example, the public key itself or its hash). This hash is a digest of the original data; any tiny change to the data causes the hash to change dramatically.

2. **Encrypting the hash with the private key**:
   - Next, the client uses its own private key to encrypt this hash, producing the digital signature. In the RSA algorithm, this process essentially raises the hash to the power of the exponent and then takes the result modulo the modulus.

3. **Sending the data and the signature**:
   - The client sends the original data (the public key) together with the digital signature to the server.

4. **Verifying the digital signature**:
   - After receiving the data and the signature, the server first applies the same hash algorithm to the same data to generate a hash.
   - Then, the server uses the client's public key to try to "decrypt" the signature. In RSA, this means applying the inverse modular operation to the signature value (i.e., raising it to the inverse exponent modulo the modulus).

5. **The matching process**:
   - If the signature is valid, the value obtained by decrypting with the public key should be identical to the hash the server computed itself. This is because private-key encryption and public-key decryption are mutually inverse operations, and they share the same modulus (in RSA, the modulus is the part common to both the public and private keys).

fn my_connect(target_ip: &str, target_port: u16) -> Result<i32> {
    let target_fd = unsafe { libc::socket(AF_INET, SOCK_STREAM, 0) };
    let target_ip = target_ip.to_owned() + "\0";

    let mut target: sockaddr_in = unsafe { mem::zeroed() };

    target.sin_family = libc::AF_INET as u16;

    target.sin_addr.s_addr = unsafe { inet_addr(target_ip.as_ptr() as *const _) };
    target.sin_port = target_port.to_be();

    let res = unsafe {
        libc::connect(
            target_fd,
            &target as *const _ as *const _,
            mem::size_of_val(&target) as u32,
        )
    };

    if res < 0 {
        return os_error!();
    }

    Ok(target_fd)
}

        .lock()
        .get(&real_path.as_os_str().to_string_lossy().to_string())
        .map(|f| {
            println!("cached fd");
            Ok(f.to_owned())
        })
        .unwrap_or_else(|| {
            println!("create new unix socket");

                return os_error!();
            }

            sock.sun_family = AF_UNIX as u16;
            let path: String = real_path.as_os_str().to_string_lossy().to_string() + "\0";

                return Err(anyhow!("Socket path too long"));

            unsafe {

                    sockfd,
                    &sock as *const _ as *const _,
                    mem::size_of_val(&sock) as u32,
                )
            };

            if res < 0 {
                unsafe {
                    libc::close(sockfd);
                }
                println!("Failed to bind socket");
                return os_error!();
            }

            let res = unsafe { libc::listen(sockfd, 100) };
            if res < 0 {
                unsafe {
                    libc::close(sockfd);
                }
                println!("Failed listen socket");
                return os_error!();
            }
            Ok((sockfd, vec![]))
        })?;

    let client_fd = unsafe { libc::accept(sockfd, std::ptr::null_mut(), std::ptr::null_mut()) };
    if client_fd < 0 {
        unsafe {
            libc::close(sockfd);
        }
        return os_error!();
    }

    LISTEN_SOCK
        .lock()
        .entry(real_path.as_os_str().to_string_lossy().to_string())
        .or_insert((sockfd, vec![]))
        .1
        .append(&mut vec![client_fd]);

        // 包含两个元素：sockfd（Unix域套接字的监听文件描述符）和一个空向量vec![]（用于存储从监听套接字上接受到的客户端连接的文件描述符）。

    Ok(client_fd)
}

    }

        libc::connect(
            sockfd,
            &sock as *const _ as *const _,
            mem::size_of_val(&sock) as u32,
        )
    };

    if res < 0 {
        unsafe {
            libc::close(sockfd);
        }
        return os_error!();
    }

    Ok(sockfd) //返回目标套接字

fn session_dec(keys: SessionKey, msg: &[u8]) -> Result<Vec<u8>> {
    if msg.len() % 16 != 0 {
        return Err(anyhow!("Invalid message length"));
    }

    let key = GenericArray::<_, U32>::from_slice(
        keys.key
            .get(0..32)
            .ok_or_else(|| anyhow!("Invalid key length {}", keys.key.len()))?,
    );
    let iv = GenericArray::<_, U16>::from_slice(
        keys.iv
            .get(0..16)
            .ok_or_else(|| anyhow!("Invalid iv length {}", keys.iv.len()))?,
    );
    let mut msg = msg.to_vec();

    let dec = match Aes256CbcDec::new(key, iv).decrypt_padded_mut::<Pkcs7>(&mut msg) {
        Ok(dec) => dec,
        Err(err) => return Err(anyhow!("Failed to decrypt message {}", err)),
    };

    Ok(dec.to_vec())
}

fn session_enc(keys: SessionKey, msg: &[u8]) -> Result<Vec<u8>> {
    let key = GenericArray::<_, U32>::from_slice(
        keys.key
            .get(0..32)
            .ok_or_else(|| anyhow!("Invalid key length {}", keys.key.len()))?,
    );
    let iv = GenericArray::<_, U16>::from_slice(
        keys.iv
            .get(0..16)
            .ok_or_else(|| anyhow!("Invalid iv length {}", keys.iv.len()))?,
    );
    let mut msg = msg.to_vec();
    let msg_len = msg.len();
    let padding_len = (16 - (msg_len % 16)) % 16;
    msg.extend(vec![padding_len as u8; padding_len]);

    let enc = match Aes256CbcEnc::new(key, iv).encrypt_padded_mut::<Pkcs7>(&mut msg, msg_len) {
        Ok(enc) => enc,
        Err(err) => return Err(anyhow!("Failed to encrypt message {}", err)),
    };

    Ok(enc.to_vec())
}

        stream_fd,
        client_key_n.as_mut_ptr() as *mut c_void,
        client_key_n.len() as size_t,
    )?;

    my_read(
        stream_fd,
        client_msg_len.as_mut_ptr() as *mut c_void,
        client_msg_len.len() as size_t,
    )?;

    let client_key_len = u64::from_le_bytes(client_msg_len) as usize;

    println!("Client key e len {}", client_key_len);

    let mut client_key_e = vec![0; client_key_len];

    my_read(
        stream_fd,
        client_key_e.as_mut_ptr() as *mut c_void,
        client_key_e.len() as size_t,
    )?;

        rsa::BigUint::from_bytes_be(&client_key_n),
        rsa::BigUint::from_bytes_be(&client_key_e),
    )?;

    let signature = pkcs1v15::Signature::try_from(&*client_verify)?;

    client_verify_key
        .verify(
            &vec![
                client_key_n.len().to_le_bytes().to_vec(),
                client_key_n,
                client_key_e.len().to_le_bytes().to_vec(),
                client_key_e,
            ]
            .concat(),
            &signature,
        )
        .map_err(|_| anyhow!("Invalid client key"))?;

        ConnType::New | ConnType::Renew => {
            let session_key = SessionKey {
                key: thread_rng().gen::<[u8; 32]>().to_vec(),
                iv: thread_rng().gen::<[u8; 16]>().to_vec(),
            };
            //thread_rng() 函数用于获取线程本地的随机数生成器（ThreadRng）
            //分别生成32字节的密钥和16字节的初始化向量（IV），它们被用于会话中的对称加密。这些值存储在SessionKey结构体中。
            CLIENT_KEY
                .lock()
                .insert(client_key.clone(), session_key.clone());

            println!("gen new key {:?}", session_key);

            let enc_key =
                client_key.encrypt(&mut thread_rng(), Pkcs1v15Encrypt, &session_key.to_bytes())?;
            //客户端的公钥(client_key)和非对称加密算法（在这里是Pkcs1v15Encrypt）来加密session_key
            let enc_time = client_key.encrypt(
                &mut thread_rng(),
                Pkcs1v15Encrypt,
                &now_timestamp().to_le_bytes(),
            )?;

            let new_session = vec![
                enc_key.len().to_le_bytes().to_vec(),
                enc_key,
                enc_time.len().to_le_bytes().to_vec(),
                enc_time,
            ]
            .concat();
            //加密后的会话密钥和时间戳组合
            let new_session_sign = signing_key.sign(&new_session).to_bytes();
            //私钥（signing_key）对整个new_session消息进行签名
            let new_session_sign = vec![
                new_session_sign.len().to_le_bytes().to_vec(),
                new_session_sign.to_vec(),
            ]
            .concat();

            my_write(
                stream_fd,
                new_session_sign.as_ptr() as *const c_void,
                new_session_sign.len() as size_t,
            )?;

            my_write(
                stream_fd,
                new_session.as_ptr() as *const c_void,
                new_session.len() as size_t,
            )?;

            println!("Sending new session finished");

            session_key
        }
        ConnType::Restore => {
            let session_keys = CLIENT_KEY.lock();
            let session_key = session_keys
                .get(&client_key)
                .ok_or_else(|| anyhow!("Invalid client key"))?;
            session_key.clone()
        }
        ConnType::Unknown => {
            return Err(anyhow!("Invalid connection type"));
        }
        ConnType::Restart => {
            exit(0);
        }
    };

    let recv_res = my_read(
        stream_fd,
        pre_conn.as_mut_ptr() as *mut c_void,
        pre_conn.len() as size_t,
    )?;
    pre_conn.resize(recv_res as usize, 0);

    let pre_conn = session_dec(session_key.clone(), &pre_conn)?;
    //解密
    if pre_conn.len() < 16 {
        return Err(anyhow!("Invalid pre connection data"));
    }

    let conn_type = ProxyType::from_le_bytes(&pre_conn[0..4]);
    let status = ProxyStatus::from_le_bytes(&pre_conn[4..8]);
    //
    println!("Conn type {:?} status {:?}", conn_type, status);

    let signature = pkcs1v15::Signature::try_from(&pre_conn[8..])?;

    client_verify_key
        .verify(&pre_conn[0..8], &signature)
        .map_err(|_| anyhow!("Invalid client key"))?;

    let ok_msg = vec![0; 4];
    let signing_key = pkcs1v15::SigningKey::<Sha256>::new(pri_key.clone());
    let key_exchange_sign = signing_key.sign(&ok_msg).to_bytes();
    let ok_msg = vec![
        ok_msg,
        key_exchange_sign.len().to_le_bytes().to_vec(),
        key_exchange_sign.to_vec(),
    ]
    .concat();
    let ok_msg = session_enc(session_key.clone(), &ok_msg)?;

    my_write(
        stream_fd,
        ok_msg.as_ptr() as *const c_void,
        ok_msg.len() as size_t,
    )?;

    let res_msg = match status {
        ProxyStatus::Send => {

            let recv_res = my_read(
                stream_fd,
                conn_data.as_mut_ptr() as *mut c_void,
                conn_data.len() as size_t,
            )?;

            conn_data.resize(recv_res as usize, 0);

            let conn_data = session_dec(session_key.clone(), &conn_data)?;

            if conn_data.len() < 32 {
                return Err(anyhow!("Invalid data"));
            }

            let target_fd = i32::from_le_bytes(conn_data[0..4].try_into()?);

            if CLIENT_STREAM
                .lock()
                .get(&client_key)
                .and_then(|fds| fds.contains(&target_fd).then_some(0))
                .is_none()
            {
                return Err(anyhow!("Invalid fd: {}", target_fd));
            }

            let mut send_data_size = usize::from_le_bytes(conn_data[4..12].try_into()?);

            let mut send_data = vec![];
            let mut remain_data = vec![];

            if send_data_size <= conn_data.len() - 12 {
                send_data.extend(conn_data[12..(12 + send_data_size)].to_vec());
                remain_data = conn_data[(12 + send_data_size)..].to_vec();
                if remain_data.len() < 512 {
                    let mut send_data_part = vec![0; 512];
                    let recv_res = my_read(  //没发送完，分了两次发过来 签名长度一般大于等于512
                        stream_fd,
                        send_data_part.as_mut_ptr() as *mut c_void,
                        send_data_part.len() as size_t,
                    )?;
                    send_data_part.resize(recv_res as usize, 0);
                    let send_data_part = session_dec(session_key.clone(), &send_data_part)?;
                    remain_data.extend(send_data_part);
                }
                send_data_size = 0;
            } else {
                send_data.extend(conn_data[12..].to_vec());
                send_data_size -= conn_data.len() - 12; //还不够数据的长度，下次发送过来还会有数据部分
            }
            if send_data_size > 0 {  //还有数据部分没有发送过来
                // ensure read signature
                let mut send_data_part = vec![0; send_data_size + 0x2000];
                let recv_res = my_read(
                    stream_fd,
                    send_data_part.as_mut_ptr() as *mut c_void,
                    send_data_part.len() as size_t,
                )?; 
                send_data_part.resize(recv_res as usize, 0);
                let send_data_part = session_dec(session_key.clone(), &send_data_part)?;
                send_data.extend(send_data_part[0..send_data_size].to_vec());
                remain_data.extend(send_data_part[send_data_size..].to_vec());
            }

            let signature = pkcs1v15::Signature::try_from(&*remain_data)?;

            client_verify_key
                .verify(
                    &vec![
                        target_fd.to_le_bytes().to_vec(),
                        send_data.len().to_le_bytes().to_vec(),
                        send_data.clone(),
                    ]
                    .concat(),
                    &signature,
                )
                .map_err(|_| anyhow!("Invalid client key"))?;

            println!("Send data to fd {} size {}", target_fd, send_data.len());

            let send_res = match conn_type {
                ProxyType::Tcp => my_write(
                    target_fd,
                    send_data.as_ptr() as *const c_void,
                    send_data.len() as size_t,
                )?,
                ProxyType::Udp => my_sendto(target_fd, &send_data)?,
                ProxyType::Sock => my_send_msg(target_fd, &send_data)?,//服务器将客户端发送过来的数据发送给目标套接字
                ProxyType::Unknown => return Err(anyhow!("Invalid conn type")),
            };
            send_res.to_le_bytes().to_vec()
        }
        ProxyStatus::Recv => {
            let mut conn_data = vec![0; 2048];
            let recv_res = my_read(
                stream_fd,
                conn_data.as_mut_ptr() as *mut c_void,
                conn_data.len() as size_t,
            )?;

            conn_data.resize(recv_res as usize, 0);

            let conn_data = session_dec(session_key.clone(), &conn_data)?;

            if conn_data.len() < 32 {
                return Err(anyhow!("Invalid data"));
            }

            let target_fd = i32::from_le_bytes(conn_data[0..4].try_into()?);

                .lock()
                .get(&client_key)
                .and_then(|fds| fds.contains(&target_fd).then_some(0))
                .is_none()

                return Err(anyhow!("Invalid fd: {}", target_fd));

            println!("Recv data from fd {} size {}", target_fd, recv_data_size);

            let signature = pkcs1v15::Signature::try_from(&conn_data[12..])?;

            client_verify_key
                .verify(&conn_data[0..12], &signature)
                .map_err(|_| anyhow!("Invalid client key"))?;

            let recv_data = match conn_type { //得到返回数据
                ProxyType::Tcp => {
                    let mut recv_data = vec![0; recv_data_size as usize];

                    let recv_sz = my_read(
                        target_fd,
                        recv_data.as_mut_ptr() as *mut c_void,
                        recv_data.len() as size_t,
                    )?;
                    recv_data.resize(recv_sz as usize, 0);
                    recv_data
                }
                ProxyType::Udp => my_recvfrom(target_fd, recv_data_size as usize)?,
                ProxyType::Sock => my_recv_msg(target_fd, recv_data_size as usize)?,

                "succ recv data from fd {} size {}",
                target_fd,
                recv_data.len()
            );

        }

                conn_data.as_mut_ptr() as *mut c_void,

                    libc::close(conn_fd);

        });
    }

    Ok(())

# Public key exchange and signatures
- The sender sends its public key together with a signature of that public key (a signing key derived from the private key and some algorithm is used to sign the message)
- The receiver uses the received public key to authenticate the received public key (included in the data portion) and its signature (via the sender's public key)

# Session key
- The sender encrypts the (randomly generated) session key with the receiver's public key using the relevant algorithm, then signs the encrypted data and sends both together
- The receiver authenticates the data and the signature using the sender's public key, then decrypts the data portion with its own private key, finally obtaining the session key

# Subsequent communication
- The sender encrypts the data portion and the signature of the data portion (made with the private key) using the session key, then sends them

#  Lifetimes and raw pointers


In the code snippet
```rust
let mut recv_iov = [iovec {
    iov_base: vec![0u8; recv_size].as_mut_ptr() as *mut _,
    iov_len: recv_size,
}];
```
the following lifetime problem exists:

1. **The relationship between `Vec` and the raw pointer**:
   When you create a `Vec<u8>` and immediately obtain a raw pointer to it via `as_mut_ptr()`, this raw pointer points to the memory inside the `Vec`. However, the lifetimes of the `Vec` and the raw pointer are not explicitly linked. The `Vec`'s lifetime is confined to the scope in which it is created, while the raw pointer's lifetime is indeterminate, because it escapes Rust's lifetime management system.

2. **Automatic deallocation of the `Vec`**:
   Because the `Vec` is created in a local scope, when that scope ends the `Vec` is automatically dropped and its memory is reclaimed. If the raw pointer is still in use at that point, it becomes a dangling pointer, pointing to a block of memory that is no longer valid.


In Rust, the expression `vec![0u8; recv_size]` creates a `Vec<u8>` whose lifetime is bound to the scope in which it is created.
```rust
iovec {
    iov_base: vec![0u8; recv_size].as_mut_ptr() as *mut _,
    iov_len: recv_size,
}
```
Here, `vec![0u8; recv_size]` is created in the context of the `iovec` struct initialization. This means the lifetime of this `Vec<u8>` is bound to the block containing the line where the `iovec` is initialized (i.e., the region of code enclosed by curly braces). Once this block finishes executing, the `Vec<u8>` also reaches the end of its lifetime and its memory is freed.

However, the lifetime of the `Vec<u8>` created by `vec![0u8; recv_size]` in this line may conflict with the lifetime of the `iovec`, because the `iovec`'s `iov_base` field is set to a raw pointer to this `Vec`. When the `Vec<u8>`'s lifetime ends, its memory is freed, but the `iovec` may still hold a raw pointer to the freed memory, which results in a dangling pointer.

The my_recv_msg function is equivalent to:

1. Initialize iov_base with a memory buffer of recv_size bytes;
2. Free this memory, yielding a dangling pointer;
3. At unsafe { recvmsg(fd, &mut msg, 0) }, read the data previously sent to the specified fd and write it into this memory (UAF);
4. Finally, obtain a slice via unsafe { slice::from_raw_parts(recv_iov[0].iov_base as *const u8, recv_size) }; then res.to_vec() allocates another heap chunk of the same size and copies the data from the res slice into this new memory block

# General idea (the exp is still subject to change)
tcache has been added, and tcache has no next-pointer check
1. sendmsg sends zero bytes; recvmsg is given a large msg_recvsize so that the iov_base of the internal msg, after being freed, goes into the unsorted bin. recvmsg then writes the received data (zero bytes, so nothing is actually written) into msg's iov_base, leaving the residual libc address unmodified
2. res.to_vec() reallocates at this point, with the same size as the bin that was just freed, then leaks the libc address and copies the previous content over
3. Because after the free there are two consecutive allocations that copy the original data: the first allocation returns the original chunk, and the second is the chunk corresponding to the overwritten fd. Since the original data is copied (if fd is free_hook-0x8 system, the allocation lands on free_hook-0x8 and writes free_hook-0x8 system), we change fd to free_hook-0x8 system
4. Because there are many more free operations later that will call the system function, but with incorrect arguments system fails to execute and that thread gets stuck; this does not matter
5. At the next UAF, send the relevant command; this time what gets written into the freed chunk is the command. The allocation then returns the original chunk, res.to_vec() creates a new chunk and copies the content of the original chunk, i.e., the command; when its lifetime ends, system(command) is invoked
