# Overview
Two network layered architectures

Combining the de facto standard and the de jure standard yields a neutralized 5-layer architecture
![Image](/images/csdn/2024/csdn-135737551/image-001-63076a4ab7.png)

# Where Did the OSI Model Come From?
At the beginning, the network architectures of various companies were different, so they could not interconnect
Therefore the ISO organization proposed this model, but because it deviated somewhat from practical applications, practical applications still adopted the TCP/IP model

![Image](/images/csdn/2024/csdn-135737551/image-002-856c962806.png)

# The OSI Reference Model
The resource subnet and the communication subnet correspond respectively to processing the resource and transmitting that resource
![Image](/images/csdn/2024/csdn-135737551/image-003-4cd0e5810c.png)
# The OSI Reference Model Explains the Communication Process
Intermediate systems have only three layers

The physical layer adds nothing to the data; it forms the data into a bit stream and transmits it onto the transmission medium

The intermediate system receives the data, and each layer restores and examines the information in turn

End-to-end: only the sending end and the receiving end have the upper four layers, so the upper four layers can be directly regarded as directly connected end-to-end (because only one transmission process reaches the upper four layers, there is only one connection corresponding to the upper four layers, similar to the departure point and destination of a route)

Point-to-point: every node has the lower three layers, so this cannot serve as a unique indicator of a sending end and a receiving end, so it is regarded as point-to-point (similar to one node to the next node on a route)
![Image](/images/csdn/2024/csdn-135737551/image-004-609ac56aa6.png)
Each layer adds the control information of that layer (except the physical layer)

The data link layer adds two parts
![Image](/images/csdn/2024/csdn-135737551/image-005-c8f9e9f7de.png)
# Layer-by-Layer Analysis
## Application Layer
The interface between the user and the network
Only programs that require a network connection to be used belong to the application layer
![Image](/images/csdn/2024/csdn-135737551/image-006-e6e7cf58f4.png)
## Presentation Layer
The two communicating systems are the receiving end and the sending end
The way data is presented on the screen
Data format conversion: for example, when an image's bit stream is passed up from below to the presentation layer, it is converted into the image's data format

Data compression and restoration: for example, image data is compressed and transmitted onto the link, and the receiving end decompresses or restores it after receiving it
![Image](/images/csdn/2024/csdn-135737551/image-007-f6d98b4776.png)


## Session Layer
The role of establishing connections
Sessions are independent of each other and do not affect each other
For example, the conversation between a video app and its corresponding server does not affect the conversation between Baidu and its corresponding server (fast-forwarding the video does nothing to Baidu)

Checkpoint: when a session suddenly closes, the checkpoint is used to restore the previous session (for example, when transferring a large file, if it is suddenly interrupted, retransmitting would waste the part already sent; the checkpoint allows continuing from where it left off)

![Image](/images/csdn/2024/csdn-135737551/image-008-6394aaab77.png)
## Transport Layer
The upper four layers are all end-to-end
The lower three layers are all point-to-point
 A host's processes are identified by port numbers
The file is cut into segments one by one

Reliable transmission (large files): the receiving end replies with acknowledgment information to the sending end; if it is not received, the data is retransmitted
Unreliable transmission (small files): no acknowledgment mechanism
Error control: segments arriving out of order or being lost
Flow control: speed matching, making the sending and receiving speeds match, controlling the sending end
Multiplexing and demultiplexing: multiple processes can use the transport layer, and the transport layer can distribute information to each process

![Image](/images/csdn/2024/csdn-135737551/image-009-0e687cdb2e.png)
## Network Layer
Routing: choosing a transmission route
Flow control: making the sending and receiving speeds match, controlling the sending end
Congestion control: when packets (i.e. datagrams) cannot be received in time, packets are discarded, causing network congestion, at which point some control is needed to resolve it

![Image](/images/csdn/2024/csdn-135737551/image-010-0239d6a787.png)
## Data Link Layer
Framing: a frame is also a bit stream, the assembly of datagrams
Flow control: making the sending and receiving speeds match, controlling the sending end

Access control: in a broadcast network, only one machine can send information at the same time while all others are listening; it controls which host occupies the current channel, which connects to each machine
 
 ![Image](/images/csdn/2024/csdn-135737551/image-011-828b63a6a2.png)
## Physical Layer
Converts the bit stream into electrical signals, without modifying the data
Transparent transmission: regardless of the combination of bits, transmit them onto the link

Defining interface characteristics: such as how many pins, how to connect
Defining transmission modes: half-duplex (at the same time only one party can send information to the other, but it can be A to B or B to A), full-duplex (both sides can send to each other at the same time), simplex (only one direction of sending)
Bit synchronization: for example, whatever is sent can be received by the receiver
Bit encoding: for example, what voltage represents 1 and what voltage represents 0
![Image](/images/csdn/2024/csdn-135737551/image-012-93ef887364.png)
