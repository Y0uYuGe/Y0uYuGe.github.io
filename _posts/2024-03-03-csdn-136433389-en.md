# UTS Namespace
In Linux, the UTS (UNIX Time-sharing System) namespace allows different processes on a single system to have their own independent system identifiers, such as the hostname and the NIS domain name. This means that inside a UTS namespace, a process can change its hostname without affecting the hostnames of other processes on the system.

clone(): This is a Linux system call used to create a new process. The clone() call offers more options than fork(), because it allows you to control the extent of resource sharing between the new process and the original process by specifying different flags. These flags can determine which namespaces the new process belongs to. For example, using the CLONE_NEWPID flag creates a new PID namespace for the new process. The newly created process and all of its subsequent child processes are included in the specified namespace.

unshare(): This system call allows an existing process to detach itself from a namespace (even one it previously shared with other processes). For example, if a process wants to create a new network namespace separate from the current one, it can do so with unshare() and the appropriate flag (such as CLONE_NEWNET).

setns(): The setns() system call is used to move a process into an already-existing namespace. This call requires a file descriptor that specifies the target namespace. It is commonly used in container technology, for example to move a process from the host's namespace into a container's namespace.
# The unshare command and the unshare system call
Both the unshare command and the unshare() system call are used in the context of isolation and virtualization on Linux systems, but they differ in how and where they are used:

The unshare command: unshare is a user-level tool run from the command line that creates independent namespaces without starting a new init process. Namespaces are a mechanism Linux uses to isolate resources such as processes, networking, user IDs, and filesystems. With the unshare command, a user can create new namespaces for a specific process or script without affecting the rest of the system.

Common usage examples of the unshare command:

```bash

unshare --创建命名空间类型 程序

unshare --uts sh 创建UTS 的namespace，并在其中运行sh
```

The unshare() system call: unshare() is a low-level programming interface (API) written in C, one of the system calls provided by the Linux kernel. Developers can call unshare() directly in an application to change the namespace membership of an existing process, detaching it from the sharing of certain resources.
Prototype of the unshare() system call:
```c

#include <sched.h>

int unshare(int flags);
```
 
This call takes a flags argument that specifies which types of resources to unshare. On success it returns 0; on failure it returns -1 and sets errno to indicate the cause of the error.

Both are fundamental tools and calls for implementing Linux containerization and OS-level virtualization. For example, container technologies like Docker rely heavily at the underlying level on mechanisms such as namespaces and cgroups, and the unshare command and the unshare() call are among the ways to manipulate namespaces.
# Fixing the root user lacking the regular user's go command
Since running this program directly with go is not allowed, you need to switch to the root user or use sudo.
```bash
首先 su  切换到root用户
添加以下行到 root 用户的 shell 配置文件（例如 /root/.bashrc 或 /root/.bash_profile）中：

export PATH=$PATH:/usr/local/go/bin

之后，运行以下命令来应用更改：

source /root/.bashrc
```

But annoyingly, after switching with su, the utsnamespace.go file you want to run is no longer there.
# Using sudo go

```bash
当你运行 echo $PATH 命令时，我们看到 /usr/local/go/bin 包含在你的用户的 PATH 环境变量中，这意味着你的用户应该能够找到 go 命令。

然而，当你以 sudo 运行 go 命令时，你遇到了 sudo: go: command not found 错误。这可能是因为当使用 sudo 命令时，sudo 可能没有使用你用户的 PATH 环境变量，它可能使用了一个不包含 /usr/local/go/bin 的不同的 PATH。

你可以用下面的命令来查看 sudo 的 PATH 环境变量：

sudo env | grep PATH
 
如果从这个命令的输出中看不到 /usr/local/go/bin 目录，这会解释为什么 sudo 不能找到 go 命令。一个比较快捷的解决方法是指定 go 命令的完整路径：

sudo /usr/local/go/bin/go run utsnamespace.go
 
如果这个方法有效并且你想要修正 sudo 的 PATH 问题，一个更持久的解决方案是编辑 /etc/sudoers 文件，你可以使用 visudo 命令来安全地编辑这个文件：

sudo visudo
 
在 visudo 编辑器中，寻找 secure_path 这一行并且确保 /usr/local/go/bin 被包含在里面。例如：

Defaults    secure_path="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/local/go/bin"
```
# Code Analysis

## The os package and the os/exec package
```go
exec是os/exec包的一部分，正确的导入方式应该是：

import "os/exec"
```

The os package: The os package provides a set of functions for interacting with the filesystem, such as creating, deleting, reading, and writing files and directories, as well as getting and setting environment variables. These are all standard interactions directly between your program and the operating system, and do not require starting or interacting with external, independent programs.

The os/exec package: The os/exec package is used to execute external commands and programs. It allows your Go program to start another independent process that runs a command or script external to the operating system, such as a Shell command or another executable. os/exec can capture the output of these external processes, provide input to them, handle their error output, and control their execution (such as starting, waiting for completion, killing the process, etc.).

A simple example to illustrate the difference:

Suppose you want to read a file and print its contents. You only need the os package for this task: open the file, read its contents, and then close it.
Now suppose you want to run the ls command (which lists directory contents in Unix) or the dir command (in Windows) on the operating system. This operation requires a Shell environment to interpret and execute the command. In this case, os/exec is what you need; your Go program will use it to start a new external process to run the command.
Therefore, some things the exec package can do when interacting with external processes cannot be done with just the os package, because the os package does not provide the ability to start and control external processes. The reverse is also true: the os/exec package is not meant for filesystem-level operations, while the os package is specifically designed for those kinds of tasks.

## log.Fatal(err)
In Go, the log.Fatal function is used to log an error message and then terminate the program. It is a convenient function provided by the log package that first outputs its arguments (usually an error message) to the log, and then calls os.Exit(1) to terminate the program. Take a closer look at this line of code:

```go
log.Fatal(err)
```

 
The purpose of this line is to check whether the err variable is not nil (i.e., whether an error exists). If an error has occurred:

1.  log.Fatal(err) outputs the error message err to standard error (stderr). The output format usually includes the current timestamp and file name, which helps with debugging.

2. After the error message is logged, log.Fatal calls os.Exit(1) to terminate the program. The argument 1 passed to os.Exit is the program's exit status code. In UNIX and UNIX-like systems, an exit status code of 0 usually means the program executed successfully, while a non-zero value indicates an error occurred during execution. Therefore, 1 means the program terminated due to an error.

##  SysProcAttr 
The Cmd struct represents an external command to be executed, and in Go's os/exec package it encapsulates the information related to execution. When the Run or Start method of Cmd is used, a new process is created to execute the specified command. The fields of the SysProcAttr struct are used to adjust the system-level attributes of this new process.

Regarding the Cloneflags field of the SysProcAttr struct, here is its meaning and purpose:

- Cloneflags: This field is used to pass a set of bit flags to the underlying system call, which on Linux is usually clone. These flags define special behaviors when the process starts, including how it shares resources with other processes and whether it should run in a different namespace.

- syscall.CLONE_NEWUTS: This particular bit flag asks the operating system to create a new UTS (UNIX Time-sharing System) namespace for the newly created process. A UTS namespace allows a process to have its own system identifiers, such as hostname and domain name, so that changing the hostname inside this namespace does not affect other namespaces, improving isolation.

So, in the Go snippet above, cmd.SysProcAttr is set to &syscall.SysProcAttr{} with the syscall.CLONE_NEWUTS flag, which means when the command represented by cmd runs:

1. A new process will be created. The creation of this new process will include a new UTS namespace, allowing it to have an independent hostname and domain name, isolated from other processes.
2. The command is executed.


## cmd's input and output
1. cmd.Stdin=os.Stdin
This line sets the command's standard input to come from the operating system's standard input, which usually refers to the input of the terminal or command-line interface. This means the external command can read data typed by the user through the terminal.

2. cmd.Stdout=os.Stdout
This line sets the command's standard output to the operating system's standard output, which usually refers to the output of the terminal or command-line interface. This means the running command will send its output data back to the terminal so the user can see it directly.

3. cmd.Stderr=os.Stderr
This line sets the command's standard error to the operating system's standard error, which is also usually the terminal or command-line interface. Standard error is used to output error messages; by setting standard error to os.Stderr, the command's error messages are displayed directly on the current error output device, which is usually also the terminal.

Overall, the code above redirects the command's input, output, and error streams to the current terminal, so that when the command runs the user can interact with it through the terminal and see its output and error messages there. This is a very common practice when executing external commands, and it ensures an interactive experience for command-line tools.

# Go code
Core logic: create a new process that runs inside a newly created UTS namespace (a namespace that has an independent hostname and domain name, isolated from other processes), and then have the new process run the sh command.
```go
package main

import
(
	"exec"
	"syscall"
	"os"
	"log"
)

func main(){
	cmd:=exec.Command("sh")
	cmd.SysProcAttr=&syscall.SysProcAttr{
		Cloneflags: syscall.CLONE_NEWUTS,}
	cmd.Stdin=os.Stdin
	cmd.Stdout=os.Stdout
	cmd.Stderr=os.Stderr

	if err:=cmd.Run();err!=nil{
		log.Fatal(err)
	}
}
```
