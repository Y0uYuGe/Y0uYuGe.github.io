# Approach
Similar to the previous challenge, but it requires side-channel brute-forcing and using mprotect to modify memory segment attributes.
Migrate the stack to the bss segment, then use SROP to call open, read, mprotect, and shellcode in sequence.
After using mprotect, i.e., after the syscall, pop rbp, ret; at this point, the top of the stack at ret is the address of the shellcode on bss.

## Finding a Memory Region Where shellcode Can Be Written

To write and execute shellcode, the region needs w and x permissions. After examining all of them, none matches, so the memory segment's permissions need to be modified.
![Image](/images/csdn/2024/csdn-135636845/image-003-d38761f359.png)
## Using mprotect() to Modify Attributes
The mprotect() function changes the protection attributes of the memory region starting at start with length len to the value specified by prot.

```c
#include <unistd.h>
#include <sys/mmap.h>
int mprotect(const void *start, size_t len, int prot);
```
**Note that start must be the starting address of a page, and len must be an integer multiple of the page size**

**Note that even if the original attributes include PROT_READ and PROT_WRITE, if the parameter passed to mprotect is PROT_EXEC, only the PROT_EXEC attribute will remain; any read or write operation at this point will raise an exception**
prot can take the following values, and several attributes can be combined with "|":

-  PROT_READ: indicates the contents of the memory segment are writable;

- PROT_WRITE: indicates the contents of the memory segment are readable;

- PROT_EXEC: indicates the contents of the memory segment are executable;

- PROT_NONE: indicates the contents of the memory segment cannot be accessed at all.

It should be pointed out that the specified memory range must cover entire memory pages (4K). The starting address of the range, start, must be the starting address of a memory page, and the range length len must be an integer multiple of the page size.


If the call succeeds, it returns 0; if it fails, it returns -1 and sets errno to indicate the specific reason for the failure. The main reasons for errors are as follows:

1) EACCES
The memory cannot be set to the corresponding permissions. This can happen, for example, if you mmap(2) a file as read-only and then use mprotect() with the PROT_WRITE flag.

2) EINVAL

start is not a valid pointer; it does not point to the beginning of a memory page.

3) ENOMEM

The kernel's internal structures could not be allocated.

4) ENOMEM

The process's address space in the range [start, start+len] is invalid, or one or more memory pages are not mapped. 

If the calling process's memory access violates these configured protection attributes, the kernel generates a SIGSEGV (Segmentation fault) signal for the process and terminates it.

            fram_read.rax=constants.SYS_read

            fram_read.rsi=bss
            fram_read.rdx=40
            fram_read.rip=syscall_pop_rbp_ret

            loop:
            cmp byte ptr[0x404060+{0}], {1}
            jz loop
            '''.format(one,two)

            shellcode_address=bss+248+16+248+16+16+24+248+16

            f.sendlineafter(b"Do u know what is SUID?\n",payload2)
