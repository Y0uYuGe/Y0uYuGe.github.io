# 5-ary Search Tree
Divide the range further; values in different divisions go into different subtrees
Four numbers make the divisions, so there are five intervals
Now one node corresponds to multiple keys. If the leaf node still does not contain the corresponding key, the search fails — then check which interval of the leaf node's keys it falls into
Each node can hold just one key or multiple keys, and the number of its subtrees naturally differs accordingly

## How to Search
###  Successful Search
9 is less than 22, so go into the left subtree to its root node. Compare the keys — you can search sequentially or use binary search. The key is not found here, but the range interval is found, so jump to the second of the three subtrees and search sequentially again; the corresponding key is found — search successful

###  Failed Search
41 is greater than 22, so first go to the right subtree, compare the keys, go into the corresponding second subtree, compare the keys again, and enter the corresponding second subtree — but it is empty, so the key is not found

# B-Tree
Nodes are multi-way, and the heights of the subtrees of every node are balanced, so it is called a multi-way balanced search tree.
An m-order B-tree may be empty, in which case it has no nodes
Each node has at most m subtrees and at most m-1 keys
As for the minimum: except for the root, the minimum number of subtrees can be 0 — no wait, it is 2. If it were 1, then since the root's key would have two branches, one would have height and the other would not, violating the B-tree requirement
Other nodes have at least ceil(m/2) subtrees.

Here the leaf nodes are all empty nodes; the terminal nodes are not empty nodes

# The Height of a B-Tree
For the minimum height, the tree is as full as possible: starting from the root, every node has m subtrees, so each node has m-1 keys.
The number of nodes in each level is a power of m, each node has m-1 keys, and the total number of keys is n
Here n corresponds to the upper limit of a full m-ary tree, from which the minimum value of h can be derived

![在这里插入图片描述](/images/csdn/2023/csdn-135153867/image-010-ddcc31fd37.png)

The maximum height corresponds to the fewest branches: the root has at least 2 branches, and other nodes have at least ceil(m/2) branches

Here the relationship of the leaf nodes is used
Why must a B-tree with n keys have n+1 leaf nodes? Because you can imagine that the essence of a B-tree is dividing intervals, and all the resulting intervals end up in the leaf nodes. So a B-tree with n keys must have n+1 leaf nodes

But the lower bound on the number of leaf nodes for the tallest B-tree is actually as shown in the figure — the (h+1)-th level has ... leaf nodes — because the number of keys in the terminal nodes can increase without limit
Suppose h is the height of the tallest B-tree; then the number of keys in every node except the terminal nodes of this tallest B-tree must be the minimum number of keys per node, while the number of keys in the terminal nodes can be greater than or equal to the minimum number of keys per node

So for the tallest B-tree of height h, the minimum number of leaf nodes is the one derived geometrically as shown in the figure, and the maximum must be less than the number of leaf-node keys derived from this geometric progression plus the number of keys in the terminal nodes, since the total number of keys in the terminal nodes can grow — if it were equal, the height could still increase

Therefore, for a B-tree with n keys whose maximum height is h, the number of keys in the leaf nodes must be greater than the minimum number of leaf nodes (derived geometrically) of a B-tree of height h
![在这里插入图片描述](/images/csdn/2023/csdn-135153867/image-011-9371c40831.png)What is used here is: if the total number of keys is less than the total number of keys of a tree in which every node has the minimum number of keys, then the height must be less than h, because if it were still h, then since no node could have fewer keys, it would fail. So if the maximum height is h, then the total number of keys must be greater than the total number of keys of a tree of height h in which every node has the minimum number of keys
