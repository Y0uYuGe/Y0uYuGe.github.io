## Checks
All protections enabled
![在这里插入图片描述](/images/csdn/2024/csdn-135453403/image-004-d647aded92.png)
Viewing the sandbox rules
![在这里插入图片描述](/images/csdn/2024/csdn-135453403/image-005-d87215e8ed.png)
It first checks the architecture; if it is not ARCH_X86_64, the system call is forbidden. Then it fetches the second argument of the system call and copies it to X, then obtains the system call number. Next it checks whether the syscall number is the same as read, write, fstat, or lseek — if the same, execution is allowed. If it matches none of them, it checks whether it equals mmap; if so, it checks whether the second argument of the system call is odd — if odd it is forbidden, otherwise allowed. If the syscall number differs from mmap, it checks whether it equals mprotect; if so, it again checks whether the second argument is odd — forbidden if odd, allowed otherwise. If the syscall number differs from mprotect, it checks whether the syscall number equals the second argument of the system call; if equal, the syscall is allowed. Otherwise it checks whether the syscall number equals brk, exit, or exit_group — equal means allowed; if all differ, the syscall is forbidden

## Approach
Note that there are still eight bytes between the array and var_8; the index corresponding to var_8 is 201
![在这里插入图片描述](/images/csdn/2024/csdn-135453403/image-006-bcc7762618.png)


First, since the ret instruction at the end of main returns to the position libc_start_main+241, we can use show to display this address out of bounds; the corresponding array index is 203. This leaks the libc base address, from which we then get the addresses of various gadgets
![在这里插入图片描述](/images/csdn/2024/csdn-135453403/image-007-b34fd548c3.png)
Since our goal is to read the contents of the flag file, we need the open function, then read, then write. Invoking the open system call requires rdx=rax to succeed
Since we must first read the file contents into memory and then output them via write, we also need to know some location in memory. At this point we find that a stack address exists on the stack, corresponding to array index 205. Subtracting the return address from this stack address gives 0xE0, so the corresponding index is 231
![在这里插入图片描述](/images/csdn/2024/csdn-135453403/image-008-261f47cd4b.png)
![在这里插入图片描述](/images/csdn/2024/csdn-135453403/image-009-52a7f5bc72.png)
Subtracting 231*8 from the stack address obtained this way yields the starting address of the array; then input open's first argument at this position, i.e. ./flag. Note that since the function input is an integer at this point, the input bytes are placed into memory in reverse order, while open is called with a string argument, which is converted byte by byte from low address to high address. So we need to input the bytes of ./flag in reverse, i.e. input them as the bytes galf/.

Next, just build the ROP chain: first open(starting address of the array, 0, 2) with rax=2. The rdx constructed here has no effect on the function; it merely makes the second argument equal to rax's value so the system call can be invoked successfully.

Then read(the return value of the previous open, i.e. the value of rax, an address of a region on the stack, the length of input to write) with rax=0. Here we must first move rax's value into rdi, and then set rax to 0.
At this point we cannot find mov rdi, rax; ret; — every gadget is followed by a jump. We need to control the jump target so that we eventually return to the ROP chain. To do that, we need to control rcx in advance: if rcx holds the address of a pop ; ret gadget, we can still return to the gadget right after mov rdi, rax; call rcx (because the call pushes a return address onto the stack; after the pop, ret lands exactly on the gadget following mov rdi, rax; call rcx). So we need to prepare the address of a pop ; ret gadget on the stack in advance, then first execute pop rcx; ret so that rcx becomes the address of the pop ; ret gadget. The other two arguments are relatively easy to control
![在这里插入图片描述](/images/csdn/2024/csdn-135453403/image-010-e49a508009.png)
Finally write(1, the address that read wrote into, output length) with rax=1. Here we only need to modify rax and rdi; rsi and rdx stay unchanged (same as read's rsi and rdx). Finally, the flag is output
![在这里插入图片描述](/images/csdn/2024/csdn-135453403/image-011-7060bdea9e.png)
