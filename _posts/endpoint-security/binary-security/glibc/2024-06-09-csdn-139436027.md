# Buffering Mechanism
- Read: first read a large chunk of data from the file into the buffer, then read the needed portion of data from the buffer
- Write: first write to the buffer, and when the buffer is full, write it out to the file

# IO_FILE_PLUS

# fopen
fopen is actually IO_new_fopen, and it first enters fopen_internal
## fopen_internal
![Image](/images/csdn/2024/csdn-139436027/image-001-5f040c86f0.png)

```c
FILE *
__fopen_internal (const char *filename, const char *mode, int is32)
{
  struct locked_FILE
  {
    struct _IO_FILE_plus fp;
#ifdef _IO_MTSAFE_IO
    _IO_lock_t lock;
#endif
    struct _IO_wide_data wd;
  } *new_f = (struct locked_FILE *) malloc (sizeof (struct locked_FILE));

  if (new_f == NULL)
    return NULL;
#ifdef _IO_MTSAFE_IO
  new_f->fp.file._lock = &new_f->lock;
#endif
  _IO_no_init (&new_f->fp.file, 0, 0, &new_f->wd, &_IO_wfile_jumps);
  _IO_JUMPS (&new_f->fp) = &_IO_file_jumps;
  _IO_new_file_init_internal (&new_f->fp);
  if (_IO_file_fopen ((FILE *) new_f, filename, mode, is32) != NULL)
    return __fopen_maybe_mmap (&new_f->fp.file);

  _IO_un_link (&new_f->fp);
  free (new_f);
  return NULL;
}
```
It allocates a structure of size sizeof (struct locked_FILE). Then _IO_no_init initializes the allocated structure, _IO_JUMPS assigns the vtable, _IO_new_file_init_internal links the structure into list_all, and then _IO_file_fopen makes a system call to open the file and set the file descriptor

First it checks whether the buffer has been initialized; if not, it calls _IO_doallocbuf to allocate a region as the buffer. Then it checks whether the data remaining in the input buffer can satisfy the amount to be read out; if so, it uses __mempcpy. If the content of the input buffer is smaller than the length the user wants to read, it memcpys the input buffer content first and then calls __underflow. If there is no input buffer content available for the user at all, it also calls __underflow to fill the buffer. Then in certain cases, when `fp->_IO_buf_base

- **Check the file stream mode**:
  - `if (fp->_mode > 0)` checks whether the file stream is opened in wide-character mode (for example, involving multi-byte encodings such as UTF-16 or UTF-32). A `fp->_mode` value greater than 0 indicates that the stream is wide-oriented.

- **Releasing wide-character encoding resources**:
  - If the stream is in wide-character mode, the following operations are performed:
    - Get the encoding converter structure pointer: `struct _IO_codecvt *cc = fp->_codecvt;`
    - Lock to ensure thread safety: `__libc_lock_lock(__gconv_lock);`
    - Release the input and output conversion steps (likely the internal state of character encoding conversion): `__gconv_release_step(cc->__cd_in.step)` and `__gconv_release_step(cc->__cd_out.step)`
    - Unlock: `__libc_lock_unlock(__gconv_lock);`

- **Backup area handling**:
  - Otherwise (i.e., the file stream is not in wide-character mode), it checks whether a backup area exists:
    - `if (_IO_have_backup(fp))` confirms whether the file stream has a backup area, which is typically used to implement features such as write rollback.
    - If it exists, the backup area is freed: `_IO_free_backup_area(fp);`

- **Releasing file stream resources**:
  - In either case, the following is eventually executed:
    - `_IO_deallocate_file(fp);` frees the entire file stream structure and all its associated resources.
