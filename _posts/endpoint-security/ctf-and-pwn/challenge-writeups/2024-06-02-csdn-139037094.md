# Vulnerability
There is a delay with a dependency relationship; the isvalid variable of each structure indicates whether the previous step has finished executing
It is divided into three stages
- Parse to get vid (there are checks: the register index and the content stored in the register (the accessed address) cannot exceed data_size)
- Execute to get alu
- Change values to get mem

vid and the value change do not happen immediately; if the parameter value is changed after vid is parsed (when the previous instruction reaches the mem step), the parameter checks in vid can be bypassed
# Approach
- Arbitrary address write via registers: store the address you want to write minus the value of database in a register, then use the mem-style mov [register+database], value or register to write the value to any address
- Arbitrary address read is similar: store the address you want to read minus the value of database in a register, then use the mem-style mov register, [register+database], and the register then holds the content at the address you want to read
