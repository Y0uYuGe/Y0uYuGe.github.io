# Virtualization and virtual machines
Virtualization: abstracting the various physical resources of a computer to present different virtual resources

Virtual machine: using virtualization technology to turn one computer into multiple logical computers — system virtualization in virtualization technology

Virtualization at different abstraction layers is divided into:
Hardware virtualization: presents an abstraction layer similar to physical hardware for virtual operating systems (VMware)
Operating system virtualization: provides an OS-like abstraction layer for multiple user spaces (docker)
Library function virtualization: virtualizes library functions so that applications can run with different libraries
Programming language virtualization: process-level virtualization, simulating a compiler/interpreter to generate machine code

Hardware virtualization:
Compute virtualization: virtualizes CPU and memory resources.
Network virtualization: virtualizes network link resources.
IO virtualization: virtualizes IO resources.
Storage virtualization: virtualizes disk storage resources

# Basic model
A computer can generally be divided into
physical hardware layer, operating system layer, application layer

A virtual machine can be divided into: virtual hardware layer, operating system layer, application layer

## Virtual hardware layer — VMM
It can be regarded as a software layer between the virtual machines and the hardware. This software layer not only abstracts the hardware layer, but is also responsible for creating and destroying VMs. And it provides a runtime environment for VMs

## Conditions for a VMM to satisfy the virtualized system architecture
Equivalence: running under the VMM is no different from running on the physical machine
Resource control: the VMM has complete control over the virtualized resources
Efficiency: the frequently used portion of machine instructions should execute directly on the hardware without VMM intervention (this improves efficiency)

# Two VMM schemes
The VMM sits at the same layer as the operating system, running on the hardware
The VMM sits at the same layer as the applications, running on the operating system

# Sensitive instructions and privileged instructions
Privileged instructions: the system has instructions that operate on and manage critical system resources; these instructions can only run correctly at the highest privilege level. If run at a non-highest privilege level, a privileged instruction raises an exception, and the processor traps into the highest privilege level to be handled by system software.

Sensitive instructions: instructions that operate on privileged resources, including modifying the running mode of the virtual machine or the state of the underlying physical machine; reading and writing clock and interrupt registers; accessing the storage protection system, the address relocation system, and all I/O instructions
Sensitive instructions must be completed under the VMM's supervision or through the VMM.

# Ring Compression
The VMM runs at the highest privilege level, while the Guest VM runs at a lower privilege level. When the Guest VM executes a sensitive or privileged instruction, it traps into the VMM at the highest privilege level, and the VMM then executes the sensitive or privileged instruction.
