## Background

Network scanning leaves patterns in connection metadata: destination ports, protocols, connection states, and packet counts. This project explores how those signals can support a detector for Nmap scanning behavior, bringing together traffic observation, supervised learning, and a visual processing workflow.

## Implementation

The repository contains two connected paths:

- **Training:** notebooks prepare labeled connection data, encode categorical fields, and train a `RandomForestClassifier`. `GridSearchCV` searches model parameters; the fitted estimator is saved with joblib.
- **Prediction:** the exported Node-RED flow starts Zeek, watches `conn.log`, converts selected fields into CSV, and sends newly read rows to a Flask service. The service applies feature transformations and returns predicted labels.

`run/model_api.py` exposes `POST /predict`, keeps prediction history, and provides JSON logs at `/log` and an HTML view at `/log_view`. A detection branch calls an email alert function. This makes the project useful for examining the interfaces between a network monitor, a classifier, and an application service.

## Running the project

The capture workflow requires a Linux environment with Zeek, Node-RED, Python, and permission to observe the chosen network interface. Python dependencies include pandas, NumPy, scikit-learn, joblib, and Flask. Before importing the flow, adapt its absolute paths, capture interface, and prediction URL to the local environment; configure email delivery separately if used.

The published tree uses `run/` and `train/`. These are the source paths to follow when reproducing the prototype, since the README's directory sketch differs from the checked-in files. Model results depend on the labeled dataset and evaluation split; the repository includes evaluation code for inspection.
