#  Deep Q Network
![在这里插入图片描述](/images/csdn/2025/csdn-145337075/image-001-b5d8ee3fe1.png)
This approach is well suited to grid games. Because each cell in a grid game is a state, which is discrete, but in real life many states are not discrete but continuous. So we can use a neural network to handle tasks with discrete states: the input is the state, and the outputs are the Q values corresponding to each action (which can also be understood as probabilities). In this way, the input can be continuous — that is, the state can be continuous

 
There is no fundamental difference between Q learning and DQN. DQN simply uses a neural network — that is, a function (the neural network) — to replace the original Q table. Deep network + Q learning = DQN

Here the Q values are the probabilities of different actions output by the neural network at the end

#  The Internal Implementation of zip(*batch)

First, let's look at how `batch` is constructed:

```python
batch = sample(history_memory, min(len(history_memory), args.batch_size))
```

`batch` is obtained by sampling from `history_memory`. Suppose `history_memory` is a list containing multiple experiences, where each experience is a 4-tuple (`state, reward, next_state, terminal`). Each element looks like this:

```python
[state, reward, next_state, terminal]
```

When you call `zip(*batch)`, `*batch` unpacks each 4-tuple in `batch` into four different lists or tuples, corresponding to `state`, `reward`, `next_state` and `terminal`.

## Suppose:
```python
batch = [
    (state_1, reward_1, next_state_1, terminal_1),
    (state_2, reward_2, next_state_2, terminal_2),
    (state_3, reward_3, next_state_3, terminal_3)
]
```

When you execute `zip(*batch)`, `*batch` is unpacked into the following four arguments passed to `zip()`:

```python
zip((state_1, reward_1, next_state_1, terminal_1), 
    (state_2, reward_2, next_state_2, terminal_2), 
    (state_3, reward_3, next_state_3, terminal_3))
```

Then, the `zip()` function "aligns" the elements of these tuples by position, producing the following result:

```python
[(state_1, state_2, state_3), 
 (reward_1, reward_2, reward_3), 
 (next_state_1, next_state_2, next_state_3), 
 (terminal_1, terminal_2, terminal_3)]
```

## Result:
`zip(*batch)` returns an iterator that produces a list containing four tuples (assuming there are three experiences in `batch`):

```python
(state_batch, action_batch, reward_batch, next_state_batch, terminal_batch)
```

These four tuples correspond to:

- `state_batch`: contains all the `state` values (`state_1, state_2, state_3`)
- `reward_batch`: contains all the `reward` values (`reward_1, reward_2, reward_3`)
- `next_state_batch`: contains all the `next_state` values (`next_state_1, next_state_2, next_state_3`)
- `terminal_batch`: contains all the `terminal` values (`terminal_1, terminal_2, terminal_3`)
