# _IO_2_1_stdout_ Leak
By tampering with the flags field and the _IO_write_base field in the _IO_2_1_stdout_ structure: tampering with the flags field bypasses some checks, and tampering with the _IO_write_base field makes the next put function's write syscall print the content between the _IO_write_base field and the _IO_write_ptr field, leaking the libc address.
1.  Allocate onto stdout (most commonly via the fastbin fd and the tcache fd)
2. Make the unsorted bin's fd appear in the corresponding fastbin fd or tcache fd
3. The last three hex digits of the stdout structure address are fixed, but the fourth-to-last digit is randomized due to ASLR. Since we can only write two bytes and cannot write one and a half bytes, the fourth-to-last digit can only be predicted through brute forcing.

# Vulnerability
Only chunks with sizes between 0x50~0x70 can be allocated, and the chunk array subscript is within 15.
You can exploit the array out-of-bounds to write into the chunk corresponding to the bin address stored in tcache (equivalent to edit-after-free, modifying the fd of a freed chunk). Meanwhile, there is no show function, so you need to leak libc through stdout_leak.


# Exploitation
- The starting chunk of the bin on tcache needs to contain a residual libc address, so that it can be modified for brute forcing when the array goes out of bounds
- You can first modify the residual heap address in a freed chunk, so that the obtained chunk can modify the size of the next chunk to be larger than fastbin; then when that chunk is freed, it can enter [the unsorted bin]


1. Allocate multiple chunks, free the first and the last one, and modify the fd of the latter (which goes into tcache) so that the corresponding chunk can cover the header of the original second chunk
2. malloc twice; on the second time, modify the size in the header of the second chunk to be larger than smallbin
3. Then free the third and fourth chunks into tcache, and free the second chunk into the unsorted bin
4. At this point, malloc a chunk size smaller than the third and fourth ones; the unsorted bin gets split. Since it is the only chunk in the unsorted bin, the remainder after splitting stays in the unsorted bin, and the split should be made so that its address ends up exactly overlapping the address of the fourth chunk
5. At this point, use the array out-of-bounds to modify the trailing bytes of the fourth chunk for brute forcing, and malloc twice, so that you finally obtain the stdout chunk
6. Craft the relevant stdout parameters and leak the libc base address
7. Finally, free two more chunks and modify the fd of the second chunk to the address of free_hook; the first malloc sets up /bin/sh, and the second malloc changes the value of free_hook to system
8. Finally, free the chunk that was malloc'd first to getshell
