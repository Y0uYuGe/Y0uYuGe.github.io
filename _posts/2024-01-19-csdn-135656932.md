# Performance Metrics
## Rate
How many bits of data the receiving end receives per unit time from the sending end
Pay attention to the conversion multiples between storage capacity and rate

![Image](/images/csdn/2024/csdn-135656932/image-006-9de92a1326.png)
## Bandwidth
The first figure shows the link after 3us; the three smiley faces represent the 1 bit of data sent onto the link in each of the three us
The second figure is similar, except that each us corresponds to 2 bits
![Image](/images/csdn/2024/csdn-135656932/image-007-d8847f2b32.png)

## Throughput
The sum of the rates of all links on an interface
For example, in the figure the throughput of the switch is 20mb/s + 10mb/s
![Image](/images/csdn/2024/csdn-135656932/image-008-c6ece327c9.png)
## Delay
### Transmission Delay
The time required from when the sender starts sending the first bit until the last bit is sent onto the link

When solving problems, bandwidth is usually treated as the sending rate, but in reality it is not that ideal

For example, if the length being sent is 10 and the sending rate is 10b/s, then according to the formula the transmission delay at this time is 1s
![Image](/images/csdn/2024/csdn-135656932/image-009-a46dc3acc0.png)
### Propagation Delay
It is the time to travel from one end of the link to the other
Electromagnetic waves travel slower in the link than in a vacuum
It depends on the length of the link and the propagation speed of electromagnetic waves
![Image](/images/csdn/2024/csdn-135656932/image-010-1df8844dda.png)

### Queuing Delay and Processing Delay
At this point 10 bits have arrived at the router, but because the router is busy, these bits are first placed in the router's buffer space to wait for a while. This waiting time can be called the queuing delay

The processing delay is the time required when the router starts processing these bits after queuing ends. After processing, it must wait for the outgoing link to become available before sending to the router's corresponding exit
![Image](/images/csdn/2024/csdn-135656932/image-011-29985dc7b5.png)
### Supplement: High-Speed Links
High speed only increases the bandwidth; the propagation delay is not affected
![Image](/images/csdn/2024/csdn-135656932/image-012-ee68b31b6c.png)
## Delay-Bandwidth Product
The bandwidth is the bandwidth at which the sender sends onto the data link

The link is a cylinder, and the bandwidth is the cross-section

It can be understood as: every unit of time, one bandwidth's worth of bits is sent onto the link, and as time goes on they propagate along the link, thus forming a link length made up of bits
![Image](/images/csdn/2024/csdn-135656932/image-013-5d489f77bf.png)

## Round-Trip Time (RTT)
 The end processing time is sometimes ignored, depending on the problem requirements

In this definition, the receiver sends an acknowledgment immediately after receiving the data

The start is when data begins to be sent, i.e. when bits start being placed; the end is when the first bit of the received acknowledgment arrives
Data can keep being sent until an acknowledgment is received. The larger the RTT, the later the acknowledgment is received, the more time is spent sending, and the more data is sent

![Image](/images/csdn/2024/csdn-135656932/image-014-b20c94fe66.png)
## Utilization
Channel utilization: the link is considered utilized when there is data passing over it

If utilization is high, it means there is data more of the time, and correspondingly there is more data on the link, which causes congestion, i.e. queuing

Why does high utilization mean more data on the link?
Because we assume there is data at every moment, i.e. the utilization is high. At this point, since some data flows out at every moment, if there is not much data on the link, there may happen to be no data left after it flows out, whereas if there is a lot, there will still be data after it flows out, which corresponds to high utilization
![Image](/images/csdn/2024/csdn-135656932/image-015-bf90e31004.png)


## Summary
