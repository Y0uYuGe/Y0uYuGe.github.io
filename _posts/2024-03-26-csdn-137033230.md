# USER Namespace
That is, the process runs in a new namespace, and the User ID and Group ID in that namespace can be different inside and outside the namespace, so a user can be root in the namespace but not root on the host

Just add syscall.CLONE_NEWUSER to Cloneflags
![Image](/images/csdn/2024/csdn-137033230/image-001-46fb32ea4b.png)
# Code

```go
package main

import (
	"os/exec"
	"os"
	"syscall"
	"log"
)

func main(){
	cmd:=exec.Command("sh")
	cmd.SysProcAttr=&syscall.SysProcAttr{
		Cloneflags: syscall.CLONE_NEWIPC|syscall.CLONE_NEWPID|syscall.CLONE_NEWUTS|syscall.CLONE_NEWNS|syscall.CLONE_NEWUSER,}
	cmd.Stdin=os.Stdin
	cmd.Stdout=os.Stdout
	cmd.Stderr=os.Stderr

	if err:=cmd.Run();err!=nil{
		log.Fatal(err)
	}
}
```
#  NETWORK Namespace

Network Namespace is a namespace used to isolate network resources such as network devices, IP addresses, and ports

That is, the process has independent (virtual) network devices in the namespace. Moreover, after setting up a bridge on the host, communication between containers can be easily achieved, and applications on different containers can use the same ports

Just add syscall.CLONE_ NEWNET to Cloneflags

I found that processes in the network namespace have no network devices (maybe there are none by default and relevant initialization is needed), while the host still has network devices
![Image](/images/csdn/2024/csdn-137033230/image-002-ae7822873e.png)
