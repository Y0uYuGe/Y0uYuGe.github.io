# Union File System
- It merges multiple directories into a single directory
- It uses a mechanism called copy-on-write (COW). If the file to be modified is located in a read-only layer, UnionFS copies the file to the topmost writable layer and modifies it there. This ensures that the underlying filesystem remains unchanged, while the changes only happen at the top layer.


# overlay Mounting
Use the mount command to mount to a certain location; you need to specify lowerdir, upperdir, workdir, merged_dir
```bash
mount -t overlay overlay -o lowerdir=lower1:lower2:lower3,upperdir=upper,workdir=work merged_dir
```
This command puts the contents of the directories lower1, lower2, lower3, upper, and work into the merged_dir directory

lowerdir: the read-only layer, corresponding to the files of all layers below the current layer
upperdir: the read-write layer, the files of the current layer
workdir: don't worry about it
merged_dir: where the merged result is placed


At this point, if you modify the contents of a file, if the file comes from lowerdir, then after the file is modified, a file with the modified content appears in upperdir, but the content in lowerdir does not change

At this point, if you delete a file from merged_dir, if the file comes from lowerdir, then after the deletion in merged_dir, a whiteout file appears in upperdir (which marks that the file is gone), but the file in lowerdir does not change

# Images, Containers, and overlay2
Actually, `/var/snap/docker/common/var-lib-docker/overlay2` can also store the init layer and the container layer. A complete container is divided into 3 layers: image layer, init layer, and container layer. When docker creates a container, it creates the init layer and the container layer

 overlay2 uses union mount technology to mount the diff of the image layer, the diff of the init layer, and the diff of the container layer to the merged directory of the container layer

- init layer: does some configuration the container needs; because the image layer is a read-only layer and cannot be modified, init is used for configuration
- image layer: corresponds to the images below the container layer
- container layer: corresponds to the directory where the mounted merge is located

At this point the corresponding overlay mount hierarchy is as follows
- lowerdir: the diff files of the images below the container layer
- upperdir: the diff file of the container layer
- merged: the merged of the container layer

![在这里插入图片描述](/images/csdn/2024/csdn-137211344/image-005-8eed029bfe.png)
The container layer merges the init layer and image layer with the same name into the merged layer of the container layer
