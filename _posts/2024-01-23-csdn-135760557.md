# Traditional Computers
A traditional physical machine has only one operating system.
Running two processes on the same operating system carries some risks (mutual interference, contention for resources, etc.).
Solution: if each process runs on a different operating system (different physical machines), these risks disappear. But this wastes the physical machine's hardware resources, because one physical machine could potentially run multiple processes.

# Virtual Machines

 In the first type, the VMM manages the hardware resources and allocates them to the individual virtual machines.
 A single-core CPU can be divided into time slices so that different virtual machines use different time slices; from each VM's point of view it looks like a dedicated CPU (essentially, some of the CPU's time slices are assigned to the VM). Disk and memory are likewise partitioned into regions for different virtual machines.
 The VMM runs in kernel mode and can execute privileged instructions, while the VM's kernel mode and user mode both run in guest mode.
 The VM's operating system believes it is in kernel mode; when it executes a privileged instruction, the VMM traps it and performs an equivalent transformation, so the VM believes the instruction executed successfully.
 ![Image](/images/csdn/2024/csdn-135760557/image-001-8b47947aeb.png)

In the second type, the VMM runs as a process on top of a host operating system. The VMM must request hardware resources from the host OS and then redistributes them. The actual manager of the hardware resources is still the host operating system.

Note that both types of virtual machines run, from the host's perspective, as a process of the host machine.
![Image](/images/csdn/2024/csdn-135760557/image-002-61121ed169.png)
# Comparison of VMMs
Resource allocation: the first type directly obtains physical addresses and, after partitioning and assigning them to virtual machines, virtualizes them into the VM's virtual addresses. The second type of VMM requests a large virtual space from the Host OS and then partitions and assigns it to the virtual machines (both memory and storage are virtual addresses); the VM then treats the virtual address it receives as a physical address, so it must be virtualized once more into what the VM considers its virtual addresses.

Number of supported virtual machines: the first type has no host OS and no host OS processes; it runs entirely the virtual machines, so the VMs occupy most of the hardware resources and more VMs can be supported. In the second type, the host OS and its processes also need hardware resources, so the virtual resources available to VMs are relatively fewer, and naturally fewer virtual machines are supported.

Migratability: the first type of VM holds physical addresses, so migrating to another VMM has fairly cumbersome physical-address requirements. The second type of VM holds virtual addresses allocated by the host OS, which are much easier to satisfy.

Execution modes: in the first type, assume the VMM is in ring0, the guest OS in ring1, and the guest user space in ring2; instructions are dispatched to different places based on type. You can think of privileged instructions as split between ring1 and ring0: non-sensitive instructions are placed in ring1 (by requiring the guest OS to handle ring1 instructions so they jump to the guest OS for execution) and sensitive instructions in ring0, so fewer instructions trap to the VMM and the number of switches into the VMM is naturally reduced. In the second type, the VMM lives partly in the kernel and partly in user space; system calls become nested like Russian dolls: after the guest application issues a system call it switches to the guest kernel mode, the guest OS passes the system call to the VMM, and the VMM then makes the request to the host OS.

# CPUs Supporting Virtualization Usually Have More Instruction Levels (Privileged vs Sensitive)
Privileged instructions usually include the sensitive instructions.

In virtualization technology, privileged instructions and sensitive instructions are both concepts closely tied to the CPU's execution privileges and resource management. Specifically:

Privileged instructions: instructions that can only be executed at the highest privilege level (usually kernel mode or ring 0). These instructions can access and manipulate the computer's critical resources, such as the memory management unit and I/O devices.
Sensitive instructions: in a virtualized environment, the instructions that the Virtual Machine Monitor (VMM) must trap and emulate so that the guest OS can run without directly accessing the hardware.
In most cases, sensitive instructions are indeed privileged instructions, because they typically involve accessing and managing critical system resources. For example, on RISC processors (such as MIPS, PowerPC, SPARC), sensitive instructions are a subset of privileged instructions. However, on the x86 architecture, although the vast majority of sensitive instructions are privileged, there are also some sensitive-but-not-privileged instructions, which do not automatically trigger a trap for the VMM to intercept when executed.

In summary, privileged instructions and sensitive instructions both play important roles in virtualization technology; they ensure the security and stability of the system.
