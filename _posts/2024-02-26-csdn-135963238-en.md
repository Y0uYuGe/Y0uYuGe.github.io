# Setting Breakpoints in Namespaces
## Namespace

> A namespace (English: Namespace), also called naming space, name space, etc., indicates the visible scope of an identifier. An identifier can be defined in multiple namespaces, and its meaning in different namespaces is independent of each other. In this way, any identifier can be defined in a new namespace without conflicting with any existing identifier, because the existing definitions all reside in other namespaces.

> For example, suppose Bill is an employee of company X with employee ID 123, and John is an employee of company Y, also with employee ID 123. Since the two work at different companies, the same employee ID can be used to identify them without confusion; here each company represents an independent namespace. If the two worked at the same company, their employee IDs could not be the same, otherwise confusion would occur when paying salaries.

# Saving Breakpoints That Have Been Set
In GDB, you can use the save command to save your breakpoints. Here are the steps to use this command:

- First, you need to set the breakpoints you want. You can use the break command to set breakpoints. For example, if you want to set a breakpoint on the function foo, you can type break foo.

- Once you have set breakpoints, you can use the info breakpoints command to view all the breakpoints you have set.

- Finally, you can use the save command to save your breakpoints. You can choose to save them to a specific file; for example, save breakpoints my_breakpoints will save the breakpoints to the my_breakpoints file.

> Note: the save command will save all breakpoints, not just the one you just set.

![在这里插入图片描述](/images/csdn/2024/csdn-135963238/image-009-aa89371a9a.png)

In GDB, the source command is used to execute a file as a sequence of GDB commands.

The source command is very useful, especially when you need to repeatedly execute a series of complex commands. You can write these commands into a script file and then use the source command to execute the commands in that file, which can greatly improve debugging efficiency. For example, if you have a complex debugging session containing multiple breakpoints and watchpoints, you can save all the settings into a script, and the next time you debug you only need to load that script.

# Setting Conditional Breakpoints

```c
/* a/file.c */
#include <stdio.h>

void print_a (void)
{
  puts ("a");
}

/* b/file.c */
#include <stdio.h>

void print_b (void)
{
  puts ("b");
}

/* main.c */
extern void print_a(void);
extern void print_b(void);

int main(void)
{
  int i=1;
  print_a();
  print_b();
  i=2;
  return 0;
}
```
![在这里插入图片描述](/images/csdn/2024/csdn-135963238/image-013-c9e424e30c.png)

In GDB, you can use the break command to set conditional breakpoints. A conditional breakpoint allows you to specify an expression; the program stops at that location only when the value of the expression is true.

**Whether a breakpoint takes effect when execution reaches it depends on whether the condition is satisfied at the moment execution reaches the breakpoint, not on whether the condition was satisfied when the breakpoint was set**

Here are the steps to set a conditional breakpoint:

1. First, you need to set the breakpoint you want. You can use the break command to set breakpoints. For example, if you want to set a breakpoint on the function foo, you can type break foo.

2. Then, you can use the condition command to add a condition to that breakpoint. For example, if you want to stop execution at that breakpoint only when the variable x is greater than 10, you can type condition 1 x>10.

3. Finally, you can use the info breakpoints command to view all the breakpoints you have set along with their conditions.

**Note: if the result of the conditional expression is false, the program will not stop at that location. In addition, you can use the commands command to specify a sequence of commands to execute when the condition is satisfied.**
## The commands Command
In GDB, the commands command can indeed specify a group of commands that are automatically executed each time the program runs to a certain breakpoint. Here is how to use the commands command:

Specify the breakpoint: First, you need an already-set breakpoint; you can use the break command to set one. For example, break main sets a breakpoint at the main function.
Add commands: Then, you can use the commands command followed by the breakpoint number to add commands to be executed for that breakpoint. For example, if you want to print the value of the variable x at breakpoint 1 and continue executing the program, you can enter:
        
```bash
commands 1
silent
print x
continue
end

```
Here, the silent command is used to prevent GDB from displaying prompt messages from the continue command.
View breakpoints: Finally, you can use the info breakpoints command to view all the breakpoints you have set along with their associated commands.
In addition, you can combine the commands command with conditional breakpoints to execute a series of commands under specific conditions. For example, if you want to print the value of the variable x at a breakpoint when x is greater than 10, you can set the following commands:

```bash
break 2 if x > 10
commands 2
silent
print x
continue
end
```

    
In this way, the commands command can help you automate some repetitive tasks during debugging, thereby improving debugging efficiency.


# Ignoring Breakpoints

```c
#include <stdio.h>
	
int main(void)
{
        int i = 0;
		int sum = 0;

		for (i = 1; i <= 200; i++)
		{
			sum += i;
		}
	
		printf("%d\n", sum);
        return 0;
}
```

After setting a breakpoint, you can ignore it with the command "ignore bnum count": this means that the next count triggers of breakpoint number bnum will not interrupt the program, and only the (count + 1)th and later triggers will interrupt the program. Take the above program as an example:
