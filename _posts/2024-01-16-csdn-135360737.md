## sub_40136E()

```c
__int64 sub_40136E()
{
  char v1[10]; // [rsp+6h] [rbp-2Ah] BYREF
  _QWORD v2[4]; // [rsp+10h] [rbp-20h] BYREF

  v2[0] = 0x6F6E6B2075206F44LL;
  v2[1] = 0x6920746168772077LL;
  v2[2] = 0xA3F444955532073LL;
  strcpy(v1, "easyhack\n");
  syscall(1LL, 1LL, v1, 9LL);
  syscall(0LL, 0LL, &unk_404060, 4096LL);
  syscall(1LL, 1LL, v2, 24LL);
  syscall(0LL, 0LL, v1, 58LL);
  return 0LL;
}
```
1. First print out the nine characters of v1
2. Then read 4096 bytes into the position at offset 404060 on the bss segment
3. Then output the 24 bytes in v2 to the terminal
4. Then read 58 bytes into v1
# Approach
There is a stack overflow vulnerability, and only rbp and the return address can be modified — stack migration is clearly needed
If, after stack migration, we directly use the shellcode obtained from onegadget, the conditions it must satisfy are quite tricky, and we also need to obtain the libc base address
Obtaining the base address should be achievable by executing the sub_40136E() function twice (starting from the second time, rsp needs to be restored to match the call invocation style, i.e. rsp needs to be decremented by 8), because v1 has both output and input. Satisfying the conditions of the corresponding shellcode is rather troublesome — I look forward to everyone's attempts
![Image](/images/csdn/2024/csdn-135360737/image-006-7e79d8a573.png)

So if we can't getshell, we use orw — which is also obvious in combination with the sandbox. orw needs many syscall-related gadgets, and without having obtained the libc base address, the corresponding gadgets can be implemented via SROP

1. The first input constructs the ROP chain for after stack migration
   ROP chain:
   Construct the sigreturn frame for the first read, so that the flag file location string we need is input into a writable memory location
   Whether a chmod sigreturn frame is needed at this point depends on the situation
   Construct the sigreturn frame for the first open, opening the file corresponding to flag; the corresponding file descriptor is 3
   Construct the sigreturn frame for the second read, reading the contents of the flag file into some writable memory location
   Construct the sigreturn frame for the first write, outputting the flag contents written into memory to the terminal to obtain the flag
   
3. The second input performs stack migration to reach the ROP chain listed above

# Notes

The rt_sigreturn system call function updates the values of all registers; those not set default to 0, so set every necessary register — there is no order-dependent sequential update.

> When file 1 and file 2 are created, since the process first opens 0, 1, 2 at startup (corresponding to stdin, stdout, stderr respectively), fd1=3 and fd2=4.
> After file 1 is closed, fd=3 is released, so when file 3 is created, fd3 is assigned the current smallest descriptor, i.e. the just-released fd1, so fd=3.

The argument settings of the open and chmod functions are a bit special because they involve strings, which is tricky to set in a sigreturn frame.
For chmod
> int chmod(const char *pathname, mode_t mode);
The second argument has the following settings, which can be combined via OR to set them simultaneously
S_ISUID	set-user-ID on execution
S_ISGID	set-group-ID on execution
S_ISVTX	saved-text (sticky bit)
S_IRWXU	user read, write, execute
S_IRUSR	user read
S_IWUSR	user write
S_IXUSR	user execute
S_IRWXG	group read, write, execute
S_IRGRP	group read
S_IWGRP	group write
S_IXGRP	group execute
S_IRWXO	others read, write, execute
S_IROTH	others read
S_IWOTH	others write
S_IXOTH	others execute


The corresponding setting in the sigreturn frame is constants.S_IRUSR | constants.S_IRGRP | constants.S_IROTH, i.e. user read | group read | others read

> int open(const char *pathname, int flags);

The first argument path means: a path name or a file name. A path name is an absolute path (e.g. C:/cpp/a.cpp), while a file is in the current working directory.

The second argument oflags means: the action taken when opening the file.

    Possible values: exactly one of the following must be specified:

    O_RDONLY (read-only),

    O_WRONLY (write-only),

    O_RDWR (readable and writable)

When opening/creating a file, at least one of the three constants above must be used
The following constants are optional; these options are bitwise-ORed with the mandatory options above to form the flags argument.

- O_APPEND means append; if the original file has content, this write goes to the very end of the file.
- O_CREAT means: if the specified file does not exist, create this file
- O_EXCL means: if the file to be created already exists, an error occurs, -1 is returned, and the value of errno is modified.
- O_TRUNC means truncate; if the file exists and is opened write-only or read-write, its length is truncated to 0.
- O_NOCTTY: if the path name points to a terminal device, do not use this device as the controlling terminal.
- O_NONBLOCK: if the path name points to a FIFO/block file/character file, the file open and subsequent I/O are set to nonblocking mode-

**The following three constants are also optional; they are used for synchronized I/O**

- O_DSYNC: wait for physical I/O to complete before write. Without affecting the reading of newly written data, it does not wait for file attribute updates.
- O_RSYNC: read waits until all write operations to the same region complete before proceeding
- O_SYNC: wait for physical I/O to complete before write, including I/O that updates file attributes

The corresponding setting in the sigreturn frame is constants.O_RDONLY, opening in read-only form here
