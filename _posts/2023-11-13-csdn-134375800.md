## movabsq
movabsq is a newly added instruction. It is used to store a 64-bit value directly into a 64-bit register.
## ja
JA (jump above) jumps to the target instruction if greater. It compares the magnitude relationship between two unsigned numbers and jumps if greater
##   pretty_alert
This damn function uses printf, and one printf call takes pretty_alert's first argument as its first argument. This can be exploited with a format string vulnerability. (This can be discovered from the output and dynamic debugging)

# Let's pwn
All protections enabled (standard practice in foreign competitions)
![Image](/images/csdn/2023/csdn-134375800/image-003-8794324c00.png)
Normal logic can't bypass exit; we can only use printf format strings, but we can only printf once before exit, so we have to bypass exit. pretty_alert and exit(0) are adjacent — why not use printf's arbitrary write to change pretty_alert's return address?

#  Approach
The overflow can modify the values of the variables that follow
Found an exploitable rbp chain; two rounds of nesting will do
The first nesting modifies the value at some position on the stack to the address of the return address
The second nesting modifies the actual content at that return address position to the function that printfs the flag

However, note that the content modified the first time in a single printf may not have been updated in time for the second modification, so
