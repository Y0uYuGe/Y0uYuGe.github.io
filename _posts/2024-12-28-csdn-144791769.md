### **Direct implementation suits 8-bit processors**

#### **Why is it suitable for 8-bit processors?**
- **An 8-bit processor** can only process **8 bits (1 byte)** of data at a time. The core algorithms of AES (such as S-Box, ShiftRows, MixColumns, etc.) are matrix-based operations, which in this case can only process each byte step by step.
- Because 8-bit processors have inherently low performance and limited resources, using a direct implementation is simpler and easier to use.

#### **Example:**
One AES data block is **128 bits (16 bytes)** in size. If the processor can only process 8 bits (1 byte) at a time, it must process each byte one by one. For example:
1. AES needs to encrypt a 128-bit block of data.
2. Only 8 bits (1 byte) can be processed each time, so **128 ÷ 8 = 16 steps** are required.
3. Each step involves multiple computations (e.g., byte substitution, ShiftRows, MixColumns, etc.), so the entire process may take hundreds of instruction cycles.

Although this byte-by-byte approach is simple, it is inefficient on **32-bit or 64-bit processors**, because they can process more data at once (for example, a 32-bit processor can handle 4 bytes simultaneously, and a 64-bit processor can handle 8 bytes).

---

### **Optimized table lookup method**

#### **Why is optimization needed?**
- On modern 32-bit or 64-bit processors, byte-by-byte processing is too slow. The idea of optimization is: **replace complex computations with lookup tables**.
- A lookup table is a collection of precomputed results; the corresponding result is found directly through an index (such as the value of a byte), without real-time computation.

#### **Optimization methods:**
1. **S-Box optimization:**
   - The S-Box is the table used in AES to substitute bytes (each byte is replaced by a specific byte), so a lookup table with 256 entries can be generated in advance.
   - Whenever a byte needs to be substituted, you can simply look it up in the table.
   
2. **Merging operations:**
   - Not only the S-Box, but also the other AES operations (such as ShiftRows and MixColumns) can be merged into a single lookup table.
   - In this way, all computations for each byte can be completed at once through a table lookup.

3. **Final optimization:**
   - Generate **4 tables**, each containing **256 entries**, with each entry **32 bits wide**.
   - Each round of AES only needs 16 table lookups to complete all byte processing. (16 bytes; the table contains the results of all the operations corresponding to each byte)

#### **Example:**
Suppose AES needs to process a 128-bit data block:
- **Original approach:** byte-by-byte processing requires hundreds of instruction cycles (e.g., S-Box substitution + ShiftRows + MixColumns for each byte).
- **Optimized approach:** each byte only needs 1 table lookup, so the entire data block needs **16 table lookups**, greatly reducing the number of instructions and the computation time.

This optimization is very well suited to modern processors, because modern processors are good at efficient table lookup operations.

---

### **Speed on modern 64-bit processors**

#### **Why is it faster?**
Modern 64-bit processors can process multiple pieces of data in parallel:
1. The lookup tables can be placed in the processor's cache, making table lookups extremely fast.
2. A 64-bit processor can process 8 bytes of data at the same time, so the parallelism of the computation is greatly improved.

#### **Example:**
- Suppose AES needs to encrypt a file:
  - The file size is **2 GB (about 1.6 billion bits)**.
  - In the optimized implementation, the processing speed of AES is **1.6 Gbit/s**.
  - Processing a 2 GB file only takes **2 × 8 ÷ 1.6 = 10 seconds**.

The optimized table lookup method makes AES encryption extremely fast on modern hardware.

# Security

### **1. Brute-force attack**
**Translation:**  
Since the AES key length is 128 bits, 192 bits, or 256 bits, brute-force attacks are infeasible.

**Explanation:**  
- **What is brute-force cracking?**  
  Brute-force cracking refers to trying all possible key combinations until the correct key is found. For AES, the security of the encryption depends on the key length.
  
- **Why is it infeasible?**  
  - The key lengths used by AES are very large:
    - **128-bit key**: the total number of possible keys is \(2^{128}\), about \(3.4 \times 10^{38}\).
    - **192-bit key**: the total number of possible keys is \(2^{192}\), about \(6.3 \times 10^{57}\).
    - **256-bit key**: the total number of possible keys is \(2^{256}\), about \(1.1 \times 10^{77}\).
  - Even with the fastest supercomputer available today, the time required to exhaust these keys far exceeds the lifetime of the universe, so brute-force cracking is impossible.

---

### **2. Analytical attacks**
**Translation:**  
There is currently no known analytical attack that is more effective than brute force.

**Explanation:**  
- **What is an analytical attack?**  
  An analytical attack refers to breaking the encryption directly through mathematical or algorithmic weaknesses, without trying all the keys. For example, an attacker might try to find a vulnerability in the AES algorithm to shorten the cracking time.

- **The situation with AES:**  
  - AES has undergone rigorous mathematical validation, and no weaknesses are known in its design.
  - At present, all known attacks against AES require a computational effort comparable to, or even greater than, brute force.
  - Therefore, AES remains secure by design, and no known analytical attack can defeat it.

---

### **3. Side-channel attacks**
**Translation:**  
- Several side-channel attacks have been made public.  
- It should be noted that side-channel attacks do not target the algorithm itself, but rather the specific implementation of the algorithm.

**Explanation:**  
- **What is a side-channel attack?**  
  A side-channel attack does not directly break the encryption algorithm; instead, it exploits physical information leaked during the encryption operation (such as timing, power consumption, or electromagnetic radiation) to infer the key or the encrypted data.
  
- **Examples:**  
  1. **Timing attack:**  
     By measuring the execution time of encryption operations, the attacker infers certain parts of the key.
  2. **Power analysis:**  
     By observing the fluctuations in a device's power consumption during encryption, the attacker analyzes the internal operational details.
  3. **Electromagnetic attack:**  
     By analyzing the electromagnetic signals generated by a device during encryption, the attacker extracts critical information.

- **Why doesn't it affect the algorithm itself?**  
  Side-channel attacks do not target weaknesses in the AES algorithm itself; they exploit vulnerabilities in the device's implementation.  
  **For example:**
  - If certain steps of the encryption operation are inconsistent in timing, an attacker can exploit these timing differences to infer the key.
  - If the hardware is poorly designed, it may leak more electromagnetic information, making it easier for attackers to obtain encrypted information.
