# Why Do We Need a Function Calling Convention?
 
![Image](/images/csdn/2024/csdn-136702466/image-003-bb5c5368fc.png)
A function calling convention exists to ensure that communication and data transfer between the callee and the caller can proceed efficiently during a function call. It specifies how registers are used, how parameters are passed, how return values are returned, how the stack is managed, and so on. The existence of a function calling convention provides the following benefits:

- Consistency and portability: The function calling convention defines general rules and standards, ensuring that the interactions between different functions are consistent and predictable. This allows compilers to generate code that follows the same convention, so that the code can be ported and executed across different compilers and platforms.

- Register allocation and management: The function calling convention specifies which registers should be saved and restored by the callee during a function call, and which registers can be used by the caller. This ensures that the use of registers between functions does not interfere with one another, and that registers are correctly restored after the function call ends.

- Parameter passing: The function calling convention defines how function parameters are passed. By agreeing on how parameters are passed, the compiler and assembler can efficiently handle the passing of function parameters and generate correct assembly and machine code. Common parameter passing methods include storing parameter values in specific registers, passing parameters via the stack, and so on.

- Return value passing: The function calling convention specifies how a function returns a value to the caller. By defining how return values are passed, the compiler and assembler can generate correct code and ensure that function return values are correctly returned to the caller.

- Stack management: The function calling convention defines how the stack is managed during a function call, including how stack frames are allocated and released, how the stack pointer is managed, and so on. This ensures that the use of the stack during function calls is safe and reliable.

	la sp, stack_end	# prepare stack for calling functions

	lw s1, 4(sp)
	addi sp, sp, 8

	ret

```bash
.section .text
.globl square
.type square, @function
square:
  li t0, 0       # 设置寄存器 t0 为 0 (sum)
  mul a0, a0, a0  # 计算 a0 * a0，并将结果保存在 a0 中
  mv a1, a0      # 将计算结果保存在 a1 中
  jr ra           # 返回到调用者

.globl sum_squares
.type sum_squares, @function
sum_squares:
  li t0, 0       # 设置寄存器 t0 为 0 (sum)
  li t1, 1       # 设置寄存器 t1 为 1 (j)

loop:
  bgt t1, a0, end_loop  # 如果 t1 大于 a0，则跳转到 end_loop 标签处
  mv a0, t1             # 将 j 的值保存在 a0 中
  jal ra, square        # 调用 square 函数，计算平方并返回结果放置在 a0 中
  add t0, t0, a0        # 将计算结果加到 sum 中
  addi t1, t1, 1        # j++
  j loop               # 继续循环

end_loop:
  mv a0, t0   # 将 sum 的值保存在 a0 中
  jr ra       # 返回到调用者

.globl _start
.type _start, @function
_start:
  li a0, 3    # 设置 a0 为 3
  jal ra, sum_squares  # 调用 sum_squares 函数
```

Embedding RISC-V assembly language into C code requires the use of inline assembly. The syntax and usage of inline assembly may vary by compiler; the following is a general example showing how to embed RISC-V assembly language into C code.

Core syntax:

```c
asm("assembly code"
    : output operands
    : input operands
    : clobbered registers);
 
```

- assembly code: This is the RISC-V assembly code to be embedded.
- output operands: Represent the output operands, which can be variable names, registers, or memory addresses.
- input operands: Represent the input operands, which can likewise be variable names, registers, or memory addresses.
- clobbered registers: Specify the registers that are modified.
- Note: Each item is separated by a colon (:), but there is no colon after the last item.

1. Operand constraints:
In inline assembly, operand constraints are used to specify the register constraints in the embedded assembly code.

For example, register constraints include the following characters: r (general-purpose register), a (argument register), and f (floating-point register). Numbers indicate specific registers. For example, %0 refers to the first operand, %1 refers to the second operand, and so on.

2. Input and output operands:
In inline assembly, output and input operand constraints can be used to specify variable names in C code as the inputs and outputs of the assembly code.

3. Output: Use the = symbol together with a constraint to specify an output operand. For example, "=r"(output_var) means outputting the result into the output_var variable.
Input: Use an input operand constraint to specify an input operand. For example, "r"(input_var) means using the input_var variable as an input operand.
4. Clobbered registers:
In inline assembly, you can specify which registers are modified, so that the compiler will save them before the embedded assembly and restore them afterwards.

For example, "cc" indicates all registers that may be modified; "memory" indicates that the embedded assembly may modify memory. These constraints ensure that the embedded assembly code does not produce side effects on other code.

Below is an example of embedding RISC-V assembly into C code:

```c

int main() {
   int a = 10, b = 20, sum;

   asm volatile (
      "add %0, %1, %2\n\t"  // 使用RISC-V汇编的加法指令
      : "=r"(sum)           // 输出操作数（结果）使用寄存器约束，保存在sum变量中
      : "r"(a), "r"(b)      // 输入操作数使用寄存器约束，对应a和b变量
      : "cc"               // 修改寄存器
   );

   return 0;
}
```

 
In this example, we use the add instruction of RISC-V assembly to perform the addition of a and b, and store the result in the sum variable.

```c
int foo(int a, int b)
{
    int c;
    asm volatile(
        "mul %[result_a], %[a], %[a]\n"
        "mul %[result_b], %[b], %[b]\n"
        "add %[c], %[result_a], %[result_b]\n"
        : [c] "=r" (c)
        : [a] "r" (a), [b] "r" (b), [result_a] "r" (0), [result_b] "r" (0)
    );
    return c;
}
 
```

By embedding the asm volatile directive, we can embed RISC-V assembly code within a C function. In the assembly code, the mul instruction is used to store the square of a in the result_a register and the square of b in the result_b register, and then the add instruction adds the values of result_a and result_b and stores the result in the c register. Finally, the constraint operand ([c] "=r" (c)) is used to store the value of the c register into the variable c, and the values of variables a and b are stored in the corresponding registers.
