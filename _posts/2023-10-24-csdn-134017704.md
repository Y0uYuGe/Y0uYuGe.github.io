### house of force
When requesting a heap allocation, if all the chunks that have already been freed cannot satisfy the requirement (all bins fail), and at the same time the top chunk size minus the size of the chunk to be allocated still satisfies the minimum chunk size, then a chunk of the corresponding size is split from the top chunk as the requested heap space.


By controlling the top chunk size value (change it to -1 because of the corresponding unsigned form), then malloc makes the top chunk jump to any position; then malloc again (that position satisfies the chunk format) so you can control the content at that position

Controlling memory forward:
1. Take the chunk pointer obtained from an already-allocated chunk and add a certain value so that its corresponding address is the address of top chunk size
2. Modify by dereferencing the modified pointer content
3. malloc a suitable value (after checks and conversion) so that the modified top chunk size value satisfies the conditions, and at the same time the top chunk address plus the malloc argument gives the needed address

When a negative number is passed in, we know that whether it is an unsigned number or a signed number, it actually adds their corresponding binary-encoded forms; only the way the final result is interpreted differs. If the sum of the two in signed form is positive, then the sum in unsigned form is exactly the same.

Controlling memory backward:
Same as above, except the argument is positive

Formula: newchunk address - 0x10 - topchunk address = malloc argument

(64-bit)
When the argument is negative, the computed number is still a multiple of 0x10. After adding SIZE_SZ + MALLOC_ALIGN_MASK and then performing & !MALLOC_ALIGN_MASK, the result is equivalent to the original number plus 0x10 and remains unchanged (32-bit is similar)

## Hijacking _malloc_hook and _free_hook
When malloc and free are called, they jump according to the function addresses stored in the _malloc_hook variable and the _free_hook variable, thereby executing the corresponding functions. In this case, malloc's argument corresponds to the allocation size, and free's corresponds to some address (overwrite the /bin/sh string at the chunk userdata)


What each bins linked list stores in the bins array is an fd member and a bk member

Memory freed by the user is not always returned to the system immediately; ptmalloc uniformly manages the freed chunks in the heap and mmap. When the user makes the next allocation request, ptmalloc first tries to pick a chunk from the freed chunks for the user. There are 128 bins, stored using an array: bin 1 is the unsorted bin, bins 2-63 are small bins, bins 64-126 are large bins, and there is also a fastbin array (sized according to the size field)
###  fastbin
Last in, first out
Only the fd member is used; it is a singly linked list structure
The P bit is not modified; chunks are not actively merged, but they do merge in certain specific cases
fastbinY is the array that manages fastbins; each member manages a linked list of a different size, and all point to the tail node of the current list
During malloc, it first looks in the fastbin for a suitable freed chunk

#### fastbin_attack
Freed chunks in the fastbin are connected with a singly linked list, using only fd, and if a chunk would enter the fastbin after being freed, even after it is freed its next physically adjacent chunk will not set the pre_inuse bit to 0 (0 means the previous chunk has been freed, 1 means it is still in use)

##### Checks when freeing into the fastbin:
1. The chunk's IS_MMAPPED bit cannot be 1
2. The chunk's address must be aligned
3. The size must satisfy the fastbin recycling requirements
4. The head of the linked list cannot be this fakechunk
5. The size of the fake chunk's (physically adjacent) nominal next chunk cannot be less than 2*SIZE_SZ, and cannot be greater than av->system

C's free() function does not automatically set the pointer to NULL
##### fastbin double free
1. After a chunk is freed, the pre_inuse bit of the next physically adjacent chunk is not cleared, so free thinks it is still in use
2. When freeing a chunk into the corresponding fastbin, only the chunk directly pointed to in the list array is checked; the ones after it are not checked. So freeing twice in a row does not work, but freeing another chunk in between the two frees succeeds

fastbin: when the program mallocs and the malloc size is to be picked from the fastbin, the newly added one is chosen for allocation, i.e., first in, first out
##### Approach:
1. free(chunk1)  free(chunk2)  free(chunk1); at the second free, fd points to chunk2
2. malloc returns the userdata pointer of chunk1; at this point chunk1 is the same as at the second free
3. Modifying the malloc'ed chunk modifies chunk1's userdata, but at this point it corresponds to modifying fields such as fd of chunk1 in the linked list
4. Find or construct a heap chunk at the position pointed to by the fd field, with the size field set to a suitable size so that the final malloc succeeds. (fd can point to the GOT region, which stores the starting positions of functions)
5. Finally malloc twice so that the list array stores the value of fd
6. Finally malloc (a suitable size) so that the allocation succeeds (_int_malloc in malloc verifies whether the size at the allocation position matches the size corresponding to the current fastbin list array position)
7. Modify the finally allocated chunk (if it is the GOT region, you can modify the function address corresponding to that GOT entry)
8. Make the corresponding function run, achieving the effect of calling function A but actually running function B

##### Arbitrary Alloc
Similar to alloc to stack, but the slight difference is that the corresponding fd value is no longer limited to within the stack; it can be any memory address (such as a function)

Core idea: use the unsorted bin to leak the libc base address and overwrite the _malloc_hook address in the GOT table

5. Because at this point the third chunk pointer is also the address of the fifth chunk, use the print function to print out the unsorted bin address at the fd of the fifth chunk
6. Calculate the libc base address, and at the same time request a suitable chunk of a size that can be recycled into the fastbin. At this point the chunk in the unsorted bin is split: one part becomes usable, and one part remains in the unsorted bin with only its size changed

### smallbin
1. When a malloc request is not satisfied in the fastbin, it goes to the small bin to look
2. Doubly linked list
3. First in, first out
4. When a chunk fitting the small bin is freed, it is preferentially placed into the unsorted bin; only in certain cases is it placed into the small bin
5. When a chunk is freed and a physically adjacent chunk is found to be free, they are merged before being placed into the bin

### unsortbin
1. When a chunk whose size does not belong to the fast bin is freed, and it is not adjacent to the top chunk, it is first placed into the unsorted bin
2. The unsorted bin is a doubly circular linked list with no restriction on chunk size
3. When chunks in the fastbin and smallbin cannot satisfy the user's requested chunk size, the heap manager uses the unsorted bin. It merges the fragments in the heap
4. The traversal order is FLFO (last in, last out); insertion happens at the head of the unsorted bin, removal takes from the tail of the list, and traversal uses the bk pointer
5. Freeing a chunk that does not belong to the fast bin, and where the chunk is not right next to the top chunk, the chunk is first placed into the unsorted bin
#### unsortedbin attack
Control the bk pointer of the chunk at the head of the unsorted bin queue; when malloc happens, the fd field of the fakechunk corresponding to the head's bk is modified to the address of the bin element.

When freeing a chunk, it checks whether the previous chunk of this chunk is in a freed state (physically adjacent at this point, i.e., right next to it).
