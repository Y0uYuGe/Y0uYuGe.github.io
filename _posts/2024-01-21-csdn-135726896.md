# Overview
![Image](/images/csdn/2024/csdn-135726896/image-001-27fc04daca.png)
# Why Layering
There is a lot of preparatory work to do before sending a file
![Image](/images/csdn/2024/csdn-135726896/image-002-0b389b219b.png)
Break this preparatory work down into small problems to be solved layer by layer — that is, solve it in layers
# How to Layer
Each layer is independent of the others, and the work done by each layer is different
The boundaries should be natural and clear; the interfaces between layers should reflect the relationships between layers while being concise and clear — not too many interfaces

The operations performed by the peer entities at the same layer are opposite

![Image](/images/csdn/2024/csdn-135726896/image-003-5b01bfee17.png)


# Formally Understanding Layering
Only lower layers provide services to upper layers
The SDU can be regarded as the data that needs to be transmitted for this layer to complete the function requested by the user
The PDU becomes the SDU of the next layer

# Concepts

Described in terms of functionality, i.e. different functions distinguish different structural layers

Only with interfaces can an upper layer use the services of the layer below

Implementation versus architecture is like the difference between writing code and overall design
![Image](/images/csdn/2024/csdn-135726896/image-004-d33463c9a8.png)
