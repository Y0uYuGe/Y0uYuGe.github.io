# QEMU Memory Management (How QEMU Manages the Memory of a Specific VM)
QEMU: able to perform the gva-gpa-hva-hpa address translation

## MemoryRegion gpa->hpa
QEMU manages virtual machine memory through MemoryRegions; each MemoryRegion corresponds to a portion of the VM's memory, along with information about the corresponding Host virtual memory. Different MemoryRegions are connected in a tree organization under a root MemoryRegion; different MemoryRegion trees represent memory with different roles, such as system memory space (system_memory) or IO memory space (system_io)

MemoryRegion can be divided into the following three types
 - Root-level MemoryRegion: initialized via memory_region_init; it is only for management (e.g., system_memory) and has no corresponding memory of its own
 - Concrete MemoryRegion: initialized via memory_region_init_ram; it has corresponding memory of size size
 - Alias MemoryRegion: initialized via memory_region_init_alias; it has no corresponding memory of its own and exists as an alias of a concrete region, pointing to the corresponding concrete region via the alias member; alias_offset represents the offset of the starting GPA of the memory represented by this alias MemoryRegion relative to the starting GPA of the memory represented by the concrete MemoryRegion

## FlatView: Represents the Address Space Corresponding to the MR Tree
```c
struct FlatView {
    struct rcu_head rcu;
    unsigned ref;
    FlatRange *ranges;
    unsigned nr;
    unsigned nr_allocated;
    struct AddressSpaceDispatch *dispatch;
    MemoryRegion *root;
};
```
##  FlatRange: Stores Address Information Corresponding to Different MRs

```c
struct FlatRange {
    MemoryRegion *mr;
    hwaddr offset_in_region;
    AddrRange addr;
    uint8_t dirty_log_mask;
    bool romd_mode;
    bool readonly;
    bool nonvolatile;
};
```

## AddressSpace: MemoryRegion Trees of Different Types
There are two: address_space_memory and address_space_io
```c
/**
 * struct AddressSpace: describes a mapping of addresses to #MemoryRegion objects
 */
struct AddressSpace {
    /* private: */
    struct rcu_head rcu;
    char *name;
    MemoryRegion *root; //是对应树的根

    /* Accessed via RCU.  */
    struct FlatView *current_map; //对对应树的地址空间表示

    int ioeventfd_nb;
    struct MemoryRegionIoeventfd *ioeventfds;
    QTAILQ_HEAD(, MemoryListener) listeners;
    QTAILQ_ENTRY(AddressSpace) address_spaces_link;
};
```

## RAMBlock
The Host virtual memory corresponding to an MR; each RAMBlock represents the Host virtual memory information occupied by a single concrete MemoryRegion, and multiple RAMBlocks form a RAMList
Each RAMBlock has a unique corresponding MemoryRegion

# QEMU Device Emulation (How QEMU's Emulated IO Devices Interact with the VM)
QEMU performs device emulation independently in user space; virtual devices are invoked by other VMs through interfaces provided by the VMM. And device emulation is independent of the VMM
## QEMU Device IO Handling
When a VM accesses the physical memory/port of a virtual device, control is transferred from the VM to the VMM; at this point QEMU handles it differently according to the type of event that triggered the VM-exit, i.e., MMIO or PMIO.
MMIO: reading/writing the address_space_memory type address space
PMIO: reading/writing the address_space_io type address space
