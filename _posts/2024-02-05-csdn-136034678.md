# What Is Process Synchronization

## Example 1
Asynchrony: for example, with two concurrent processes, one process is almost finished running while the other process has only run to the middle part. The speed is unpredictable, and a process does not care where the other process has run to; it advances and runs independently.

If you want to make a certain instruction of one process execute before a certain instruction of another process, you need to use process synchronization.

# What Is Process Mutual Exclusion
![Image](/images/csdn/2024/csdn-136034678/image-004-8c4a250c62.png)
## The Logic of Mutually Exclusive Access to Critical Resources
- Entry Section: this part of the code is responsible for checking whether the critical section can be entered. If conditions allow — that is, no other process is accessing the critical resource — then a flag is set; this flag indicates that a process is currently accessing the critical resource, thereby preventing other processes from entering at the same time.
- Critical Section: this is the code segment that actually accesses the critical resource. In this region, the process exclusively occupies the critical resource and performs the necessary operations.
- Exit Section: once a process has finished accessing the critical resource, it executes the code of the exit section. The role of this part of the code is to clear the flag set earlier, that is, to "unlock", so that other processes waiting to access the critical resource can enter.
- Remainder Section: this part of the code performs operations on non-critical resources and does not involve access to critical resources.
