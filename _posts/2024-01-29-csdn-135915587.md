# The Scheduler and the Idle Process
## The Scheduler / Scheduling Program
### Process Scheduling
Whether to take the current process off the processor, and which process to put on the processor


After a new process is created, it enters the ready queue; the newly ready program may change the ready queue, so the scheduler may check whether the current process should leave the processor and whether this newly ready process should be put on the processor (process scheduling)

When a process exits, the processor becomes idle, and the scheduler is needed at this point

An I/O interrupt (some process's awaited event has occurred) changes the ready queue, and the scheduler checks whether this newly ready process needs to enter the running state

When the scheduler is triggered, it checks whether there are new entries in the ready queue and whether those newly ready processes need to enter the running state (be put on the processor)

## The Idle Process
When there are no ready processes, the processor runs the idle process

Checking for interrupts: if there is an interrupt, it wakes up the scheduler
The zero-address instruction: no memory access needed, simple to execute, low consumption

## Turnaround Time
With equal turnaround time, a job with a longer running time feels better to the user, because its waiting time is shorter (i.e., less stutter)
![Image](/images/csdn/2024/csdn-135915587/image-007-9acaa16af7.png)
A smaller weighted turnaround time means the running time accounts for a larger proportion and the waiting time is correspondingly smaller. A smaller turnaround time means the job itself completes sooner, which is naturally better

![Image](/images/csdn/2024/csdn-135915587/image-008-d659f2ba60.png)
## Waiting Time
While waiting for I/O to complete, the I/O device is actually also serving the process

Being served = being in use

Note that a job's waiting time and a process's waiting time are not the same

In an operating system, a job's (or process's) CPU service time and I/O service time are usually determined by the job's own characteristics, such as the amount of computation required and the volume of data to be processed. This means that no matter which scheduling algorithm is used, these service times essentially do not change. Specifically:

- CPU service time: the time a job needs to execute instructions on the CPU. It depends on the job's complexity and the amount of computation required. Once the job starts executing, it occupies the CPU until its computation task completes.
- I/O service time: the time a job needs to interact with input/output devices, such as reading and writing files or network communication. During this time the job may not need the CPU and is instead waiting for the I/O operation to complete.
