# Synchronous Timing
## Read Command
A bus transfer is divided into multiple clock cycles
First the CPU sends out the address information during phase T1, at which point the address line signals change
The CPU issues the read command during phase T2, the read command line goes low, and the device at the corresponding address receives the command and gets ready
During phase T3, the CPU receives the data that the slave device has placed on the data lines
In phase T4, the CPU has received the data and deasserts the read command and the address signals
![Image](/images/csdn/2024/csdn-135374293/image-003-0f635d34d6.png)
## Summary
Several intervals make up one bus cycle; the figure below contains an error
Everything works clock cycle by clock cycle, so the control logic is simple to implement — you only need to schedule each clock
But it is rather rigid: when something unexpected happens there is no spare time to do anything else
With a short bus, problems are less likely than with a long line
![Image](/images/csdn/2024/csdn-135374293/image-004-c75a2bfd10.png)
# Asynchronous Timing
The rules are more flexible and varied, and the implementation is not rigid, so it is more complex to implement
![Image](/images/csdn/2024/csdn-135374293/image-005-0373521f8a.png)


After gaining control of the bus, the master sends the address information over the address bus and the read command over the control bus. This is the request information; the reply information is the data the slave device puts onto the data lines to the master

![Image](/images/csdn/2024/csdn-135374293/image-006-921a24c5e4.png)
# Semi-Synchronous Communication
A feedback signal WAT is added
Again taking the read command as an example
At the end of T2, the slave device should have prepared the data to put onto the data lines, but due to differences among devices it may need more time to prepare. In that case it sends a feedback signal WAT to the bus controller, which then stretches a few more clock beats to wait for the slave. Once ready, communication continues according to the previous synchronous scheme

"Synchronous" in the figure below means that within one clock cycle, the master sends on the leading edge of the clock and the slave receives and processes on the trailing edge — that is, the master and slave complete one information transfer per clock cycle
![Image](/images/csdn/2024/csdn-135374293/image-007-9bf0bc38c9.png)
# Split-Transaction Communication
Here the slave module can also request to occupy the bus
The bus transfer cycle is divided into two independent sub-cycles
The master first requests bus ownership and sends the request signal, then releases bus ownership; the slave waits until it is ready, requests bus ownership, and transmits the data onto the bus.
This makes full use of the slave's preparation time, during which the bus is free to do other things

Here synchronous communication means the request is issued within a specified beat and bus ownership is released within a specified beat
