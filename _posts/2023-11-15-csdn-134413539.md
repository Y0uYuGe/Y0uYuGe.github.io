# Memory virtualization

 - Able to provide a contiguous physical address space that the Guest perceives as starting from zero
 - Effectively isolate, schedule, and share memory resources among VMs
# Common abbreviations
HPA: Host Physical Address

HVA: Host Virtual Address

GPA: Guest Physical Address

GVA: Guest Virtual Address

PDBR: the page directory table physical base address register, called CR3 on x86 (Page Directory Base Register)

EPT: Extended Page Table

SPT: shadow page table

ptr: used here to describe a register pointing to some page table

# Principles of memory access in virtual machines
When the Guest accesses its own memory, the steps are as follows:

 **1. Convert the GVA to a GPA through the Guest page table
 2. The GPA corresponds to a large block of mmap'd memory in the Host, so the GPA must be converted to an HVA
 3. Finally, the HVA is converted to an HPA through the Host page table**

Disadvantage: the process is cumbersome, making memory access performance in the virtual machine extremely poor

# Shadow page table
Shadow page table: a page table of GVA→HPA mappings
**Implementation mechanism:
When accessing memory, the instructions that read and write CR3 (the register holding the physical base address of the page directory table) are needed. Since this operation is a sensitive instruction, the VMM intercepts it and replaces the page table with the shadow page table, so the page table becomes one of GVA→HPA mappings.**

Disadvantage: each set of page tables requires an independently maintained shadow page table, and multiple switches between the VMM and the VM are needed — considerable overhead
# Extended page table
EPT: a page table of GPA→HPA mappings
At the hardware level, the EPTP register is introduced to point to the base address of the EPT page table. When the Guest runs, the Guest page table is loaded into the PDBR, while the EPT page table is loaded into the dedicated EPT page table pointer register EPTP.

**Implementation mechanism:
**GVA->GPA translation is still done by looking up the original page table, while GPA->HPA translation is done by looking up the EPT. Each guest VM has an EPT maintained by the VMM. Meanwhile, the hypervisor only needs to intercept EPT Violation exceptions (an EPT entry is empty)****

# VPID (Virtual Processor Identifier): TLB (Translation Lookaside Buffer) resource optimization
The TLB is a cache of page table entries, caching recent virtual address translation records. When performing address translation, the CPU first queries the TLB; the TLB checks whether there is a corresponding cache entry for the virtual address, and the page table is only consulted if the cache misses.

Since the TLB works with the corresponding page table, its original contents become invalid when the page table is switched, so we should use INVLPG to invalidate the TLB. For example, on VM-Entry and VM-Exit the page table is switched, and the CPU forcibly invalidates the TLB — but doing so still incurs some performance loss.

VPID is an optimization of TLB resource management: it tags each TLB entry with a VPID identifier (the VMM assigns a unique VPID to each vCPU, stored in the VMCS; the logical CPU's VPID is 0). When the CPU looks up the TLB cache, it first compares the VPID, so we no longer need to flush all cached entries on every VM entry/exit and can keep reusing the previously retained cache.
