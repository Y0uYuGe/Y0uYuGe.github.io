# TestAndSet Instruction
Test-and-Set is a special hardware instruction used to achieve mutual exclusion between processes. It is usually used to control access to shared resources (critical resources).

Specifically, the Test-and-Set instruction consists of two steps:

Test step: check the current value of the specified memory address (usually a flag bit).
Set step: set that memory address to 1 (or some preset value).
These two steps constitute an atomic operation, that is, it will not be interrupted by other processors during execution, ensuring the synchronization of the operation.

The Test-and-Set instruction is usually applied in the following scenarios:

When a process needs to enter the critical section, it executes the Test-and-Set instruction to check the state of the lock.
If the returned old value is 0 (indicating that the lock is not occupied), the process enters the critical section and sets the lock to 1, preventing other processes from entering.
When the process leaves the critical section, it sets the lock to 0 (unlocks it), allowing other processes to enter.

Yield-while-waiting: it is still in the while loop when it cannot access the critical section, causing it to occupy the CPU.

![Image](/images/csdn/2024/csdn-136045657/image-003-aca234996e.png)
## Why It Is Suitable for Multiprocessors
The TestAndSet instruction is suitable for multiprocessors because it provides a mechanism to ensure mutually exclusive access to shared resources in a multiprocessor environment.

First, the TestAndSet instruction is an atomic operation, which means that when this instruction is executed, it will not be interrupted by other processes or processors. This feature is especially important in multiprocessor systems, because multiple processors may try to access the same shared resource at the same time. By using the TestAndSet instruction, it can be ensured that at any time only one processor can modify the state of the shared resource.

Second, the TestAndSet instruction allows the processor to interact directly with memory without the intervention of the operating system. This makes it very useful in multiprocessor environments, because it can reduce the dependence on the operating system kernel, thereby improving the efficiency and response speed of the system.

Finally, although the TestAndSet instruction may not be suitable for user processes in some cases, it is still a very valuable tool in the kernel processes of multiprocessor systems for achieving mutually exclusive access to critical resources.

# Process Mutual Exclusion: Locks
![Image](/images/csdn/2024/csdn-136045657/image-006-92e2cdda23.png)
If the critical section is unlocked during busy waiting, there is no need to switch the process context. In this way the cost is very low compared to waiting. On the other hand, if during busy waiting the process is taken off the processor and switched to another process, then if the critical section happens to be unlocked at that moment, you have to switch back to the original process that was busy-waiting to access the critical resource before the critical section can be used (of course, the premise of this is that the total time from a process locking and using the critical section to unlocking it is relatively short, so the busy-waiting time of other processes is relatively short).

Not suitable for uniprocessors: because during busy waiting, even if another process wants to unlock, it has to wait until the busy-waiting time ends.
