# Remotely Debugging a Program Running in Docker from the Host
[https://www.roderickchan.cn/zh-cn/2023-02-13-%E4%BD%BF%E7%94%A8docker%E8%B0%83%E8%AF%95pwn%E9%A2%98/#0x3-%E4%BD%BF%E7%94%A8%E6%8A%80%E5%B7%A7](https://www.roderickchan.cn/zh-cn/2023-02-13-%E4%BD%BF%E7%94%A8docker%E8%B0%83%E8%AF%95pwn%E9%A2%98/#0x3-%E4%BD%BF%E7%94%A8%E6%8A%80%E5%B7%A7)
### Environment Preparation

1. **Preparation in the container**:
   - **Install gdbserver**: First, `gdbserver` needs to be installed in the Docker image. This is usually done by adding the corresponding install command to the Dockerfile (e.g., `RUN apt-get update && apt-get install -y gdbserver` for Debian-based images).

2. **Preparation on the host**:
   - **Install GDB**: Make sure GDB is installed on your host; this is the client part of the debugger and will be used to remotely control the program running in the container.
   - **Executable or symbol file**: The host needs the executable file or debug symbol file corresponding to the program to be debugged in the container. This is because GDB runs on the host and needs this information to parse and display debug information.

### Debugging Steps

1. **Start the container and map ports**:   Chose roderick's container for direct debugging
[https://hub.docker.com/r/roderickchan/debug_pwn_env/tags](https://hub.docker.com/r/roderickchan/debug_pwn_env/tags)

```bash
docker run -it --rm -v host_path:container_path -p host_port:container_port --cap-add=SYS_PTRACE IMAGE_ID /bin/bash
```



2. **Start gdbserver in the container**: After entering the container, use `gdbserver` to attach to the program you want to debug and specify the listening port. For example, if your program is named `my_program`, the command is as follows:
   ```bash
   gdbserver localhost:12345 my_program
   ```
   This makes `gdbserver` start your program in the container and listen on port 2345 waiting for a connection from GDB.

3. **Connect with GDB on the host**: Open a terminal on the host and use GDB to connect to the `gdbserver` in the container. You need to specify the executable file path on the host (even though it actually runs in the container) and the target remote address and port:
   ```bash
   gdb -ex 'target remote 127.0.0.1:12345' /path/to/your_program
   ```
   `/path/to/your_program` should be a copy of the same program or the symbol file on the host as in the container, ensuring GDB can recognize and load the correct debug information.

4. **Start debugging**: Once the connection succeeds, you can set breakpoints, single-step, view variables, etc. in the host's GDB, just like debugging a program directly on the local machine.

The volume mount `-v host_path:container_path` makes modifications to files on the host also take effect in docker; then debug and run in docker while modifying this folder or file on the host

# pwngdb+tmux

```python
# 绑定Ctrl+a为新的指令前缀
set -g prefix C-a

# 从tmux v1.6版起，支持设置第二个指令前缀, 设置一个不常用的`键作为指令前缀，按键更快
set-option -g prefix2 `

# 修改分屏快捷键
unbind '"'
bind - splitw -v -c '#{pane_current_path}' # 垂直方向新增面板，默认进入当前目录
unbind %
bind | splitw -h -c '#{pane_current_path}' # 水平方向新增面板，默认进入当前目录

# 设置面板大小调整快捷键
bind j resize-pane -D 5
bind k resize-pane -U 5
bind h resize-pane -L 5
bind l resize-pane -R 5

# 刷新配置文件
bind R run-shell "tmux source-file ~/.tmux.conf"

# 上一个窗口
bind a last-window


```

[https://louiszhai.github.io/2017/09/30/tmux/](https://louiszhai.github.io/2017/09/30/tmux/)

- Ctrl+a <arrow key>: move the cursor to another pane
- Ctrl+a hjkl: adjust the size of the current pane
- Ctrl+a a: switch to the previous window
- Ctrl+a |: add a pane horizontally
- Ctrl+a -: add a pane vertically
