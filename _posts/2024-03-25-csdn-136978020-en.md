# UART
In embedded development terms, qemu simulates that development board (the hardware)
When using qemu on a computer, you can think of qemu as simulating that board, with the board already connected to your computer (the kernel we specified also runs on that board, and the connection and data transfer follow the UART form: the board's UART interface is connected to the computer's UART interface so that data is transferred to the computer and then displayed by the computer)
![在这里插入图片描述](/images/csdn/2024/csdn-136978020/image-001-ec47fc55d4.png)

UART (Universal Asynchronous Receiver/Transmitter) is a widely used hardware communication protocol for serial communication. The UART communication protocol allows devices to communicate with each other through serial ports. This protocol does not require a clock signal to synchronize sending and receiving data, so it is called "asynchronous" communication.
![在这里插入图片描述](/images/csdn/2024/csdn-136978020/image-002-3bbe1b2abb.png)


In UART communication, data is transmitted in serial form, i.e., one bit at a time. Communication between two devices usually involves two wires: one for transmitting data (TX) and the other for receiving data (RX)
![在这里插入图片描述](/images/csdn/2024/csdn-136978020/image-003-5cd6037bed.png)
In practice, the connection is an interface, and data is transmitted in the form specified by the interface
![在这里插入图片描述](/images/csdn/2024/csdn-136978020/image-004-724fc01f7e.png)
#  NS16550A
The programming interface of the NS16550A refers to how software interacts with this UART chip. In layman's terms, we can think of the NS16550A as a mailbox with many small slots (registers), each with a specific function. Programmers control the behavior of the UART, or obtain its status, by writing data to or reading data from these slots.
It is similar to the computer having a memory region used to communicate with the UART device (like a relay, and for configuring the form of the relay)

An interface, as the name suggests, is where two devices connect. This place involves the exchange and transmission of data, so it is natural to specify how the two sides exchange and transmit data, as well as the related buffers for the exchange and transmission

Map the interface's registers to memory addresses, so that we can access the interface's registers by accessing addresses
![在这里插入图片描述](/images/csdn/2024/csdn-136978020/image-005-1ca6a25e7a.png)
# Specification
The NS16550A interface has eight related registers, but there is multiplexing. For example, 000 denotes the zeroth register, which has two modes, and in read mode it has only one purpose (receive holding register), while in write mode it has two functions

Some registers only have a function in the corresponding mode

![在这里插入图片描述](/images/csdn/2024/csdn-136978020/image-006-bd251f58d6.png)
A UART register is eight bits
The names of the relevant registers and the meaning of each bit are as follows
![在这里插入图片描述](/images/csdn/2024/csdn-136978020/image-007-ae019f501b.png)


**Initialization**
The first is disabling interrupts
The second is setting the baud rate
The third is setting the parity bit

The functions of the corresponding registers

DLL: LSB of Divisor Latch (write mode)
DLM: MSB of Divisor Latch (write mode)

When bit 7 of LCR is set to 1, the device considers that baud rate setting has begun. The baud rate is determined by the 16-bit value jointly formed by DLL and DLM and the input frequency, as follows
![在这里插入图片描述](/images/csdn/2024/csdn-136978020/image-011-138fef1eb2.png)
After bit 7 is set to 0, the device knows that the baud rate setting is complete, and the device saves the baud rate via separate registers

> Writing to DLL and DLM writes to memory; the io device should have separate registers for saving the baud rate, and once the baud rate in DLL and DLM is set, the io device automatically saves it (a reply from an expert in the group)

# Goal
	 * - number of the word length: 8 bits
	 * - number of stop bits：1 bit when word length is 8 bits
	 * - no parity
	 * - no break control
	 * - disabled baud latch


# Sending Data
First write the data to THR, then send it out

Polling: continuously check whether the register is free (whether the data has been sent out)
![在这里插入图片描述](/images/csdn/2024/csdn-136978020/image-012-318aa5d393.png)

THR holds the data to be sent, one character; LSR holds the signal of whether the data in THR has been sent out, in bit 5
![在这里插入图片描述](/images/csdn/2024/csdn-136978020/image-013-d54aa19914.png)
Continuously check bit 5 of the LSR register; if it is 1, break out of the loop and transmit the data

## extern
The extern keyword is used to declare a variable or function that is defined elsewhere. This means the declaration tells the compiler that the entity corresponding to the name exists, but its definition may be in another file of the program. Such declarations usually appear in header files (.h files), or in projects that use multiple source files (.c files). 

When compiling and linking, each C file is first compiled into an object file, and then linked. If you want to use functions from other files during compilation, you need to declare them with extern, and they are only specifically resolved at link time
