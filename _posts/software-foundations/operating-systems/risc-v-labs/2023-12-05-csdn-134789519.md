# The GDB Debugger
GDB debugging involves 2 programs: the gdb program and the program being debugged. Depending on whether these 2 programs run on the same computer, GDB's debugging model can be divided into 2 types:
Local debugging: the debugger and the debugged program run on the same computer
After gdb starts, it first forks a child process; the debugged program runs in this separate child process, and the gdb program itself also runs in its own independent process. These two processes then establish a connection through the special ptrace system call.

Remote debugging: the debugger runs on one computer, while the debugged program runs on another computer
There is a gdbserver service on the target machine; gdb interacts with gdbserver, which proxies our debugging process. The debugged program runs on the target machine, while the debugging happens on the local machine. The two machines are connected over the network

The special variable .DEFAULT_GOAL can be used to tell Make which target (or targets) to build if no target is specified on the command line (i.e., when you just run make). Otherwise, Make simply builds the first target it encounters.
.PHONY: phony target. A phony target is one that does not represent a real file name; when running make you can specify this target to execute the commands defined in its rule. A phony target is sometimes also called a label. Phony targets are declared with PHONY. The commands of a target declared in PHONY are always executed

# Exercise 4-1
Get familiar with the concept of cross-compilation. Use riscv gcc to compile code and use binutils tools to analyze the generated object file and executable file (ELF format). The specific requirements are as follows:
- Write a simple program source file that prints "hello world!": hello.c
- Compile the source file to generate the object file hello.o targeting processors that support the rv32ima instruction set architecture
- View the file header information of hello.o.
- View the Section Header Table of hello.o.
- Disassemble hello.o and examine the correspondence between the C source code of hello.c and the machine instructions.

-march=rv32ima: specifies that the generated 32-bit executable can run on processors supporting the i integer instruction set, the m multiply/divide instruction set, and the a atomic operation instruction set

-mabi=ilp32: how many bits a long integer is

```bash
riscv64-unknown-elf-gcc -march=rv32ima -mabi=ilp32 llk.c -o llk
```

- Learn Makefile syntax on your own, and understand what happens when you run make in the root directory of the riscv-operating-system-mooc repository.


```bash
SECTIONS = \
	code/asm \
	code/os \

.DEFAULT_GOAL := all
all :
	@echo "begin compile ALL exercises for assembly samples ......................."
	for dir in $(SECTIONS); do $(MAKE) -C $$dir || exit "$$?"; done
	@echo "compile ALL exercises finished successfully! ......"

.PHONY : clean
clean:
	for dir in $(SECTIONS); do $(MAKE) -C $$dir clean || exit "$$?"; done

.PHONY : slides
slides:
	rm -f ./slides/*.pdf
	soffice --headless --convert-to pdf:writer_pdf_Export --outdir ./slides ./docs/ppts/*.pptx


```
- \ means line continuation. The shell environment is only entered when the shell statements of the corresponding Makefile command are executed; each line of commands is independent and each line runs in a separate shell, so a shell variable defined in the previous line does not apply to the next line. Of course, using \ to join lines removes this limitation, making them a single command executed by one shell. The \ after SECTIONS in the figure can be understood as joining the lines below and above into one line. Otherwise, when make executes, each line runs in a separate shell, and SECTIONS would not be assigned successfully. With it, the shell executes the three lines together, so the assignment succeeds
- The for in ; do ; done loop statement: in a makefile, a shell variable needs two $ signs to represent the variable name, corresponding to dir here
- make -C directory means entering the directory and then running make
- || means executing the following command if the preceding command fails

So roughly, the whole make enters the code/asm and code/os directories and runs make; the corresponding makefile under /code/asm in turn enters each subdirectory and runs make, and /code/os does the same
