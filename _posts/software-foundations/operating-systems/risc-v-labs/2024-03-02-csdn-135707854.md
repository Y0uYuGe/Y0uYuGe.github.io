# Pseudo-instructions and Instructions
Before discussing the difference between pseudo-instructions and instructions in the RISC-V architecture, let's first understand what instructions and pseudo-instructions are.

Instructions:

- Instructions are the most basic commands that a processor can execute directly.
In the RISC-V architecture, instructions follow specific binary formats, and each instruction corresponds to a set of operations executed by hardware.
The instruction set is subdivided into different types according to the RISC-V standard, including integer computation instructions, control transfer instructions, load and store instructions, and so on.
Each instruction is compiled into a fixed-length binary instruction, and these binary codes are executed directly by the RISC-V processor.
Pseudo-instructions:

- Pseudo-instructions are not hardware instructions directly supported by the processor; they are designed for programming convenience and make it easier for programmers to write assembly code.
When a pseudo-instruction is processed by the assembler, it is usually translated or expanded into one or more basic machine instructions.
Pseudo-instructions give assembly language higher-level features, such as more readable data movement operations, operations on constants, and so on.
Examples of pseudo-instructions may include instructions like “li” (load immediate), which is used to load an immediate value into a register; in fact, it may be expanded into a set of “lui” (load upper immediate) and “addi” (add immediate) instructions to load a 32-bit or 64-bit constant into a register.

- Differences: - Direct execution vs. indirect conversion: instructions can be executed directly by hardware, while pseudo-instructions need to be converted by the assembler into one or more hardware instructions. 
- Functional level: instructions are usually low-level, atomic operations, while pseudo-instructions provide a higher level of abstraction that helps simplify complex instruction sequences. 
-  Transparency: when using instructions, programmers need to explicitly know and specify the operation of each instruction; pseudo-instructions allow programmers to write more intuitive code, with the specific instruction details handled by the assembler. - Binary representation: instructions have a definite binary format, while pseudo-instructions have no fixed binary representation, because they are converted into one or more actual instructions.
-   Programming convenience: pseudo-instructions are designed to improve the readability and writing convenience of assembly language, while instructions are the basis of actual execution.

Ultimately, the goal of pseudo-instructions and instructions is the same: to complete the operations the programmer wants to perform. But pseudo-instructions provide a simpler, more abstract way to express these operations.
