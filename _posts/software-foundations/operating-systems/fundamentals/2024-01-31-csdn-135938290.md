# First-Come First-Served Algorithm
It does not cause starvation: as long as the process or job is in the queue, once all those ahead of it have finished (the ones ahead will always finish), it will eventually get its turn to be served.
![Image](/images/csdn/2024/csdn-135938290/image-002-804732cbc9.png)

## Example
Note that the running time is the time spent running on the CPU.
Waiting time = turnaround time - time being served.
Both IO operations and CPU running count as time being served.
![Image](/images/csdn/2024/csdn-135938290/image-003-09b6e285ba.png)
# Shortest Job First
"Shortest": not rigorous; judge whether it is right or wrong depending on the situation.
If short jobs keep arriving in an endless stream, long jobs may suffer from starvation.
![Image](/images/csdn/2024/csdn-135938290/image-004-70d6e2ea43.png)


 
## Example (Non-preemptive Shortest Job First Scheduling Algorithm)
At time zero, only process P1 can be executed. After P1 finishes, it is found that P2, P3, and P4 have all arrived. At this point P3, which has the shortest running time, is executed; then P2 and P4 have the same running time, and since P2 arrived in the ready queue first, P2 is scheduled first.
 
 ![Image](/images/csdn/2024/csdn-135938290/image-005-53a75ee2d8.png)
## Example (Preemptive Shortest Job First Scheduling Algorithm)
The two time points at which the scheduling algorithm runs: one is when the ready queue changes — at this point the remaining time of the newly arrived process is compared with the remaining time of the currently running process. The other is when a process completes — at this point the process with the least remaining time is selected from the ready queue to run on the processor.

# Summary
These scheduling algorithms do not care about response time, nor do they distinguish the urgency of tasks = poor interactivity.
If a system does not care about response time and does not distinguish the urgency of tasks, the reasons for poor user interactivity are as follows:

- Poor user experience: if the system does not consider response time, users may have to wait a long time to get feedback, which makes users feel frustrated and dissatisfied.
- Low efficiency: not distinguishing the urgency of tasks may cause critical tasks to be delayed, affecting overall work efficiency.
Lack of priority management: the system should be able to reasonably sort tasks according to their importance and urgency, otherwise it may lead to wasted resources and misplaced goals.
- There are few opportunities for interaction, which naturally also makes interactivity very poor.

An early batch processing system was a way of automatically processing programs and data: after a user submitted a batch of jobs, there was no further intervention, and the system ran them automatically.
