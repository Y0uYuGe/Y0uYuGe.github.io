# Overview
![Image](/images/csdn/2024/csdn-135775719/image-001-5401dfbda4.png)
## Process States - New, Ready
When a process is being created: the new state
After creation completes: the ready state
![Image](/images/csdn/2024/csdn-135775719/image-002-16271e25bb.png)
## Process States - Running
While running an instruction sequence of a program in memory, execution reaches a system call and finds that the I/O device is busy, so its resource is temporarily unavailable
![Image](/images/csdn/2024/csdn-135775719/image-003-7ab80a11b4.png)
## Process States - Blocked
At this point, because process 2 must wait for the event of the operating system allocating the printer resource to it, the CPU takes process 2 off the CPU and lets process 1 run on the CPU. When the printer finishes its previous job and becomes idle, the operating system allocates the printer resource to process 2; the event process 2 was waiting for has now occurred, and the OS moves process 2 from the blocked state to the ready state.
![Image](/images/csdn/2024/csdn-135775719/image-004-0054326272.png)

![Image](/images/csdn/2024/csdn-135775719/image-005-67d9c070ec.png)
## Process States - Terminated
At this point the running process 1 has finished; on completion it issues the exit system call and enters the terminated state.
![Image](/images/csdn/2024/csdn-135775719/image-006-8b2b559158.png)
## Process State Transitions
The ready state lacks only the processor
Blocked state: "other" means waiting for some event whose occurrence has also not been satisfied
Active behavior: the process actively requests to wait for an event or actively issues a system call; when the condition is not met it actively enters the blocked state
Passive behavior: it can only wait for some event to occur; it is not under the process's control, hence passive

Running can go back to ready: the time slice expires and a process switch occurs (concurrency)
