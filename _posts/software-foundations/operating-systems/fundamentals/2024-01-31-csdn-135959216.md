# Round Robin
A time-sharing operating system is an operating system that allows multiple users to share the resources of one computer; it provides service to each user by means of round-robin time slices.
Note that its scheduling algorithm does not distinguish the urgency of tasks.
![Image](/images/csdn/2024/csdn-135959216/image-002-0ce57c516c.png)

Note that by default, a newly arrived process enters the ready queue first, and the process leaving the processor enters the ready queue afterwards.

## If First-Come First-Served Is Used
![Image](/images/csdn/2024/csdn-135959216/image-014-8c813c7deb.png)
The reason the first-come first-served (FCFS) algorithm may cause process response time to increase is the lack of priority consideration: when the FCFS algorithm selects a process, it is based solely on the order in which processes arrive, without considering the priority of the processes or the service time they require. This means that some short processes that need a quick response may be delayed because they are queued behind long processes.

![Image](/images/csdn/2024/csdn-135959216/image-015-fb16d68438.png)
# Priority Scheduling Algorithm
A real-time operating system (RTOS) is an operating system specially designed to meet real-time requirements; it can quickly accept and process the corresponding data when external events occur, ensuring that tasks are completed and responded to within the specified time.

## Supplement
There is not necessarily only one ready queue; they can be organized according to different priorities: some operating systems can set up multiple ready queues, each corresponding to a different priority.
Arrange processes with higher priority closer to the head of the queue: some operating systems dynamically queue processes in one ready queue according to their priority.

Raising the priority of processes with frequent IO operations can get the IO devices to work as early as possible, thereby improving resource utilization.

# Multilevel Feedback Queue Scheduling Algorithm
In practical applications it may also be non-preemptive.

Fairness: every process has the highest priority when it first arrives (it is processed first).
Timely response: every newly arrived process has the highest priority and will be responded to very quickly.
Short processes take less time: short processes pass through fewer queues, and compared with long processes, the total time they take is also shorter.
No need to estimate the running time of processes in advance: because it does not decide who executes first according to a time defined by the user — everything follows the flow of the queues uniformly and is executed directly, so it is useless for users to falsify it.
Flexible priority adjustment: for example, after an IO-intensive process finishes running for its time at its current level, the process can be put back into its original queue, keeping its priority.

Starvation: an endless stream of arriving short processes can cause long processes to never be served.

![Image](/images/csdn/2024/csdn-135959216/image-020-71f754aa32.png)

## Example
P0 enters the level-1 queue; the time slice size of the first-level queue is only one time slice. After P1 has run for one time slice, it has not finished yet, so it enters the next-level queue.
![Image](/images/csdn/2024/csdn-135959216/image-021-7d70c16db0.png)
At this point P2 arrives at the first-level queue. Since the first-level queue is not empty at this point, the first level is processed; after processing for one time slice, it enters the next-level queue and is placed at the tail of the queue.
![Image](/images/csdn/2024/csdn-135959216/image-022-8e8305ac86.png)
At this point the first-level queue is empty, so a time slice is allocated to the second-level queue; P1, at the head of the second-level queue, is dequeued. The time allocated at this point is two time slices; since P1's running time has not yet fully finished, it will be placed into the third-level queue.

![Image](/images/csdn/2024/csdn-135959216/image-023-e9bc25dacd.png)
At this point the second-level queue is not empty, so P2 is dequeued and P2 runs. After running for one time slice, P3 enters the first-level queue. Since the first-level queue is not empty at this point, the P2 process is preempted by P1, and then P3 runs on the processor.
 ![Image](/images/csdn/2024/csdn-135959216/image-024-af279a4702.png)
After P3 runs for one time slice, it finishes running and is swapped out of memory; then P2, at the head of the second-level queue, continues to run, and after running for two time slices in total, it completes.
![Image](/images/csdn/2024/csdn-135959216/image-025-c7317ea70d.png)
At this point both the first-level and second-level queues are empty, so the processes in the third-level queue run on the processor. The allocation at this point is four time slices; after P1 runs for four time slices, it still needs one more time slice to finish.

![Image](/images/csdn/2024/csdn-135959216/image-026-55b483588c.png)
Since P1 is already at the lowest level at this point, it can no longer move down to a lower-level queue; it can only be put back at the tail of its original queue and scheduled again later.
![Image](/images/csdn/2024/csdn-135959216/image-027-18eb4e80b8.png)
Then P1 only needs to use one of its four time slices to complete.
![Image](/images/csdn/2024/csdn-135959216/image-028-860e96df6b.png)

# Multilevel Queue Scheduling Algorithm
After a process is created, it is inserted into a certain queue according to its classification.

Interactive processes need timely responses, so their priority is higher than that of batch processes.
![Image](/images/csdn/2024/csdn-135959216/image-030-dccbcfaab0.png)
Fixed priority: as long as the high-priority queue is not empty, the high-priority queue runs first; this leads to the problem that if there is content in the system process queue, the interactive processes will never be responded to.
Time-slice division: each time slice is divided into multiple parts, which are then given to a certain process in each queue to execute, so that within one time slice, every type of process is responded to once.

Note that each type of queue here also uses a different scheduling method; the following is an example (each queue can also adopt a different scheduling algorithm).
The system process queue still contains many processes with different priorities; at this point the system process queue adopts priority scheduling, so the process with the higher priority will still be selected to run.
The interactive queue adopts round-robin scheduling to ensure that every process is responded to within a certain time.
The batch queue: first-come first-served, because response time is not a concern.
