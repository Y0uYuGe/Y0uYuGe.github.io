# Contiguous allocation
  The logical block number is similar to an offset
  
  Contiguous allocation is a file storage strategy in which all parts of a file are stored in contiguous blocks on the disk or other storage media. This storage method supports two types of access: sequential access and direct access.

### Sequential access

Contiguous allocation is well suited to sequential access, because in contiguous allocation the file's blocks are adjacent. This means that when reading from the beginning of the file, the disk head can read continuously from the first block all the way to the end of the file without performing additional seek operations on the disk. Since disk seek time is one of the main sources of disk access latency, contiguous access reduces this latency and thereby improves read speed.

### Direct access (random access)

Direct access refers to the ability to immediately access any position in a file. In contiguous allocation, if the address of the file's first block is known, the address of any block in the file can be computed with simple arithmetic. This is because each block has a fixed size, so you only need to know the block number (the offset relative to the file's starting block), multiply it by the block size, and you can calculate the block's absolute position on disk. This makes it possible to quickly locate the correct disk position even when reading data from the middle or end of a file, without having to read sequentially from the beginning.

### Why does contiguous allocation support both access modes?

Contiguous allocation can support both sequential access and direct access because of its data layout characteristics. Storing the file contiguously avoids unnecessary seeks during sequential reads, while the fixed block size and positional relationship allow the physical address to be computed directly from the block number, thereby supporting direct access. This flexibility makes contiguous allocation very effective in many applications, especially scenarios that require both fast sequential reads and random access, such as databases and multimedia files.

# Linked allocation
## Implicit linking
Accessing the n-th logical block means following the n-th pointer; logical block zero is the starting block
![Image](/images/csdn/2024/csdn-140068113/image-010-df629e3400.png)
Just add a linked-list node at the tail, then update the FCB
![Image](/images/csdn/2024/csdn-140068113/image-011-1b344d76f0.png)
## Explicit linking
The pointers linking the blocks of each file are not stored inside the blocks, but in a table
The implicit reason is that the next block corresponding to each physical block is stored in order, so the physical block number does not need to be recorded again
![Image](/images/csdn/2024/csdn-140068113/image-012-1fb42bf617.png)

Zero represents the physical block corresponding to the starting block number; a value greater than zero means you need to look for the next block

![Image](/images/csdn/2024/csdn-140068113/image-013-9335d94b3b.png)
