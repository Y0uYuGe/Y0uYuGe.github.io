# PID namespace
Each namespace has its own independent PID space; that is, the process IDs in each namespace are allocated starting from 1.

# Code

```python
package main
import (
	"log"
	"os/exec"
	"os"
	"syscall"
)
func main(){
	cmd:=exec.Command("sh")
	cmd.SysProcAttr=&syscall.SysProcAttr{
		Cloneflags: syscall.CLONE_NEWUTS|syscall.CLONE_NEWIPC|syscall.CLONE_NEWPID,}
	cmd.Stdin=os.Stdin
	cmd.Stdout=os.Stdout
	cmd.Stderr=os.Stderr
	if err:=cmd.Run();err!=nil{
		log.Fatal(err)
	}
}
```
# mountnamespace
NEWNS (short for New Namespace)
mount namespace is a concept in Linux systems; it is a type of Linux namespace. Namespaces are a feature of the Linux kernel that can isolate certain parts of the system (such as processes, network, user IDs, file systems, etc.), making the processes inside a namespace look as if they were in an independent system.

mount namespace is used to isolate file system mount points. Each mount namespace has its own set of mount points, and these mount points are invisible to other mount namespaces. This means that mounting or unmounting file systems in one mount namespace does not affect other mount namespaces.

For example, imagine you are in a large building (the building is like a Linux system), and everyone has their own room (each room is like a mount namespace). In your room, you can hang the paintings you like (just like mounting file systems in your mount namespace), and you can replace or take down these paintings at any time (just like unmounting file systems in your mount namespace). However, the paintings you hang in your own room cannot be seen by other people in their rooms (this is the isolation feature of mount namespaces). Likewise, you cannot see the paintings that others hang in their rooms either.

This feature is very useful in many scenarios, such as when creating containers (like Docker). Each container has its own mount namespace, so it can have its own file system without affecting the host machine or other containers.
![Image](/images/csdn/2024/csdn-136787094/image-003-74da351aa3.png)
proc is a special file system in Linux, also known as procfs or the proc file system. It is not stored on a hard disk like traditional file systems, but exists in memory. The proc file system is part of the Linux kernel, and it provides an interface for user-space programs to access kernel-space data.

The proc file system is usually mounted at the /proc directory. Under this directory, you can see many files and directories, all of which are generated by the kernel in real time and reflect the current state of the system. For example:

/proc/[pid]: Every running process has a corresponding directory, where pid is the process ID. In this directory, you can find a lot of information about the process, such as its memory usage, open files, running state, etc.
/proc/meminfo: This file contains information about the system's memory usage.
/proc/cpuinfo: This file contains information about the CPU.

```bash
mount -t proc proc /proc
```

This command is used to mount the proc file system in a Linux system. Let's break down this command step by step:

- mount: This is the command used to mount file systems.
- -t proc: This specifies the type of the file system to be mounted, here proc.
- proc: This is the device or file of the file system to be mounted; for the proc file system, this parameter is usually also proc.
- /proc: This is the mount point, i.e., the path through which the file system is accessed after mounting.
- The proc file system is a pseudo file system; it is a way for the kernel to provide system information to user-space programs. It contains a large amount of information, such as process information (each process has a directory named after its PID under /proc), memory information, hardware configuration, and so on.

After you execute the mount -t proc proc /proc command, you can obtain this information by accessing the /proc directory. For example, you can read the /proc/cpuinfo file to get CPU information, or read the /proc/meminfo file to get memory information.

# A Layman's Understanding
First, you can think of the mount command as a kind of "connecting" or "plugging in" operation. Just like you have a TV and a game console, and you want to play games, you need to plug the game console into the TV so that you can play games on the TV. In this example, the mount command is like the operation of plugging the game console into the TV.

Then, -t proc tells the mount command what type of "game console" we are plugging in; in this example, it is a file system of type proc.

Next, proc is the "game console" we want to plug in; in this example, it is the proc file system.

Finally, /proc is the TV port into which we plug the "game console", i.e., the mount point.

So the command mount -t proc proc /proc means plugging the proc file system (the game console) into the /proc directory (the TV port).

So what is the proc file system? It is actually a special file system that does not store real files like a hard disk or a CD, but provides a way to access system information. You can imagine it as a "magic game console": once you plug it into the TV, you can see all kinds of system information on the TV, such as the CPU status, memory usage, and so on.

For example, you can read /proc/cpuinfo (selecting the "CPU Info" menu on the TV) to view CPU information, or read /proc/meminfo (selecting the "Memory Info" menu on the TV) to view memory information.



>In the command mount -t proc proc /proc, -t proc specifies the type of file system we want to mount, here proc. You can think of -t proc as us telling the mount command: "The file system we want to mount is of type proc."
The next proc is a special device name that represents the proc file system itself. Because the proc file system is a virtual file system, it does not have a physical device like a hard disk or a CD, so the device name here is also proc.
So the command mount -t proc proc /proc means: "Mount a file system of type proc, whose device name is proc, and mount it onto the /proc directory."




> proc is a special file system that is part of the Linux kernel and exists in memory, unlike traditional file systems such as ext4 or xfs that are stored on hard disks. It does not have a specific physical location.
The proc file system provides an interface that allows user-space programs to access kernel-space data. When you look at the /proc directory, all the files and information you see are generated by the kernel in real time. For example, the /proc/[pid] directory contains information about the process corresponding to pid, the /proc/meminfo file contains information about memory usage, and so on.
Therefore, when we say "mount the proc file system to the /proc directory", we are actually creating an interface that allows us to obtain kernel information by accessing the /proc directory.
