# Introduction to Docker
Docker can be seen as an extremely lightweight “virtual machine” that allows you to package one or more programs together with their runtime environment into a standardized unit, and this unit can run on any system that supports Docker, regardless of the underlying operating system.

To explain it with an example closer to daily life, Docker is like a “shipping container” in the software world. Containers are used in the logistics industry for standardized transport: they can hold goods, protect the contents inside from the outside environment, and can be quickly loaded, unloaded, and transported worldwide in the same way. Similarly, Docker containers package software together with its runtime environment, ensuring that the software runs in the same way in any environment, simplifying the process of deploying and distributing software.
# An Example

Of course, let's understand Docker through a simple everyday example.

Imagine you want to cook a complex dish, say, French pan-seared duck breast. First, you need a detailed recipe telling you the cooking steps and all the ingredients needed (this is like creating a Dockerfile). Then, you need to prepare all the ingredients in your own kitchen and start cooking according to the recipe (this is like building a Docker container).

But there is a problem. This dish is very complex, and you can't go to everyone's home to cook it in person. Now, suppose you have a magical device that can faithfully replicate your entire kitchen and the pan-seared duck breast, including every grain of sea salt sprinkled on the duck breast, and that also keeps the state it was in when you finished cooking. Then you can ship this replicated “kitchen” anywhere, and people only need to warm it up slightly to enjoy the dish (this is like running a Docker container).

In this example, your kitchen is like a Docker container, your recipe is like a Dockerfile, the ingredients you prepared are the application and its dependency environment, and the “kitchen” you replicated and sent elsewhere is like a Docker container running on another machine.

So the way Docker works is a bit like “cooking” your application together with its environment, then “shipping” the “cooked” container anywhere you want, and after a slight warm-up (running), it is ready to enjoy.

# Installing Docker

```bash
curl -sSL https://get .docker.com | sh
```
1. curl: this is a command-line tool used to get or send data; here it is used to download data from the specified URL.

2. -sSL: these are all options of the curl command. Among them, -s or --silent means silent mode. In silent mode, all regular progress displays and error messages are suppressed. -S or --show-error means show errors. When the -s option is used, this -S option is very useful, because it can display error messages when problems occur. -L or --location means that if the server reports that the page has moved elsewhere (that is, a location header is sent), it follows to the new location.

https://get.docker.com: this is the URL used to download the Docker installation script.

3. |: this is a pipe symbol, whose role is to pass the output of the previous command as the input of the next command.

4. sh: this is the Shell interpreter; here it is used to execute the script downloaded from https://get.docker.com.
Then you can use docker directly.
# The Go Language



Go, also known as Golang, is a statically strongly typed, compiled programming language developed by Google. Go has the efficiency of C, the readability of Python, and strong concurrency processing capabilities.

Go's syntax is very clear and simple, making it easy for beginners to learn. At the same time, Go provides a rich standard library covering network programming, graphics processing, text processing, database operations, and more, allowing developers to complete many feature developments directly with the standard library without using third-party libraries.

C/C++ are traditional programming languages; they are procedural and object-oriented languages with full pointer manipulation and memory management capabilities. Go is a modern programming language with a garbage collection mechanism, so developers don't need to pay too much attention to memory management, and it also supports concurrent programming.

In addition, Go is a compiled language that needs to be compiled before running, and the compiled execution efficiency is relatively high. During the compilation process, Go also detects many errors and problems, ensuring the quality of the program.

Finally, Go also does an excellent job in concurrency processing. It supports Goroutines, which are similar to lightweight threads and can perform large-scale parallel computations, making it very suitable for network programming and cloud programming that need to handle high concurrency.
# Installing Go
- Go to the [official website](https://go.dev/dl/) to find a suitable version to download.
- After downloading, extract it.

```bash
tar -C /usr/local -xzf  go1.22.0.linux-amd64.tar.gz
```

- Edit $HOME/.bashrc and make it take effect immediately.

```bash
code  $HOME/.bashrc
```
- tar: this is a commonly used Unix/Linux command for handling archive/compressed files.

- -C /usr/local: the '-C' parameter is used to change the working directory of the tar command. Here, tar will operate in the '/usr/local' directory.

- -xzf: these three options tell the tar command what operation to perform.

- - x: means 'extract'.
- - z: means the tar command should use gzip to decompress or compress the file.
- - f: means 'file', that is, what follows will be a file name.

- go1.22.0.linux-amd64.tar.gz: this is the name of the file you want to extract. The file name indicates that this is the 64-bit installation package of Go version 1.22.0 for the Linux platform.

```bash
添加 export PATH=$PATH:/usr/local/go/bin
```
- export: this is a shell command used to set environment variables. This tells the shell that we want to modify the value of the PATH environment variable.

- PATH: this is a special environment variable that the operating system uses to look up commands entered on the command line. When you enter a command on the command line (such as go), the shell searches for this command in all the directories listed in the PATH variable.

- $PATH: this is how you get the current value of the PATH environment variable. Here, we concatenate it with the new path using a colon (:) to add the new path.

- :/usr/local/go/bin: this is the new path you want to add to PATH. This is the location of the Go language binaries installed on your system.

- =: this is the assignment operator. Here, it is used to assign the new PATH value (that is, the original PATH value with the new path appended) to the PATH environment variable.
```bash
source $HOME/.bashrc
```
- source: this is a Bash command that reads and executes the commands in the specified file in the current shell session.

- $HOME: this is an environment variable representing the user's home directory. On most systems, this is equivalent to /home/your-username.

- /.bashrc: .bashrc is a file in the user's home directory that contains scripts defining the behavior of the Bash shell. Every time a new Bash shell session is started (for example, when opening a new terminal window), the scripts in the .bashrc file are automatically executed.
Installation successful.
# Go Configuration
GOPATH is the path where code is actually stored. Go looks for dependency packages based on GOPATH. The GOPATH directory convention has the following subdirectories.
src: your Go source files are stored here. Each package has its own directory under src.
pkg: this directory contains package objects. These are compiled Go source code files used to generate executables.
bin: this directory contains executable commands. When you run go install package and go install locates the package through the workspace under the src directory, Go installs the files here.
Here we use /go as the GOPATH path. Edit the $HOME/.bashrc file and add the command export GOPATH=/go to the file,
then run source $HOME/.bashrc, and then run go env to see the effect. The result is as follows.
