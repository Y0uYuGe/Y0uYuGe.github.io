# Programmed Polling
![Image](/images/csdn/2024/csdn-135411880/image-002-bc6aa5ff97.png)

Here we simulate printing three characters

Suppose the three characters are in main memory. The CPU first reads one character from main memory into a CPU register — this is a main memory read operation.

The CPU issues a print command word to the printer. First, the printer driver processes it and places the print command word into a CPU register; then an OUT instruction sends the command word to the IO port control register (the OUT instruction first sends the IO port to write over the address lines, then sends the write operation over the control lines, and finally the command word is transferred to the control register over the data lines)

The IO control logic unit then passes the command signal from the control register to the peripheral interface control logic, which issues the corresponding control signal to the printer over the control lines

The printer receives the command and starts up. When its work is done, it reports completion to the IO interface over the status line. The IO control logic unit places this status signal into status register Rn+1. (This register previously held the command word, but since the command word has already been sent to the IO control logic and processed, it is no longer needed, so holding the status signal now is fine.)

After the OUT instruction sends the print word to the control register, the CPU keeps checking whether the status register has turned into the completion signal (that is, it repeatedly uses IN to input the status register's contents into a CPU register over the data lines, and the CPU checks whether that register's value is the completion signal)

When the check finds the completion signal, the CPU uses the address lines to indicate that this operation targets the data buffer register and the control lines to indicate that this is a write operation, while the character to be printed, stored in a register, is transferred onto the data lines. The character to be printed is then successfully written into the data buffer register

The data in the data buffer register is then passed to the IO control logic, then to the peripheral interface control logic, and then over the data lines to the printer, while the corresponding control signal is also issued over the control lines.

After printing completes, the printer reports the completion signal to the IO interface over the status line, and the interface passes the completion signal to the status register

Once the CPU detects that the printer has finished its work, it writes the second character to be printed into the data buffer register; the flow is the same as printing a

After the last character is printed, the printer sends the completion signal to the interface, which passes it to the status register. Meanwhile, inside the CPU, a counter tracks whether the number of printed characters has been reached. When it finds that all printing is done and the last print signal has completed, the CPU issues a stop command word to the printer (which of course must first go through the driver) into the control register

The IO control logic (IO interface) then sends this stop control signal to the peripheral interface control logic, which sends it to the printer over the control bus, and the printer stops

# Programmed Polling - Example Problem
Slow IO devices have little impact on the CPU under programmed polling
Fast IO devices have a large impact on the CPU under programmed polling
The CPU can actually use timed polling (polling does not take up all the time; polling and program execution are interleaved) or exclusive polling
