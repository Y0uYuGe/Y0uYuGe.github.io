# Basic concepts of interrupts
The interrupt implicit instruction modifies the PC value to point to the interrupt service routine
After each instruction finishes executing, at the end of the instruction cycle, it checks whether there is an interrupt signal to handle. If so, the interrupt service routine is executed (i.e. interrupt response)

JMP and Call instructions executed while the CPU runs a program still belong to that program's process, whereas an interrupt and the original program do not belong to the same process.
![Image](/images/csdn/2024/csdn-135435746/image-002-cd7317d552.png)
# Classification of interrupt requests
An atomic operation can execute certain consecutive instructions in one go; disabling interrupts means that even if an external interrupt arrives, the current instructions continue executing, so it can assist the CPU in executing certain instructions that need to run consecutively

Note the non-maskable interrupt

# Interrupt arbitration - priority setting
Power failure belongs to hardware faults
System calls belong to software interrupts
High-speed devices taking priority over low-speed devices can be understood as: respond to their interrupt requests quickly because, being high-speed, they get more done (similar to a boss handling the efficient employee's matters first, so that employee can do more things)
Input taking priority over output is because an input device updates the contents of the interface's data buffer register; if its interrupt is not responded to quickly (the data cannot be taken away in time, so when the input device inputs again, the data buffer register gets updated again), input information is lost. An output device's response can be slower because it waits for the CPU to put data into the data buffer before working — so if the data is placed later, it simply works later, causing no data loss or other faults
Real-time devices: responses must be timely and rapid
![Image](/images/csdn/2024/csdn-135435746/image-006-bc8455f120.png)
# Interrupt handling process - interrupt implicit instruction

Saving the breakpoint at this point generally goes to the stack, usually the kernel stack
The output of the queuing circuit is a single signal selected from the various interrupt signals; it corresponds to one interrupt source signal. The interrupt vector address generation component then generates the interrupt vector address, and the instruction stored at the interrupt vector address can jump to the entry address of the interrupt handler (the interrupt vector is the address of the interrupt handler)


Why use the interrupt vector address form? If the interrupt vector address generation component directly generated the address of the interrupt handler, then when the interrupt handler's address changes, the circuit structure of the interrupt generation component would need to be modified to generate the corresponding modified interrupt handler address, which is troublesome.
With the interrupt vector address form, if the interrupt handler's address changes, you only need to change the operand of the JMP instruction at the interrupt vector address

# Summary
Either disabling interrupts or pushing the program breakpoint onto the stack can come first

Disabling interrupts lets the interrupt service routine run in one go without being interrupted by other interrupts, until interrupts are re-enabled when the interrupt service routine ends
