# Supporting vs. Not Supporting Hardware Multithreading

In a processor that does not support hardware multithreading, the processor can only handle one instruction pipeline (one program or thread). To switch to another instruction pipeline (one program or thread), the environment of the current instruction pipeline (register information) must be saved to main memory, and when switching back, the previously saved register information is fetched from main memory to restore the register values
Supporting hardware multithreading is equivalent to having multiple CPUs, where different CPUs can handle different instruction sequences (programs or threads)
![Image](/images/csdn/2023/csdn-135210401/image-002-fb3fc2c166.png)
# The Three Kinds of Hardware Multithreading
![Image](/images/csdn/2023/csdn-135210401/image-003-37547b7c25.png)

Fine-grained multithreading fetches two instructions from one thread each clock cycle; the two fetched instructions have no dependencies, so they can be issued to two CPUs to run simultaneously, but the thread is switched every clock cycle

Coarse-grained multithreading runs the instruction sequence of the same thread for multiple consecutive clock cycles. Instructions can still run in parallel each time; the thread switch only happens when the pipeline stalls
Pipeline stall: a Cache miss, meaning the next instruction is not available and must be fetched from main memory. Then the pipeline environment (registers and so on) for the fetched instruction must be set up again

Simultaneous multithreading
Two threads run every clock cycle, with one CPU handling one thread.
Here instructions run in parallel — multiple instructions run simultaneously — and threads also run in parallel — multiple threads run simultaneously
