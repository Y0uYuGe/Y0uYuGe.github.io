Everything below is background related to RISC
# The Five-Stage Instruction Pipeline 
![Image](/images/csdn/2023/csdn-135207817/image-001-2124fbbac9.png)

# Setting the Machine Cycle
All stages are set to the length of the longest machine cycle
![Image](/images/csdn/2023/csdn-135207817/image-002-f70ccee568.png)
# Execution Process of Arithmetic Instructions
In RISC, the result of an operation is not written back to main memory; it is written back to a register. The memory access stage does nothing at this point, but it still takes that amount of time
Different instructions have different operands, so the registers involved also differ
![Image](/images/csdn/2023/csdn-135207817/image-003-0bba5be33a.png)
# Execution Process of the LOAD Instruction
In the figure below, 996 is the offset and Rs is the base address register. The memory access uses base addressing
First compute the address, then access memory, and finally write back to the register
![Image](/images/csdn/2023/csdn-135207817/image-004-7f65267061.png)
# Execution Process of the STORE Instruction
store is the data to be stored into memory
What the ALU computes is the address to store to
![Image](/images/csdn/2023/csdn-135207817/image-005-20140b66fc.png)
# Conditional Branch Instructions
(PC) + instruction word length is the address of the next instruction
Writing back to the PC does not happen in the WB stage; the write-back stage writes to general-purpose registers, and the PC is not general-purpose. After the ALU computes the comparison result, the M stage decides whether to write back the PC or not based on the comparison result
The stage that computes the new PC value is probably not done by the ALU
![Image](/images/csdn/2023/csdn-135207817/image-006-5117214752.png)
# Unconditional Branch Instructions
Same as above. It can be seen that the new PC does not go through the ALU: after the offset is fetched into IMM in the second stage, entering the third stage writes it directly back to the PC
The earlier the PC is changed, the sooner we avoid subsequent instructions continuing to run
![Image](/images/csdn/2023/csdn-135207817/image-007-8fcb472db5.png)
# Example Problem
Only after an instruction enters the ID stage is the result stored in the latch from its IF stage no longer needed. Otherwise, if another instruction is performing the IF stage at this time, the latch holding the fetched instruction would be changed, and when the previous instruction then executes its ID stage, it would decode the next instruction instead
![Image](/images/csdn/2023/csdn-135207817/image-008-82de6eb8d3.png)
