# Basic Concepts of Bus Arbitration
The system bus includes the data bus, the address bus, and the control bus
A device first obtains the right to use the bus through the control bus, and can then use the data bus and address bus for transmission. As for which device the data is transferred with, that is decided by the device currently holding the bus usage rights
Centralized arbitration: one entity decides who goes first
Distributed arbitration: a group decides who goes first
![Image](/images/csdn/2024/csdn-135350655/image-002-c14944dfad.png)
# Centralized Arbitration Methods
The bus controller may be integrated into the CPU or the bridge
The bus controller issues the bus clock signal
BG, BR, and BS are all control bus lines
## Daisy-Chain Query
After device 1 and device n simultaneously send signals to the bus control unit via BR, the bus control unit sends a signal to the devices via BG. The signal first passes through device 0; since device 0 has no request, it lets the signal pass. Then it reaches device 1; device 1 needs to use the bus, so it intercepts the signal and obtains the right to use the bus, and BS is now in use. When the bus controller detects the BS signal, it will not grant the bus to device n, even though device n is still requesting the bus via BR — device 1 has priority over device n
![Image](/images/csdn/2024/csdn-135350655/image-003-328f2e7871.png)
Then, when device 1 finishes using the bus, it withdraws the BS signal. Since device n is still sending a signal via BR and the bus controller no longer detects the BS signal, it sends BG, which reaches device n, and device n starts using the bus
![Image](/images/csdn/2024/csdn-135350655/image-004-d563f2226a.png)
Among the disadvantages, "sensitive to faults" means that if the device with higher priority has a fault receiving the BG signal, so that all devices behind it cannot receive the BG signal, then those devices behind can never obtain control of the bus
## Counter Query
The device address lines are a group of lines used to represent the device address, i.e., which device it is
When device 1 and device n send signals to the bus control unit via BR, the bus control unit's counter starts incrementing from 0. Each increment queries, via the device address lines, whether the device corresponding to the counter value needs the bus. At 0, the address bus reaches device 0, which turns out not to need the bus. Then the counter increments by 1, and the address bus reaches device 1, which does need the bus
(Querying a device actually means sending the counter value signal onto the device address lines, which deliver it to all devices; each device checks whether the signal matches its own device number, and if so, it responds)
![Image](/images/csdn/2024/csdn-135350655/image-005-7d467ef9e9.png)


When device 1 finishes using the bus, it withdraws BS. Since the bus controller still detects a BR signal, it keeps changing the counter value to find the next device that wants to use the bus

"Insensitive to chain faults" means that a broken line on a high-priority device does not affect the devices behind it
The increased number of control lines is because there are many device address lines
Also, since each device needs to recognize the signal from the device address lines and the counter value must be converted into signals for the device address lines, it is relatively complex
## Independent Request Method
Each device has its own BR and BG lines to the bus controller, and all are connected to a single BS. When device 1 and device n send BR signals to the device at the same time, the arbiter inside the bus controller processes the BR signals and finally sends a bus grant signal to one of the devices via BG. After the corresponding device receives the bus grant signal, it sends a signal on BS. When the bus controller receives BS, the device has obtained the right to use the bus, and the bus grant signal is withdrawn. When the device finishes using the bus, the arbiter decides which next device to send the bus grant signal to
![Image](/images/csdn/2024/csdn-135350655/image-006-6c23d806af.png)

The implementation of the arbiter is quite flexible, so controlling the priority order is also quite flexible
