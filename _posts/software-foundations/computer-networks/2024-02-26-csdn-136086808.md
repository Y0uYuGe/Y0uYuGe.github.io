# Drawbacks of the Stop-and-Wait Protocol
Low channel utilization: In the stop-and-wait protocol, after sending a frame, the sender must wait for the receiver's acknowledgment (ACK) before it can send the next frame. If the acknowledgment is lost or delayed, the sender retransmits the data frame due to a timeout, which leaves the channel idle while waiting for the acknowledgment and wastes channel resources. (This can be seen by comparing the time required to complete sending two frames.)

Pipelining: each data frame is sent right after the previous data frame.

At this point, the sequence number range needs to be increased (pipelining sends many frames), and multiple data frames may also need to be buffered (pipelining sends continuously).

# The Sliding Window in the Go-Back-N Protocol
The send window is a set of consecutive frame sequence numbers to be sent (i.e., sent out one by one).

After a frame is sent, a copy is kept at the sender.
After the receiver receives frame 0, it shifts right by one position.
After the sender receives the acknowledgment frame ACK 0 for frame 0, it shifts right by one position.

The receiver can receive multiple frames before sending the acknowledgment frame for the last frame. This still guarantees that all previous frames have been received, because the receiver's receive window only moves when a frame is received; so if the acknowledgment for the last frame can be sent, all the previous frames have already been received.

# Three Things the GBN Sender Must Respond To
Cumulative acknowledgment: The cumulative acknowledgment in the GBN (Go-Back-N) protocol is a mechanism used to inform the sender which data has been successfully received by the receiver.

In the GBN protocol, the receiver uses cumulative acknowledgment to inform the sender of the data reception status. This means the receiver does not send an acknowledgment message for every successfully received packet; instead, it sends an acknowledgment number (ACK) that represents the sequence number of the next packet the receiver expects to receive. In this way, the sender learns that the receiver has successfully received all packets with sequence numbers before the acknowledgment number.

> For example, if the receiver has received packets with sequence numbers 1, 2, and 3, but the packet with sequence number 4 has an error or is lost, the receiver sends an ACK with acknowledgment number 4, indicating that it has successfully received packets with sequence numbers 1, 2, and 3 and is waiting for the packet with sequence number 4.

GBN's handling of timeout events differs from that of the stop-and-wait protocol

# What the GBN Receiver Has to Do
And resend the ACK for the most recently received in-order frame: send the acknowledgment frame for the sequence number just before the one not received; after the sender receives it, it knows the sequence numbers of the frames the receiver has received, so it can send the frames the receiver has not received.

# GBN in Operation
After frame 1 is sent and the receiver has received frame 1, if the sent frame 2 is lost, then even if frame 3 is sent and received by the receiver, it will be discarded and acknowledgment frame 1 will be sent.

When the sender receives an acknowledgment frame, it shifts the window right by the corresponding number of positions.

When the sender times out waiting for acknowledgment frame 2, it retransmits frame 2 and all frames after it.

You can think of the receiver as eating a hamburger: it must eat it layer by layer as prescribed.

# Sliding Window Size
The upper bound on the sliding window size in the Go-Back-N protocol (Go-Back-N ARQ) is to ensure that the receiver can correctly distinguish new frames from old frames.

In the Go-Back-N protocol, the sender and the receiver maintain a send window and a receive window respectively. These windows are essentially sets of sequence numbers that indicate which frames can be sent or received. Specifically:

- Send window: allows the sender to send a group of consecutively numbered frames.
- Receive window: the receiver only accepts a frame with one specified sequence number, i.e., the receive window size is usually 1.

When n bits are used for frame numbering, 2^n different sequence numbers can be produced. To ensure the receiver does not confuse new and old data frames, the send window size should satisfy the condition 1 ≤ W_T ≤ 2^n - 1. If the send window size exceeds (2^n - 1), a situation may occur where the sequence number of a data frame that has been sent but not yet acknowledged appears again in the window, making the receiver unable to distinguish whether it is a new transmission or a retransmission of a previously sent old frame.

For example, if 3 bits are used for numbering, although there can theoretically be 8 different sequence numbers, if the send window size is set to 8, then after frames 0 through 7 have been sent, if all these frames have arrived correctly but have not yet been acknowledged, the send window will be full and sending pauses. At this point, if an error occurs and retransmission is needed, because sequence numbers repeat, the receiver will be unable to distinguish whether it is a new transmission or a retransmission of an old frame, which may cause confusion.

# Summary of Key Points of the GBN Protocol
Occasional piggybacked acknowledgment: the receiver occasionally sends data to the sender and piggybacks the acknowledgment frame on it.

Acknowledge the in-order frame with the largest sequence number: that is, when acknowledgment frames 1, 2, and 4 are received, 2 is sent back as the acknowledgment frame.

Once the send window is determined, it cannot be easily changed during operation.
