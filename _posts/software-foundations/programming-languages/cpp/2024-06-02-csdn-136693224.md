# Virtual Functions
In C++, a virtual function is a special member function that allows a derived class to rewrite or override a function defined in the base class, thereby achieving polymorphism. The key features and uses of virtual functions can be summarized as follows:

1. **Declaration and definition**:
   To declare a virtual function, you need to add the `virtual` keyword before the member function declaration in the base class. For example:
   ```cpp
   class Base {
   public:
       virtual void someFunction() {
           // 基类的实现
       }
   };
   ```
   The derived class can override the function or not; if it overrides it, it provides a new implementation in the derived class:
   ```cpp
   class Derived : public Base {
   public:
       void someFunction() override {
           // 派生类的实现
       }
   };
   ```

2. **Virtual function table (VTable)**:
   The mechanism for implementing virtual functions usually involves the virtual function table (vtable). Every class that contains virtual functions has a vtable, which stores the addresses of all the virtual functions of that class. Each object has a pointer to the vtable of the corresponding class (called the vptr). When a virtual function is called through a base-class pointer or reference, the program looks up the correct vtable based on the object's vptr and calls the function implementation of the actual object type.

3. **Pure virtual functions and abstract classes**:
   If a virtual function in the base class has no implementation and is initialized with `= 0` in its declaration, the function is called a pure virtual function. A class containing pure virtual functions cannot be instantiated and can only be inherited as a base class; such a class is called an abstract class.

# Subclass Vtable and Base Class Vtable
![Image](/images/csdn/2024/csdn-136693224/image-007-80ecca9bdd.png)
The vtable of an abstract class with pure virtual functions is filled with `__cxa_pure_virtual` — there are as many `__cxa_pure_virtual` entries as there are pure virtual functions. The vtable of the Student class contains the virtual functions it implements respectively, and above the vtable is the address of the class's typeinfo
![Image](/images/csdn/2024/csdn-136693224/image-008-f4bf481c32.png)

- RTTI (Run-Time Type Information) is a C++ feature that allows a program to identify the type of an object at runtime.
- The `typeid` operator and `dynamic_cast` are both implemented based on RTTI.
- Every instance of a class containing virtual functions has a hidden pointer in memory (called the vptr, virtual function pointer) pointing to the class's virtual function table (vtable). This vptr is automatically initialized by the compiler when the object is created.
- RTTI information is usually managed together with the vtable, which may include type description information and inheritance chain information.

1. `Aclass* ptra = new Bclass;`: this line creates a pointer to a `Bclass` instance, but the pointer is declared as type `Aclass*`. Because `Bclass` is a subclass of `Aclass` (assumed here), this is an upcast, which is the foundation of polymorphism.

2. `int ** ptrvf = (int**)(ptra);`: this performs an unsafe type conversion, casting the `Aclass` pointer to `int**`. This conversion is usually done to directly access the virtual function pointer (vptr), because on many systems the vptr is the first element of the object's memory layout and can be treated as a pointer to a pointer. However, note that this practice is very dangerous and non-standard, violating type-safety principles.

3. `*((int*)ptrvf[0]-1)`: this part is intended to find the location of the RTTI information. `ptrvf[0]` accesses the first virtual function (counting by pointers), and subtracting 1 attempts to access the position before the vptr, where a pointer to RTTI-related data is expected to be stored. This step is also very dangerous and depends on the implementation details of a specific compiler and platform.

4. `*((RTTICompleteObjectLocator*)(...))`: this further casts the found address to an `RTTICompleteObjectLocator` pointer and dereferences it. `RTTICompleteObjectLocator` is an internally used structure (not a standard public interface) that stores complete information about the object type, such as the class's type descriptor and the offset to the type name string.

# Diamond Inheritance

```cpp
#include<stdio.h>
#include<stdlib.h>

//间接基类
class A {
public:
    virtual void function() {
        printf("A virtual function\n");
    }
    int a;
};

//直接基类
class B :virtual public A { //虚继承
public:
    virtual void func() {
        printf("B virtual func()\n");
    }
    int b;
};

//直接基类
class C :virtual public A { //虚继承
public:
    virtual void func() {
        printf("C virtual func()");
    }
    int c;
};

//派生类
class D :public B, public C {
public:
    virtual void function() {
        printf("D virtual function()");
    }
    int d;
};


int main(int argc, char** argv) {
    A* A_ptr = (A*)new D();
    A_ptr->function();

    return 0;
}
```
B and C inherit from A; D inherits from B and C
