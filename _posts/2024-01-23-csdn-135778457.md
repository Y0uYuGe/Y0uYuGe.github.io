# How Is Process Control Implemented?
Implemented with primitives

Suppose primitives were not used: if the event that PCB2 is waiting for occurs, and after the kernel program responsible for process control sets state to 1 — because this is not a primitive — an interrupt signal could arrive and interrupt it. At that point PCB2's state=1, yet it is still in the blocked queue, so the state value is contradictory. Using primitives prevents this from happening.

## Child and Parent Processes
The parent process is the original process that creates a child process, while the child process is a new process created by the parent via the fork system call. Details:

1. The parent-child relationship:

- On Linux systems, except for the initial process (process 0), every process is created by another process through the fork() function.
- The process that calls fork() is called the parent process, and the newly created process is called the child process.
- A process can have only one parent process, but it can have multiple child processes.

2. The fork system call:

- fork() is called once, but returns once in the parent and once in the child.
- In the child process, fork() returns 0; in the parent process, it returns the PID of the newly created child process.
3. Execution order of parent and child:

- After fork, the execution order of the parent and child is indeterminate. The OS kernel schedules these two processes, and they may run alternately.
4. Characteristics of the child process:

- The child is a copy of the parent; it inherits most of the parent's attributes, including file descriptors, environment variables, and so on.
- The child can replace its own image with the exec family of functions, thereby executing a new program.
5. Parent-child communication:

- Parent and child can communicate through pipes, signals, shared memory, and many other mechanisms.
- The parent is typically used to create children and wait for them to finish, or to exchange data with the child.
- Understanding the concept and relationship of parent and child processes is crucial for understanding the Unix/Linux process model and is the foundation of multi-process programming.
## Block and Wakeup Primitives
Block primitive: moves a process from the running state to the blocked state
Wakeup primitive: moves a process from the blocked state to the ready state

Where there is blocking there is usually wakeup, so the two come in pairs

![Image](/images/csdn/2024/csdn-135778457/image-008-0b1d019d10.png)
## Switch Primitive
