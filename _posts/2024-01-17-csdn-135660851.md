# Related Knowledge
## Introduction to How WEB Applications Work
The original meaning of WEB is spider web and net; in web page design it is called a web page. It is now widely translated as the network, the Internet, and other technical fields. In daily life, a user uses a browser to request a URL. This URL identifies a specific resource on a specific server. After the server receives the request, the server sends the generated HTML page to the browser via the HTTP protocol.

Early WEB pages had simple content, and HTML alone was enough to meet user needs; at that time the main content of websites was static.
![Image](/images/csdn/2024/csdn-135660851/image-001-1a166ae3b3.png)



As user demands continue to increase, different users often have different needs, and dynamic pages emerged as the times require. Dynamic pages have the following three characteristics:

1. "Interactivity": the page changes and responds dynamically according to the user's requests and choices, using the browser as the client interface. This will be the general trend of future WEB development.

2. "Automatic updating": there is no need to manually update HTML documents; new pages are generated automatically, which can greatly save workload.

3. "Varying with time and person": when different people visit the same URL at different times, different pages are produced.

The working principle of dynamic pages is as follows:

Note: in the third step, the corresponding parser is used to parse and execute according to the type of script, for example index.php is handed to PHP.

## What is LAMP
![Image](/images/csdn/2024/csdn-135660851/image-003-e3221756b9.png)
LAMP is an open-source WEB development platform, using Linux as the operating system, Apache as the WEB server, MySQL as the relational database management system, and PHP as the object-oriented scripting language. Generally, Apache listens on port 80 and accepts user requests from the public Internet.

Apache is developed and maintained by an open community, and is a mature, feature-rich server.
MySQL is an open-source relational database management system used to store application data.
PHP: a programming language. The PHP open-source scripting language works with Apache to help create dynamic web pages. For example, to extract data from a database, you only need to place PHP code into the part of the page you want to make dynamic.
The architecture diagram of the four is shown below:
![Image](/images/csdn/2024/csdn-135660851/image-004-01a3d3a7c4.png)
Requests from the public Internet are first received by Apache. Apache dispatches according to the type of resource requested by the URL (static resources such as html, json, png, jpg, etc.; scripts such as php, asp, etc.). If it is a static file, it directly accesses the corresponding file system and returns its content. If it is a script such as index.php, it is handed to the corresponding script interpreter; index.php corresponds to the PHP interpreter. After PHP executes the code of index.php, the result is returned to Apache, and Apache returns the obtained content to the user. When the PHP script contains code that operates on the database, the process of PHP accessing the database is added as shown in the figure. The other processes remain unchanged.

## What is LNMP
The difference between LNMP and LAMP lies in using Nginx as the WEB server.

Nginx is a compact and efficient WEB server software on Linux. Compared with Apache, using Nginx as a WEB server consumes fewer resources, supports more concurrent connections, and is more efficient.

## What is WNMP
Since the platform has four layers, LAMP is sometimes called the LAMP stack. The stack can be built on different operating systems. When these softwares are used on the Windows operating system, it is called WAMP; on Macintosh systems it is called MAMP, and on Solaris systems it is called SAMP.
W stands for Windows, N for Nginx, M for MySQL, and P for PHP.

## Supplement: The HTTP Protocol

HTTP is the protocol for transmitting HTML over the network, used for communication between browsers and servers.

HTTP requests consist of two parts, request and response, which are the request message sent by the browser to the server and the response message returned by the server, respectively.

An example request message:

```bash
GET / HTTP/1.1
Host: www.sina.com.cn
User-Agent: Mozilla/5.0 xxx
Accept: */*
Accept-Language: zh-CN,zh;q=0.9,en-US;q=0.8
```

The first line indicates using the GET request method to obtain the resource at path /, using the HTTP/1.1 protocol. Starting from the second line, each line is an HTTP header expressed in the form Header: Value.

Commonly used HTTP Headers include:

Host: indicates the hostname being requested, because a server may host multiple websites, so Host indicates the domain name the browser is requesting;
User-Agent: identifies the client itself. For example, the identifier of the Chrome browser looks like Mozilla/5.0 ... Chrome/79, and the identifier of the IE browser looks like Mozilla/5.0 (Windows NT ...) like Gecko;
Accept: indicates the types of resources the browser can receive, such as text/*, image/*, or */* meaning all;
Accept-Language: indicates the browser's preferred language, based on which the server can return pages in different languages;
Accept-Encoding: indicates the compression types the browser can support, such as gzip, deflate, br.
Each line of the HTTP Header ends with \r\n. If two consecutive \r\n are encountered, what follows is the HTTP Body. The HTTP Body usually appears in POST requests.

> \r means returning to the beginning of the line, \n means going to the next line
> '\r' is carriage return, '\n' is line feed. The former moves the cursor to the beginning of the line, the latter moves the cursor down one line. The commonly used Enter is the two combined.

An example POST request:

```bash
POST / HTTP/1.1
Host: qh.qt.zdbc.baicuoa.com
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:89.0) Gecko/20100101 Firefox/89.0
Accept: text/html,application/xhtml+xml,application/xml;q=0.9,image/webp,*/*;q=0.8
Accept-Language: zh-CN,zh;q=0.8,zh-TW;q=0.7,zh-HK;q=0.5,en-US;q=0.3,en;q=0.2
Accept-Encoding: gzip, deflate
Connection: close
Cookie: UM_distinctid=176bb981a6a102-0958497cfbd0fb-4c3f207e-1fa400-176bb981a6c22d; CNZZDATA1277924430=1953373006-1609462947-%7C1624499868; CNZZDATA1277924487=1429083096-1609634137-%7C1624499327
Upgrade-Insecure-Requests: 1
Pragma: no-cache
Cache-Control: no-cache
Content-Type: application/x-www-form-urlencoded
Content-Length: 4

data
```

The response message is as follows:

```bash

HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 21932
Content-Encoding: gzip
Cache-Control: max-age=300
<html>...网页数据...
```

The first line of the server response is version number + space + number + space + text, where a number of 2xx indicates success, 3xx indicates redirection, 4xx indicates an error caused by the client, and 5xx indicates an error caused by the server.

Common response codes include:

200 OK: indicates success;
301 Moved Permanently: indicates that the URL has been permanently redirected;
302 Found: indicates that the URL needs a temporary redirect;
304 Not Modified: indicates that the resource has not been modified, and the client can use the locally cached version;
400 Bad Request: indicates that the client sent a bad request, such as invalid parameters;
401 Unauthorized: indicates that the client is not allowed to access the URL because its identity has not been verified;
403 Forbidden: indicates that the server rejected the client's request due to permission issues;
404 Not Found: indicates that the client requested a resource that does not exist;
500 Internal Server Error: indicates an internal error occurred while the server was processing, for example because it could not connect to the database;
503 Service Unavailable: indicates that the server is temporarily unable to handle the request at this moment.

Starting from the second line, each line returned by the server is an HTTP header. HTTP Headers often returned by servers include:

Content-Type: indicates the type of the response content, such as text/html, image/jpeg;
Content-Length: indicates the length (in bytes) of the response content;
Content-Encoding: indicates the compression algorithm of the response, such as gzip;
Cache-Control: instructs the client how to cache, for example max-age=300 means it can be cached for at most 300 seconds.
