# What Is Inter-Process Communication
Sharing a gossip article involves inter-process communication

Inter-process communication requires operating system support
![Image](/images/csdn/2024/csdn-135845026/image-001-25ce6729df.png)
# Why Does Inter-Process Communication Need OS Support?
A process cannot access memory space that does not belong to it

When processes P and Q need to exchange data, P cannot write data directly into Q's address space, so operating system support is required to accomplish this

![Image](/images/csdn/2024/csdn-135845026/image-002-b4c26f0784.png)
# Shared Memory
Request a memory region to serve as a shared memory area, and map that shared area into the address space of every participating process

Access to the shared memory area must be mutually exclusive

![Image](/images/csdn/2024/csdn-135845026/image-003-1a31e37801.png)
The operating system is only responsible for providing a shared memory region and the mapping; the format of the data each process stores in this area, and where it is stored, are controlled by the processes.

Data-structure-based sharing: it is like defining a data-structure variable that serves as the shared area for other processes. In this case the freedom of communication is low: access must follow the variable's rules (for example, if an integer array variable is defined, every write and read must be of the integer type and obey the array's constraints, such as the element-count limit).

The left figure shows data-structure-based sharing
![Image](/images/csdn/2024/csdn-135845026/image-004-5f359ccdc8.png)
# Message Passing
A formatted message consists of a message header and a message body

![Image](/images/csdn/2024/csdn-135845026/image-005-3f814e2202.png)

## Direct Communication
The kernel area holds each process's PCB, and each process's PCB contains that process's message queue — the messages sent to this process by other processes that it should receive.

P sends a message to Q: in P's process space, complete the message to be sent, then use the send primitive, which specifies the recipient of the message
![](/images/csdn/2024/csdn-135845026/image-006-6d5b040fa3.png)
This send primitive causes the OS kernel to receive the message to be sent and attach it to process Q's message queue (or rather, copy it there)
![Image](/images/csdn/2024/csdn-135845026/image-007-20463e5e55.png)
Process Q uses the receive primitive, which specifies whose message to receive; the OS kernel then copies the message from Q's message queue that came from P into process Q's address space

![Image](/images/csdn/2024/csdn-135845026/image-008-1969a9bb89.png)
## Indirect Communication
Process P requests a mailbox A (or several mailboxes) in kernel space via a system call
Process P completes the message within its own process space (similar to processing data during code execution)
![Image](/images/csdn/2024/csdn-135845026/image-009-9b7b5405e3.png)

Then it uses the send primitive, which specifies the destination mailbox A, and the operating system copies the message into mailbox A
![Image](/images/csdn/2024/csdn-135845026/image-010-7d6deb56c5.png)
Process Q uses the receive primitive, which specifies from which mailbox to receive a message, and the operating system copies the message from mailbox A into process Q's address space
![Image](/images/csdn/2024/csdn-135845026/image-011-b5f0bc846d.png)

# Pipe Communication
A pipe is unidirectional at any given moment (half-duplex)
One process writes into the pipe, another reads content out of the pipe (a circular queue)

A pipe file is requested via a system call; it is essentially an in-memory buffer

If the front of the pipe has free slots, those must be written first; only after the front is full can you write further back. Reading works the same way (first in, first out — essentially a circular queue: what is written first enters first and comes out first; if the front has free space and you write again, the front is written first)

Half-duplex: during any given period, data in a pipe flows in only one direction, from one side to the other. The direction may differ at different times, but a pipe has only one flow direction at a time


Multiple processes reading the same pipe causes confusion — there is no guarantee of which data was read by whom

Processes access a pipe mutually exclusively: at any moment only one process writes to or reads from the pipe
