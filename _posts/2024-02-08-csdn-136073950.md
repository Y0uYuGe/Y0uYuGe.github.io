# Which Layer Does the Stop-and-Wait Protocol Belong To?
The stop-and-wait protocol is a data link layer protocol.

The Stop-and-Wait protocol is a fundamental protocol in data communication. It belongs to the second layer of the OSI model, the data link layer. The main characteristic of this protocol is that it is simple but inefficient, because it requires the sender to stop and wait for the receiver's acknowledgment after sending each data packet. Only after receiving the acknowledgment can the sender continue sending the next packet. If an error or loss occurs during transmission, the sender retransmits the same packet until an acknowledgment is received.

> In the past, network quality was poor, so the link layer needed to use the stop-and-wait protocol to ensure data reliability
With the improvement of network quality today, the link layer is responsible for error control, making data transmission faster with fewer errors, while the transport layer is responsible for reliable transmission

## Numbering
In the stop-and-wait protocol, the frame numbering range is usually 0 and 1.

The stop-and-wait protocol is a basic data link layer protocol that uses frame numbers to distinguish different data frames and ensure the ordered transmission of data. In this protocol, frame numbers usually require only 1 bit, meaning the numbering range is 0 and 1. This design is sufficient for the basic needs of the stop-and-wait protocol, because the core of the protocol lies in the acknowledgment mechanism rather than in being able to handle a large number of frame numbers.
# Stop-and-Wait Protocol - Error Cases
## Data Frame Lost or Detected in Error
If the timeout timer expires before an acknowledgment frame is received, the sender retransmits the frame once the timer expires (automatic retransmission)

RTT: round-trip propagation delay (the time from sending to receiving the acknowledgment)

The retransmission time set on the timeout timer should be longer than the average RTT of frame transmission. Reason: this ensures the sender does not retransmit when the acknowledgment frame is already about to arrive

Keeping a copy (a duplicate of the frame) makes retransmission convenient
Only after receiving the acknowledgment can the sender discard the copy of the frame it just sent

- Numbering: solves the problem of frame loss and duplication
- Frame loss: After the sender sends a frame, it waits for the receiver's acknowledgment. If the acknowledgment is lost, the sender retransmits the same frame after a timeout. Since each frame has a number, the receiver can recognize the duplicate frame, discard it, and send a new acknowledgment to inform the sender that the previous data has been received.
- Frame duplication: If the acknowledgment is delayed, the sender may mistakenly believe that the previous frame was not sent successfully and send the same frame again. In this case, the receiver recognizes it as a duplicate frame by its frame number, discards it, and sends the acknowledgment again.

Frame error: the receiver discards the frame after detecting the error and does not return an acknowledgment

## ACK Delayed
The discarded duplicate frame is the one sent the second time

If the delayed ACK 0 arrives at the sender after frame 1 has been sent, the sender has already received ACK 0 and is currently expecting ACK 1, so it discards the delayed ACK 0

If the delayed ACK 0 arrives after the sender's timeout retransmission, it means frame 0 is complete and the sender starts sending frame 1. When the receiver receives the retransmitted frame 0 again, it retransmits ACK 0; when the sender receives ACK 0 again after sending frame 1, it discards it because it has already received ACK 0

# Performance Analysis of the Stop-and-Wait Protocol
Acknowledgment frame: contains only control information and no data, so it is shorter than a data frame

T0: the delay from when the sender puts the first bit onto the link to when it puts the last bit onto the link (transmission time)

After the data is put onto the link, the next part is the time it travels over the link

Sending cycle: from the moment the first bit is sent until the sender receives the last bit of the acknowledgment frame
