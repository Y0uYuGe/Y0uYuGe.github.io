#  setcbuf
The code setvbuf(stdin, 0LL, 2, 0LL); setvbuf(stdout, 0LL, 2, 0LL); setvbuf(stderr, 0LL, 2, 0LL); is used to set the buffering modes of the standard input, standard output, and standard error streams.

The prototype of the setvbuf function is as follows:

```c
int setvbuf(FILE *stream, char *buffer, int mode, size_t size);
```

 
This function is used to set the buffer of the file stream pointed to by stream, as well as the buffering mode and the size of the buffer.

- stream: The file stream whose buffer is to be set, such as stdin, stdout, stderr, etc.
- buffer: The address of the buffer; setting it to 0LL means no buffer is used at all.
- mode: The buffering mode, which can be one of the following constants:
- _IOFBF: Full buffering
- _IOLBF: Line buffering
- _IONBF: No buffering
- size: The size of the buffer.

In the given code, setvbuf(stdin, 0LL, 2, 0LL); means that the buffering mechanism of stdin is disabled, i.e., input read from stdin is not buffered but obtained directly from the terminal.

Likewise, setvbuf(stdout, 0LL, 2, 0LL); and setvbuf(stderr, 0LL, 2, 0LL); are used to disable the buffering mechanisms of stdout and stderr respectively, so that output will be displayed on the terminal immediately without being buffered.

# scanf
Note that scanf's argument is the position of the first element at the top of the stack. If you enter `-` at this point, scanf will not write any data to the position of scanf's first argument, but it will still consider the input task complete
Since the value at the top of the stack at this point is the address of io_files_jump, and the value of the top stack element is eventually assigned to the argument printed by printf, the libc base address can ultimately be leaked

# Stack Address
There are no fixed offsets between the stack address, the libc base address, and the heap base address

# Vulnerability Point
The size is at most 0x78, and you can only edit twice; edit has an off-by-one
Use the off-by-one to modify the size so that you can free and then malloc again, thereby gaining control over the fd of other chunks
# Approach
- Use the correlation between scanf's argument and the argument eventually printed by printf, together with scanf's behavior when encountering -, to leak the libc base address
- Allocate four chunks, all of size 0x18; use the first chunk's off-by-one to overwrite the second chunk's size so that it can cover the following two chunks
- Free all three chunks
- Malloc to get the large chunk, and modify the data of the subsequent chunks at the same time
- Modify the third chunk's fd to the address of free_hook (at the start of the tcache bin, first in last out)
- Malloc twice, and modify the content of _free_hook to system
- Free (the second chunk) (the second chunk is malloc'd and populated with /bin/sh)

if __name__=="__main__":
