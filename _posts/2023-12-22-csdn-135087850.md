# Factors Affecting Instruction Pipelines
## Setting the Machine Cycle
Under RISC, operands come directly from general-purpose registers

M: memory access stage
WB: stage that writes back to the general-purpose register file
Five-stage instruction pipeline
In most cases instructions can be fetched from the Cache
In most cases main memory accesses can also be served by the Cache
Instructions and data can be stored in two separate Caches
ID: fetch operands from the general-purpose registers
Imm: stores the immediate of the instruction
The result computed by the ALU may be written back to main memory, or directly back to a general-purpose register
![Image](/images/csdn/2023/csdn-135087850/image-009-373a2d829f.png)
## Factors Affecting the Pipeline
### Structural Hazards (Resource Conflicts)
Resource duplication means taking a resource that was originally accessed in one place and splitting it into two places, so there is no longer a conflict

![Image](/images/csdn/2023/csdn-135087850/image-010-6bb31c53e9.png)
### Data Hazards (Data Conflicts)
This happens because a later instruction depends on the result produced by an earlier instruction for its computation; if executed in the idealized order, the r1 data used by the later instruction has not yet been modified by the first instruction
![Image](/images/csdn/2023/csdn-135087850/image-011-c92c831533.png)
A bubble can be understood as doing nothing; it is equivalent to letting some time pass before starting the second instruction
![Image](/images/csdn/2023/csdn-135087850/image-012-c948b40333.png)
Using nop to wait
![Image](/images/csdn/2023/csdn-135087850/image-013-4610d1cd32.png)
Data forwarding connects the data line of the ALU's result back to one of the ALU's inputs, so there is no need to wait for the write-back operation
![Image](/images/csdn/2023/csdn-135087850/image-014-e653617da9.png)
Compiler optimization
That is, adjusting the instruction order by moving instructions that do not depend on the results of previous instructions to an earlier position for execution
![Image](/images/csdn/2023/csdn-135087850/image-015-a7dca93691.png)
### Control Hazards (Control Conflicts)
With pipelined execution, by the time the PC is modified, the following instructions have already partially started, but the instruction that should run next is not the one whose partial run has already begun — hence the conflict
![Image](/images/csdn/2023/csdn-135087850/image-016-ad602b21a7.png)
Simple prediction directly places the instructions corresponding to a certain case into the pipeline right after the jump instruction
![Image](/images/csdn/2023/csdn-135087850/image-017-c5f397da47.png)
With prefetching, the instruction pipelines for both outcomes exist, but a choice is still made about how to execute
![Image](/images/csdn/2023/csdn-135087850/image-018-fc0496f132.png)
That is, decide in advance so the subsequent instruction pipeline can be arranged accordingly
![Image](/images/csdn/2023/csdn-135087850/image-019-5101f16723.png)
Just improve the probability of guessing right

# Classification of Instruction Pipelines
A component-function pipeline is one where a tiny operation can be divided into several parts, and multiple operations can again be pipelined
Like Russian nesting dolls
Inter-processor: each processor sits on the pipeline (in the first row the processors are arranged one by one, and in the second row likewise, and so on)
Processor: the functional components inside the processor sit on the pipeline
Component-function level: the sub-function components inside a component sit on the pipeline
![Image](/images/csdn/2023/csdn-135087850/image-021-61e96e20ff.png)
A unifunction pipeline is one whose parts are all built to accomplish a single function
A multifunction pipeline realizes one pipeline capable of multiple functions through multiple combinations of connections between its parts
![Image](/images/csdn/2023/csdn-135087850/image-022-5351fd94d7.png)
A static pipeline has a fixed connection scheme
A dynamic pipeline has a variable connection scheme, enabling complex functions
![Image](/images/csdn/2023/csdn-135087850/image-023-ec2b7ad7c2.png)

A linear pipeline is a pipeline without loops
A nonlinear pipeline is the opposite
![Image](/images/csdn/2023/csdn-135087850/image-024-35e54a60e4.png)
# Multiple-Issue Techniques for Pipelines
The instruction execution order that cannot be adjusted is constrained by the mutual dependencies between them

## Superscalar Technology
Here multiple CPUs with multiple instruction registers run multiple instructions concurrently
![Image](/images/csdn/2023/csdn-135087850/image-025-54c93655b5.png)
## Superpipelining Technology
That is, making full use of the time inside a machine cycle, subdividing further when a later instruction can start within one machine cycle, or when certain components become free, so that certain parts of instructions can start running — similar to a component-function-level pipeline
![Image](/images/csdn/2023/csdn-135087850/image-026-b6f576bd70.png)
## Very Long Instruction Word
Since one CPU can only execute the function corresponding to one opcode, combining them here requires multiple CPUs to execute the individual opcodes
![Image](/images/csdn/2023/csdn-135087850/image-027-ea16070511.png)
