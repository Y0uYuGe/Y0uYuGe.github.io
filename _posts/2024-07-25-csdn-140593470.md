The decompiled code corresponding to the differing location in bindiff, belonging to case 4

The channel-related string GuestMsg: Channel %u, Not enough memory to receive a message was found in it, and combined with the switch-case at the beginning of the function that checks number is in the range 0-6, it is easy to associate this with the GuestRPC Handler (the code that handles RPC communication), an RPC command handler function. The code below only contains the part where the vulnerability is located; you can see this path is the handling part for subcommand=0x4, i.e., Receive reply data

Here, need represents the length of data that has not yet been sent. When need >= 4, 4 bytes are sent each time, and the case of need < 4 is specially handled at the end. The backdoor function is located in the check for need == 3.

Additionally, debugging revealed that state == 3 occurs during the phase where the host replies with data to the guest. Therefore, we need the length of the data the host replies to the guest to be congruent to 3 modulo 4, while buf happens to be exactly the command to be executed.

Debugging revealed that the reply data length is the length of the string following info-set guestinfo.x plus 2, and the executed command is exactly this string (prepended with two bytes containing a character 1 — recv rpc data mentions that the first two bytes of rpctype indicate success or failure, and Receive RPC reply length mentions that the first two bytes of the reply data always indicate the status of the RPC command). So the final total count of need is the length of the string following info-set guestinfo.x plus 2, i.e., `1 string`, and buf is the starting address of this. Therefore, when system executes the command, it will execute `1 string`. In order to execute the command inside the string, the string starts with a ; to terminate it. Finally, we just need to ensure the string length plus 2 modulo 4 equals 3 (that is, the string length modulo 4 equals 1)

Here the `;` already counts as one character, so we just need to make sure the rest is a multiple of 4. This amounts to arbitrary command execution, since we can pad by adding spaces and finally append a ; or &, otherwise the virtual machine will have problems
![Image](/images/csdn/2024/csdn-140593470/image-003-a1e09c74c4.png)

Also, the parameter of the executed command is fixed as 1 at the front; I appended a ; after it to execute the next command, so the final command to be executed is /usr/bin/xcalc ;

The colons in asm:
- The empty string after the first colon indicates there are no output operands.
- The empty string after the second colon indicates there are no input operands.
- The list after the third colon is the clobbered register list, used to tell the compiler which registers are modified by the embedded assembly code.
