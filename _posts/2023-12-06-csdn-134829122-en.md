# Analyzing the Makefile in code/asm/add
makefile
```bash
EXEC = test

SRC = ${EXEC}.s

GDBINIT = ../gdbinit

include ../rule.mk
```
Obviously it also has to execute rule.mk

rule.mk
```bash
include ../../common.mk

.DEFAULT_GOAL := all
all:
	@${CC} ${CFLAGS} ${SRC} -Ttext=0x80000000 -o ${EXEC}.elf
	@${OBJCOPY} -O binary ${EXEC}.elf ${EXEC}.bin

.PHONY : run
run: all
	@echo "Press Ctrl-A and then X to exit QEMU"
	@echo "------------------------------------"
	@echo "No output, please run 'make debug' to see details"
	@${QEMU} ${QFLAGS} -kernel ./${EXEC}.elf

.PHONY : debug
debug: all
	@echo "Press Ctrl-C and then input 'quit' to exit GDB and QEMU"
	@echo "-------------------------------------------------------"
	@${QEMU} ${QFLAGS} -kernel ${EXEC}.elf -s -S &
	@${GDB} ${EXEC}.elf -q -x ${GDBINIT}

.PHONY : code
code: all
	@${OBJDUMP} -S ${EXEC}.elf | less

.PHONY : hex
hex: all
	@hexdump -C ${EXEC}.bin

.PHONY : clean
clean:
	rm -rf *.o *.bin *.elf
```
It also has to execute common.mk, and then run the corresponding target given on the command line
common.mk

```bash
CROSS_COMPILE = riscv64-unknown-elf-
CFLAGS = -nostdlib -fno-builtin -march=rv32ima -mabi=ilp32 -g -Wall

QEMU = qemu-system-riscv32
QFLAGS = -nographic -smp 1 -machine virt -bios none

GDB = gdb-multiarch
CC = ${CROSS_COMPILE}gcc
OBJCOPY = ${CROSS_COMPILE}objcopy
OBJDUMP = ${CROSS_COMPILE}objdump
```
## Related Commands
QEMU -s automatically starts gdbserver when the emulator starts; gdbserver and gdb connect over the network. The gdb server default port is 1234, and it then waits for gdb to connect. The -S parameter means gdbserver stops after starting the debugged program and then waits for user input. -kernel ./executable specifies the image to load
gdb -q removes the messy things printed at startup; -x specifies a configuration script that gdb runs when it starts

Remote debugging means the program to be debugged is not local: the computer hosting the debugged program runs gdbserver, and the local machine can connect to gdbserver via gdb to debug that remote program

## add2

> For the two's complement of 4 and -4
Sign extension: just extend according to the sign bit
Zero extension (unsigned extension): always extend with 0
For 4, directly compute the binary encoding of 4 as 0100 (leaving one bit as the sign bit), and since it is a positive integer, extend 0 to the left, giving 00000100
For -4, first compute the binary encoding of 4 as 0100, then invert and add 1 to get 1100; since the sign bit is 1, extend 1 to the left, giving 11111100
