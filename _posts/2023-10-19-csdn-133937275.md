# Storage of the Encoding After Sending

> For a certain address
Execute in gdb:
x/30xg 0x603290
0x6032c0：0x0068732f6e69622f   /bin/sh
2f: is the ASCII code for /
Then execute:
x/30xg 0x6032c1
0x6032c1:	0x000068732f6e6962  bin/sh
62: is the ASCII code for b

> This shows that string storage stores from left to right with addresses from low to high; what gdb displays is the encoding after little-endian conversion

> The string "\x41" is stored directly as 41 in the corresponding position, i.e., the content encoding at that position is 41
