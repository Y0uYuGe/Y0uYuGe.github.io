## Thread Implementation Methods
## User-Level Threads
The program itself implements thread management and scheduling through a thread library it designs

For example, QQ has three functions that must run simultaneously; implementing this with processes means three processes, one per function

![Image](/images/csdn/2024/csdn-135883746/image-002-b9b0894d2f.png)
What if a single process implements it? That amounts to executing the three functions concurrently
![Image](/images/csdn/2024/csdn-135883746/image-003-db6cfd19f6.png)

Thread management work: done by the thread library (as with the while loop above), not the operating system.
Thread switching is completed by the program's own thread library, with no CPU mode switch
The operating system is unaware of user-level threads; it is merely executing the process's code, and the thread-library part of that code enables the threads to run concurrently

Advantages: switching threads only needs to be done in user mode
Disadvantages: when one thread blocks on a piece of code, all other threads of the entire process block as well, and multiple threads all run on a single CPU (the CPU's scheduling unit is still the process)

![Image](/images/csdn/2024/csdn-135883746/image-004-88a2407071.png)

## Kernel-Level Threads
Thread management work is done by the operating system
Thread switching requires a CPU mode switch (operating system involvement)

After kernel-level threads are introduced, the basic unit of CPU scheduling becomes the thread, and multiple threads can also be dispatched onto multiple CPUs to run in parallel

![Image](/images/csdn/2024/csdn-135883746/image-005-b5d889f91d.png)

### Many-to-Many
At this point there are two kinds of mapping between kernel-level threads and user-level threads
One kernel-level thread mapping to many user-level threads is the many-to-one case above
One kernel-level thread mapping to one user-level thread is the one-to-one case

## Thread Organization and Control
Saving the stack pointers means saving the thread's stack-top and stack-bottom addresses; after switching threads, the thread's stack information remains in memory

Thread tables can be organized in different ways: for example, all threads of the system in one table, or tables organized per process, or tables organized by thread state
