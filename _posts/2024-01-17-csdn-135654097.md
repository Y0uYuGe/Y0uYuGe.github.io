# The complete flow of the program interrupt method
First, the CPU starts the external device by executing an IO instruction; the external device can then begin its preparation work (preparing the data or information the CPU wants). During the external device's preparation, the CPU can continue executing the original program's contents
When the IO device finishes its work, it sends an interrupt request to the CPU indicating that its preparation work is complete; the instruction just executed at this point corresponds to K, and after the interrupt is handled, execution returns to instruction K+1

The interrupt handler also includes letting the IO device resume its work (for example, when outputting n characters, if an interrupt is initiated character by character, the interrupt handler must also resume the IO device's work, or rather continue executing the previous IO instruction, because it has not finished executing), and letting the peripheral prepare the next data

# Summary

![Image](/images/csdn/2024/csdn-135654097/image-003-64d13a8613.png)
The complete flow of the program interrupt method mainly includes the following steps:

1. An interrupt source issues an interrupt request. The interrupt source can be a hardware device (such as a keyboard, mouse, timer, etc.) or software (such as a system call, exception handling, etc.).

2. Determine whether the processor currently allows interrupts and whether this interrupt source is masked. This is to prevent unnecessary interrupts from interfering with the CPU's normal work.

3. Priority queuing. If multiple interrupts occur simultaneously, the preset priorities are used to decide which interrupt to handle first.

4. The processor finishes executing the current instruction, or if the current instruction cannot be completed, it immediately stops the current program, protects the breakpoint address and the processor's current state, and transfers to the corresponding interrupt service routine. This is the interrupt response stage, which includes saving the scene and jumping to the entry address of the interrupt service routine.

5. Execute the interrupt service routine. In this stage, the CPU handles the received interrupt, such as executing the device driver, managing user processes, etc.

6. Return to the original program and continue executing. After the interrupt is handled, the CPU returns to where it was originally interrupted and continues executing the original program.
