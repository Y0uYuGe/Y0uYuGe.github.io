# Circuit Switching
![在这里插入图片描述](/images/csdn/2024/csdn-135920188/image-003-ba0e826ef4.png)
## The Phases of Circuit Switching
### Establishing the Connection
First, A sends a call request to its connected switching device A; the request contains the addresses of the source host A and the destination host B
Then switching device A uses a routing algorithm to choose the next hop and forwards the call request from A to the next node, switching device B
Then switching device B uses a routing algorithm to choose the next hop and forwards the call request from A to the next node, switching device C
Then switching device C uses a routing algorithm to choose the next hop and forwards the call request from A to the next node, switching device D
Then switching device D forwards the call request directly to B

If B can accept A's connection request, it sends a call answer back along the original path

Once A receives it, the connection line between A and B is successfully established
![在这里插入图片描述](/images/csdn/2024/csdn-135920188/image-004-34b78fc1d8.png)
### Data Transfer
At this point A and B communicate in full-duplex mode
And the link is the line determined earlier
### Releasing the Connection
A sends a release request along the previously established line
After receiving the release request, B returns a release answer, also along the original path back to A, and each segment of the connection is torn down in turn (e.g., when the release reaches D, the connection between D and B is torn down)
![在这里插入图片描述](/images/csdn/2024/csdn-135920188/image-005-96a9b4ac37.png)
## Characteristics of Circuit Switching
Circuit switching is a switching technology used in communication networks, with the following notable characteristics:

1. Establishing a dedicated path: a dedicated communication path is established between the two communicating parties and remains open until the communication ends.
2. Unit of information transfer: in circuit switching, the smallest unit of information transfer is the time slot, i.e., data is transmitted within pre-allocated time slots.
3. End-to-end communication: circuit switching provides end-to-end communication, which means that once the circuit is established, data can be transmitted directly between the two endpoints.
4. Resource allocation: circuit switching dynamically allocates the resources of the transmission line in some manner; once the circuit is established, those resources are exclusively occupied by the communicating pair.
5. Application scenarios: circuit switching is mainly used in telephone networks to complete telephone calls; it has a history of over 100 years. It is also the earliest switching method to appear and is very widely used.

In summary, the characteristic of circuit switching is providing a dedicated, continuous communication path for the two communicating parties; this method suits scenarios requiring continuous, stable communication, such as traditional telephone calls 

Exclusive resources: the established link cannot be used by other users
Suitable for large volumes of data transfer: because establishing the connection takes some time, transferring too little would not be worth the cost

## Advantages and Disadvantages of Circuit Switching
The line is exclusively occupied, so transmission follows the line directly, resulting in low delay
In-order delivery, no reordering: it is like a conveyor belt — the belt is the line, and once data is placed on it, it travels to the destination host (first placed, first arrived). Hence in-order delivery with no reordering problem

Circuit switching mainly uses switches (switching exchanges) as its switching devices

- No data storage capability: because circuit switching establishes connections in real time, it has no ability to store data. This means that if any interruption or error occurs during communication, data may be lost and cannot be retransmitted or corrected as in packet switching.
- Difficulty smoothing traffic: circuit-switched resources are exclusively occupied by the communicating pair; even when the line is idle, other users cannot use it, resulting in low channel utilization. Therefore, when traffic fluctuates greatly, circuit switching can hardly allocate and optimize resources dynamically, unlike packet switching, which can smooth traffic effectively.

Data travels directly, so if the device types differ, the data may not be recognized or processed

## Advantages and Disadvantages of Message Switching
Users can send messages at any time: there is no need to wait for a connection to be established before sending
Dynamically allocated routes: smooths traffic. Suppose A-to-B traffic is heavy while A-to-C traffic is light, and C can also reach the destination host; then switching device A can dynamically choose to send messages to switching device C   

Note that in the fourth advantage, occupying the channel is not exclusive either

Message switching can send to multiple destination addresses at once mainly because it provides multi-destination service. This capability allows a message to be copied and sent to multiple intended recipients, which is hard to achieve in circuit switching — circuit switching is like passing a single letter around, so in the end only one person can receive it. Message switching is like being able to copy the letter and pass it on to others, so in the end many people can receive it.

Specifically, here are some detailed explanations:

1. Store-and-forward mechanism: every node in a message-switching network has storage capability and can temporarily hold messages passing through. When a message arrives at a node, it is stored first, then forwarded according to the destination address in the message. This mechanism allows a message to be copied at a node and sent to different destinations.
2. Flexible routing: message switching allows dynamic routing — a message can choose the best path based on network conditions during transmission. This flexibility allows a message to be sent to multiple destinations as needed, without being constrained by a fixed path.
3. No connection setup needed: unlike circuit switching, message switching does not require establishing a fixed communication path in advance. This means a message can be sent directly to multiple destinations without setting up multiple connections beforehand.      

Real-time: can be understood as reacting quickly

## Advantages and Disadvantages of Packet Switching
In packet switching, the switching node's memory management can be simplified to buffer management because packet lengths are fixed: in a packet-switching network, packet length is usually fixed, which means the buffer size each packet requires is also fixed. This fixed size lets the switching node pre-allocate a fixed-size buffer for each arriving packet, thereby simplifying memory management.

Reduced waiting-to-send time: the time a packet in the buffer waits for the previous packet to be sent is relatively short
Small packets: the error probability is naturally smaller, and less data needs to be retransmitted

Packet switching is suitable for bursty data communication.

Packet switching divides data into multiple small, equal-length segments and prepends the necessary control information as a header to each segment, forming packets. This mechanism enables packet-switched networks to handle bursty data traffic efficiently. The reasons packet switching suits bursty data communication include:

1. High resource utilization: packet switching does not pre-occupy the resources of an entire communication link; a link segment's resources are occupied only while a packet is being transmitted over it. This means link resources can be used by other communications when no data is being transmitted, improving resource utilization.
2. Strong flexibility: packet switching uses store-and-forward, allowing switches to temporarily store received packets, queue them on the route toward the destination, and forward them later. This mechanism lets the network adapt better to traffic fluctuations, maintaining high transmission efficiency even under bursty traffic.
3. Good adaptability: because packets are short, packet switching is especially suited to bursty data communication between computers. In bursty communication, data is often discontinuous, and packet switching can respond quickly to this discontinuity, achieving fast data transmission.
4. Strong fault tolerance: each packet in a packet-switched network carries complete address and control information, so even if some packets are lost or corrupted during transmission, they can be independently retransmitted or corrected without affecting the rest of the data stream.
5. Priority management: a packet-switched network can assign different priorities to different packets based on urgency; urgent data can be transmitted immediately, which is ideal for bursty urgent data.

Although packet switching has advantages in handling bursty data communication, it also has some disadvantages, such as store-and-forward delay and the need for more powerful node switches. However, these disadvantages do not prevent packet switching from being an effective way to handle bursty data communication in modern communication networks.
                                              
The transmission delay of packet switching is smaller than that of message switching mainly because packet switching uses smaller data units for transmission. Specifically, the advantages of packet switching lie in:

1. Smaller transmission units: packet switching splits data into smaller packets, which are shorter than a complete message and therefore faster to transmit.
2. Parallel processing capability: because packets are independent, they can be transmitted in parallel over different paths in the network without waiting for the entire message to be transmitted, reducing transmission delay.
3. Buffer management efficiency: in packet switching, packet lengths are fixed, making buffers easier to manage; switches can process and forward packets quickly, reducing processing time at nodes.
4. Lower queuing delay: in packet switching, because packets are small, even when network traffic is heavy, a packet's waiting time in the queue is relatively short, reducing queuing delay.
5. Fault tolerance: packet switching handles each packet independently; if an error occurs, only the erroneous packet needs retransmission rather than the entire message, which also helps reduce overall transmission delay.

In summary, by splitting data into small units for transmission, packet switching not only improves network transmission efficiency but also reduces transmission delay, making it a widely adopted data transmission method in modern communication networks.      

When packet switching uses datagram service: specifically, datagram service is a form of packet switching that does not require establishing a fixed communication path before data transfer. In this service, each packet independently selects its route and may reach the destination via a different path. The advantage of this approach is its flexibility and speed, because there is no need to establish and maintain a fixed communication path in advance. However, it also brings challenges: packets may arrive out of order, be lost, or be duplicated, and they must be reassembled into the original message at the destination node.

# Choosing Among the Data Switching Methods
As can be seen, message switching requires the whole message to arrive at the next node before that node can process it, whereas packet switching does not: while the current node sends the next packet, the node that received the previous packet can already forward that packet to the next node. So packet switching has lower delay than message switching

Low delay: therefore suitable for the fast processing of bursty data communication

# The Two Modes of Packet Switching
## The Datagram Mode
![在这里插入图片描述](/images/csdn/2024/csdn-135920188/image-023-4b7ea1fce3.png)
### Characteristics of the Datagram Mode
All the packet switching discussed earlier was in the datagram mode
Packets of the same message may arrive at the destination out of order, duplicated, or lost, so packet numbers are needed to handle this

In network communication, a switching node may discard some packets; this usually happens during network congestion or failures. When a switching node's buffer space is insufficient to store more packets, it may discard some packets according to a certain policy to keep the network running normally.

Discarding packets can affect data transmission, causing problems such as data loss and increased transmission delay. Therefore, when designing a network system, this situation must be considered and appropriate measures taken to handle it.

A common method is to include information such as sequence numbers and checksums in packets so the receiver can detect and repair lost packets. In addition, some network protocols provide retransmission mechanisms that allow the sender to resend a packet when no acknowledgment has been received.

### Characteristics of the Virtual Circuit Mode
Circuit switching is a physical connection, while a virtual circuit is a logical connection. Detailed analysis:

- Circuit switching: a communication method that establishes a dedicated physical path between the two communicating parties. This connection is physical because it involves actual physical lines that are exclusively occupied for the duration of the communication until it ends. Circuit switching is connection-oriented: a fixed physical path must be established before data transfer, and this path remains open and unchanged throughout the communication.
- Virtual circuit: a virtual connection established in the network that does not involve exclusive occupation of physical lines. A virtual circuit is realized by establishing a series of logical associations among multiple nodes in the network; these logical associations can be viewed as a "virtual" path on top of the physical network. A virtual circuit connection is temporary — it is released when the session ends — and one physical line can support multiple virtual-circuit logical connections.

The link is still shared; a virtual circuit is not exclusive, unlike circuit switching

## Datagram & Virtual Circuit
Datagrams and virtual circuits have different reliability guarantee mechanisms, as follows:

Reliability guarantees of datagrams:

- Guaranteed by the user host: in datagram service, the network layer provides best-effort delivery and does not guarantee reliable packet transmission. Therefore, reliability is usually guaranteed by the user host. This means users must handle packet errors, loss, duplication, and reordering themselves. For example, reliability and ordering are ensured by implementing acknowledgment, retransmission, and sequencing mechanisms in higher-layer protocols (such as TCP).
- Complete addresses: each datagram packet contains the complete address of the destination, which allows each packet to be routed independently and increases network flexibility. However, it also means each packet must carry extra routing information, increasing overhead.

Reliability guarantees of virtual circuits:

- Guaranteed by the network: virtual circuit service is connection-oriented; the network maintains this logical connection and can usually provide fairly reliable data transmission. Once the connection is established, all packets are transmitted along the same route, and the nodes in the network maintain the state of this connection, thereby guaranteeing reliability and ordering.
- Short virtual circuit number: in a virtual circuit, once the connection is established, each packet only needs to identify itself with
- a short virtual circuit number, reducing header overhead. At the same time, because packets travel along the same path, the network can provide flow control and error control, further improving communication reliability.

In summary, the reliability of datagram service mainly depends on the user host's processing, while the reliability of virtual circuit service is guaranteed by the network itself.


Datagrams and virtual circuits have different mechanisms and policies for error handling and flow control.

Error handling and flow control of datagrams:

- Error handling: in datagram service, each packet is transmitted independently, so error handling is usually the responsibility of the destination host. The destination host must perform error detection on each received datagram, typically using a checksum or CRC check. If an error is found, the datagram is discarded and retransmission may be requested. The retransmission strategy depends on the higher-layer protocol; for example, TCP uses acknowledgments and timeout mechanisms to achieve reliable transmission.
- Flow control: datagram service itself does not provide flow control. Flow control is usually implemented by higher-layer protocols; for example, TCP controls the sending rate through the sliding-window mechanism to adapt to network congestion and the receiver's processing capacity.

Error handling and flow control of virtual circuits:

- Error handling: virtual circuit service provides a more reliable communication method. Once the connection is established, all packets are transmitted along the same route; the nodes in the network maintain the state of this connection and perform error detection. If a packet has an error, the network can take appropriate action, such as requesting retransmission or reporting the error. This mechanism ensures the reliability and integrity of data transmission.
- Flow control: virtual circuit service usually provides flow control mechanisms to ensure the sender does not exceed the receiver's processing capacity or the network's capacity. This can be achieved with techniques such as buffer management and window mechanisms. For example, the sender may adjust its data sending rate based on feedback received from the receiver.

In summary, datagrams and virtual circuits have different strategies and mechanisms for error handling and flow control. Datagrams rely on the destination host and higher-layer protocols for error handling and flow control, while virtual circuits have these functions provided by the network itself.
