# Casually Made Shellcode
mmap is a method of memory-mapping files, i.e., mapping a file or other object into the address space of a process, establishing a one-to-one correspondence between file disk addresses and a segment of virtual addresses in the process's virtual address space. After establishing such a mapping, the process can read and write this segment of memory using pointers, and the system automatically writes dirty pages back to the corresponding file on disk—completing operations on the file without needing to call system call functions like read and write. Conversely, modifications to this region in kernel space are also directly reflected in user space, thereby enabling file sharing between different processes

> In Linux everything is a file. All system calls that perform I/O operations go through file descriptors. When a program just starts, 0 is standard input, 1 is standard output, and 2 is standard error. If a new file is opened at this point, its file descriptor will be 3.
The direction of standard input and output is default; after opening a terminal by default, 0, 1, and 2 all point to the same location, i.e., the current terminal. We can modify where they point, which is redirection

# got-it
Exploits the property that the GOT table, data segment, and bss segment are adjacent, and the property that the lower bound of arrays is not checked

>  Python 3.1 introduced a new integer class method int.to_bytes(). It is the reverse conversion method of int.from_bytes() discussed in the previous article.
>>> (258).to_bytes(2, byteorder="little")
b'\x02\x01'
>>> (258).to_bytes(2, byteorder="big")
b'\x01\x02'
>>> (258).to_bytes(4, byteorder="little", signed=True)
b'\x02\x01\x00\x00'
>>> (-258).to_bytes(4, byteorder="little", signed=True)
b'\xfe\xfe\xff\xff'
The first argument is the length of the converted byte data; the second argument byteorder defines the byte order as little or big-endian; the optional argument signed determines whether two's complement is used to represent the integer.


When outputting bytes, it follows this principle: each byte read is compared against the ASCII codes; if it is a displayable ASCII character (special characters, letters and digits, excluding control characters), then that byte is represented according to the ASCII code, otherwise it is represented as hexadecimal \x-something.
So a bytes object cannot contain a unicode string beyond the ASCII code range of 0 to 127, and cannot accept unicode strings beyond this range
b'string' denotes a bytes object; in this case it is equivalent to a function bytes('string') that accepts a unicode string within the ASCII code range of 0 to 127
\x plus two hexadecimal digits represents one byte
encode converts to bytes; bytes can be converted back to a string via decode

This shows that the bytes type's display format is hexadecimal format, with ASCII codes shown as-is unchanged, but the final stored value is still the binary format value equivalent to the corresponding hexadecimal value format.

Always remember: what is displayed is hexadecimal format; what is stored is the corresponding code value. For example:

>>> b'a'[0]
97

What is displayed is the character a; what is actually stored is the corresponding ASCII code value 97

> When a Python module (.py file) is created, some built-in variables are automatically loaded, and __name__ is one of them.
> Python modules usually define many variables and functions; these variables and functions are like features of the module. When the module is imported into other files, these variables and functions can be called. This is where the role of __name__ shows: it can identify the module's name, and can show whether a certain feature of a module is executed by itself or called and executed by another file.
> Suppose there are modules A and B; module A defines feature C itself, module B imports module A, and now feature C is executed:
If C is executed by A itself, that is, the module executed a feature it defined itself, then __name__=='__main__'

If C is executed by being called from B, that is, the current module called and executed another module's feature, then __name__=='A' (the name of the called module)
