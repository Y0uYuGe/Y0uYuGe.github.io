# Time Complexity of Algorithms
## How to Evaluate the Time Cost of an Algorithm
If you run the algorithm on a machine and then measure its time afterward, the results will differ due to different machines, different languages used to implement the algorithm, and different compiler efficiencies
And since for some algorithms you cannot wait until after they finish running to measure their running time, running the algorithm first and then measuring the running time is unreasonable
![Image](/images/csdn/2024/csdn-135333560/image-012-108a3fa941.png)
## Computing the Time Complexity of an Algorithm
Counting the number of times each statement is executed gives a time complexity of 3n+3
When a program has too many statements and the time complexity expression becomes too complex, what should we do?

### Do We Need to Count the Code Line by Line?
Sequentially executed code only affects the constant term, so it is not considered
Multiple operations inside a loop also only affect the coefficient of n, so they are not considered either; you only need to consider how many times one operation of the loop executes
![Image](/images/csdn/2024/csdn-135333560/image-018-763f6eb046.png)
When there are multiple nested loops, the outer loops are negligible compared to the inner loop
So just consider the number of executions of the innermost loop
![Image](/images/csdn/2024/csdn-135333560/image-019-a92562668b.png)

# Space Complexity of Algorithms
## Memory Requirements of a Program at Runtime
Fixed size, unrelated to the problem scale, means the space occupied does not change as the input changes
Working in place means the space complexity is constant
![Image](/images/csdn/2024/csdn-135333560/image-024-8292603f0d.png)
When n becomes very large here, the constant-level terms can be ignored, and the space occupied depends on the variables related to the problem scale
![Image](/images/csdn/2024/csdn-135333560/image-025-fade0f8b10.png)
![Image](/images/csdn/2024/csdn-135333560/image-026-b6ee516130.png)
![Image](/images/csdn/2024/csdn-135333560/image-027-635fa0f8eb.png)
## Space Complexity of Recursive Functions
The parameters and local variables used in each level of the call require additional storage space
You can refer to the function call stack, which stores the saved/restored function stack information and the local variables and parameters of the corresponding function
The space needed after entering the function at each level of recursion is fixed (in the figure below it is fixed), and as a coefficient it can be ignored
![Image](/images/csdn/2024/csdn-135333560/image-028-3a0192efa9.png)
Here the space occupied by the function call at each level of recursion depends on the passed-in parameters, so the space required is not fixed
![Image](/images/csdn/2024/csdn-135333560/image-029-02426d6755.png)
