# Random Algorithm (RAND)
It does not selectively consider which Cache block to replace, or in other words does not consider the principle of locality (the Cache block likely to be used), so the Cache block to be accessed next time may be replaced, leading to frequent replacements

![Image](/images/csdn/2023/csdn-134642195/image-003-39be6026ef.png)
  
# First-In-First-Out Algorithm (FIFO)
The Cache block that entered first is replaced first
![Image](/images/csdn/2023/csdn-134642195/image-004-01ff779131.png)

# Least Recently Used Algorithm (LRU)
Manually determine which Cache block to replace: look backward from the main memory block currently being accessed, comparing it with the Cache blocks, until only one Cache block has no corresponding main memory block — replace it  
When the total number of Cache blocks is 2^n, the counter only needs n bits.
After it is full, there are only replacements and hits; on replacement, the one with the largest counter value is replaced; on a hit, since counters lower than the hit one are incremented by 1, the number of bits of the largest counter still does not exceed n bits
And after the Cache is full, all counter values are guaranteed to be distinct.
Thrashing may still occur
![Image](/images/csdn/2023/csdn-134642195/image-005-702fe0711d.png)
# Least Frequently Used Algorithm (LFU)
If there are multiple lines with the smallest counter (multiple lines tied for the smallest counter), the one to replace can be chosen by increasing line number or by the FIFO (first-in-first-out) strategy
A newly loaded block's counter is set to 0, and is incremented by 1 on each subsequent access. When replacement is needed, the line with the smallest counter is chosen  
The counter has more bits, because at this point there is no limit on the counter value
