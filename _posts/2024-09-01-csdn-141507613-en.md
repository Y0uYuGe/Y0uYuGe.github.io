```c
char *__fastcall alloc(int size)
{
  struct chunk *next_use_chunk; // [rsp+4h] [rbp-20h]
  signed int up_align_16_size; // [rsp+10h] [rbp-14h]
  struct chunk *v4; // [rsp+14h] [rbp-10h]
  struct chunk *v5; // [rsp+1Ch] [rbp-8h]

  if ( !size )
    return 0LL;
  up_align_16_size = (size + 15) & 0xFFFFFFF0;
  v5 = next_use_chunk_ptr;
  v4 = 0LL;
  while ( 1 )
  {
    if ( !v5 )
      return 0LL;
    if ( up_align_16_size <= v5->size )
      break;
    v4 = v5;
    v5 = v5->next_use_chunk;
  }
  if ( v5->size >= (unsigned __int64)(up_align_16_size + 16LL) )
  {
    next_use_chunk = (struct chunk *)&v5->buff[up_align_16_size];
    next_use_chunk->size = v5->size - up_align_16_size - 16;
    next_use_chunk->next_use_chunk = v5->next_use_chunk;
    v5->next_use_chunk = next_use_chunk;
    v5->size = up_align_16_size;
  }
  if ( v4 )
    v4->next_use_chunk = v5->next_use_chunk;
  else
    next_use_chunk_ptr = v5->next_use_chunk;
  return v5->buff;
}
```
First, it searches from `next_use_chunk` for a use_chunk_ptr whose size is greater than or equal to `up_align_16_size `. If the use_chunk_ptr found is the current initial next_use_chunk_ptr (the first chunk that can be used), it directly updates `   next_use_chunk_ptr = v5->next_use_chunk;`. It also decides whether to split based on `v5->size >= (unsigned __int64)(up_align_16_size + 16LL)` — whether size is greater than or equal to the total length of the current chunk (greater-or-equal means that after splitting at least a remaining 0x10 part is left that can serve as a chunk_header). If size only satisfies being greater than or equal to `up_align_16_size `, it iterates with ` next_use_chunk_ptr = v5->next_use_chunk;` (cannot split, meaning the current chunk happens to fit exactly)

Since the size of the last next_use_chunk is the remaining length rather than the buff length, while the comparisons are normally done against the buffer length, the remaining length gets treated as the buffer length. When the remaining length is 0x10, allocating 0x20 at this point overflows by 0x10 bytes.

Note that the allocated size is the input `len+0x10& 0xFFFFFFF0`, while the length of the input content is `len+1`, so the input content can only fill that one overflowed byte — but this can be avoided with `len=0x xxxf`

## Delegating Constructors
A delegating constructor is a feature introduced in C++11 that allows one constructor to call another constructor of the same class. This feature can reduce code duplication and improve the maintainability and readability of the code. With delegating constructors, we can perform standardized initialization of an object in one constructor and then reuse that initialization logic in the other constructors.

### Syntax of Delegating Constructors

The basic syntax is to call another constructor through the initializer list. For example:

```cpp
class Example {
public:
    // 主构造函数
    Example(int a, int b, int c) {
        // 初始化逻辑
        x = a;
        y = b;
        z = c;
    }

    // 委托构造函数，调用主构造函数
    Example(int a, int b) : Example(a, b, 0) {}

    // 委托构造函数，调用主构造函数
    Example(int a) : Example(a, 0, 0) {}

    // 委托构造函数，调用主构造函数
    Example() : Example(0, 0, 0) {}

private:
    int x, y, z;
};
```

### Explanation

1. **`Example(int a, int b, int c)`**
   - This is the main constructor, responsible for initializing all three member variables `x`, `y`, and `z`.

2. **`Example(int a, int b) : Example(a, b, 0) {}`**
   - This is a delegating constructor; it calls the main constructor `Example(int a, int b, int c)` and defaults the third parameter `c` to `0`.
   - This avoids duplicating the initialization logic in the constructors.

3. **`Example(int a) : Example(a, 0, 0) {}`**
   - This constructor is simplified even further: it only needs one parameter `a`, with the other two parameters set to `0`, and continues to delegate to the main constructor.

4. **`Example() : Example(0, 0, 0) {}`**
   - The no-argument constructor; all parameters are set to the default value `0`.


##  std:remove and std:erase
This code removes a specific `Company*` pointer from `std::vector<Company*> companies`. Let's walk through how this code works and the principle behind it:

### Code Explanation

```cpp
companies.erase(std::remove(companies.begin(), companies.end(), company_to_remove), companies.end());
```

1. **The `std::remove` function**

   - **Purpose**: `std::remove` is an algorithm in the C++ standard library that rearranges the elements in the range `[first, last)` so that all elements not equal to `value` are moved to the front, and returns a new iterator pointing to the new end after the "removal" operation.
   - **Parameters**:
     - `companies.begin()`: an iterator pointing to the beginning of the vector.
     - `companies.end()`: an iterator pointing to the end of the vector.
     - `company_to_remove`: the specific `Company*` pointer that needs to be removed from the vector.
   - **Result**: `std::remove` does not actually delete elements; it moves the unwanted elements to the back and returns an iterator to the new end.

2. **The `companies.erase` function**

   - **Purpose**: `erase` is a member function of `std::vector` that actually removes the elements in the specified range from the vector.
   - **Parameters**:
     - The first parameter is the iterator to the new end returned by `std::remove`.
     - The second parameter is `companies.end()`, pointing to the real end of the vector.
   - **Result**: `erase` removes from the vector all the elements from the iterator returned by `std::remove` to the end of the vector.

### Principle

- **The "remove-erase" idiom**: This code uses the "remove-erase" idiom in C++, a common pattern for deleting elements from STL containers. Because `std::remove` only rearranges the elements without changing the container's size, `erase` is needed to actually remove those extra elements.

- **Efficiency**: This method is efficient because it only traverses the container once, moving elements with `std::remove`, which avoids the inefficiency caused by calling `erase` multiple times in a loop.

### Memory Management Considerations

- **Deleting pointers**: When using `std::vector<Company*>`, `erase` only removes the pointers; it does not delete the heap memory the pointers point to. If the `Company*` pointers were allocated with `new`, the programmer must make sure to release that memory with `delete` before or after the removal, to avoid memory leaks. For example:

  ```cpp
  auto it = std::remove(companies.begin(), companies.end(), company_to_remove);
  for (auto iter = it; iter != companies.end(); ++iter) {
      delete *iter; // 释放堆内存
  }
  companies.erase(it, companies.end());
  ```

When a `double` and a `uint64_t` are multiplied and the result is then converted to `uint64_t`, if the result exceeds the range representable by `uint64_t`, it can cause an overflow. In some cases, the overflowed result may be converted to `0`.

### 1. Background
`uint64_t` is a 64-bit unsigned integer whose range is `[0, 2^64 - 1]`, i.e. `[0, 18446744073709551615]`. When the product of a `double` exceeds this range, converting it to `uint64_t` causes an overflow.

In C/C++, when a floating-point number is converted to an unsigned integer type, if the floating-point number exceeds the representable range of the target type, the behavior is undefined. The concrete behavior may vary with the compiler and runtime environment. On some systems, the overflowed result may be treated as `0`.

### 2. Example Code
Here is an example demonstrating this situation:

```cpp
#include <iostream>
#include <cstdint>
#include <limits> // For std::numeric_limits

int main() {
    uint64_t a = 18446744073709551615ULL; // uint64_t的最大值
    double b = 2.0; // 将使结果超过uint64_t最大值

    double result_double = a * b; // 先计算乘积，结果为double
    uint64_t result_uint64 = static_cast<uint64_t>(result_double); // 转换为uint64_t

    std::cout << "Double result: " << result_double << std::endl;
    std::cout << "Converted to uint64_t: " << result_uint64 << std::endl;

    return 0;
}
```

In this example:
- `a` is the maximum value of type `uint64_t`, `18446744073709551615`.
- `b` is the `double` value `2.0`.

When `a` and `b` are multiplied, the result is `36893488147419103230` (i.e. `2 * 18446744073709551615`), which far exceeds the maximum value of type `uint64_t`.

When converting `result_double` to `uint64_t`, because the result exceeds the representable range of `uint64_t`, the behavior is undefined. Under some compilers or runtime environments, the overflowed result may be treated as `0`.

## Vector Insertion Logic

```c
__int64 __fastcall std::vector<Worker *>::emplace_back<Worker *&>(__int64 a1, __int64 a2)
{
  __int64 v2; // rax
  __int64 v3; // rax
  __int64 v4; // rbx
  __int64 v5; // rax
  __int64 v7; // [rsp+20h] [rbp-20h]

  if ( *(_QWORD *)(a1 + 8) == *(_QWORD *)(a1 + 16) )
  {
    v4 = std::forward<Worker *&>(a2);
    v5 = std::vector<Worker *>::end(a1);
    std::vector<Worker *>::_M_realloc_insert<Worker *&>(a1, v5, v4);
  }
  else
  {
    v2 = std::forward<Worker *&>(a2);
    v7 = *(_QWORD *)(a1 + 8);
    v3 = std::forward<Worker *&>(v2);
    std::construct_at<Worker *,Worker *&>(v7, v3);
    *(_QWORD *)(a1 + 8) += 8LL;
  }
  return std::vector<Worker *>::back(a1);
}
```

### 1. Function Parameters
- `a1`: this is the address of the `std::vector<Worker*>` object.
- `a2`: this is a reference of type `Worker*`, representing the pointer to be inserted into the `std::vector`.

### 2. Local Variables
- `v2`, `v3`, `v4`, `v5`: these are intermediate variables, usually used to store computation results.
- `v7`: used to store the address of the current end element of the `std::vector`.

### 3. Logic Analysis

```cpp
if ( *(_QWORD *)(a1 + 8) == *(_QWORD *)(a1 + 16) )
```

- `a1 + 8`: points to the current end of the `std::vector` container (i.e. the first free slot).
- `a1 + 16`: points to the end of the `std::vector` container's capacity (i.e. the capacity limit position).

This line checks whether the `std::vector` is full (i.e. whether the current number of elements equals the capacity). If it is full, it enters the reallocation logic; otherwise it inserts the element directly at the current end.

### 4. Reallocation Logic

```cpp
v4 = std::forward<Worker *&>(a2);
v5 = std::vector<Worker *>::end(a1);
std::vector<Worker *>::_M_realloc_insert<Worker *&>(a1, v5, v4);
```

- `v4`: uses `std::forward` to forward `a2`, i.e. the `Worker*` pointer to be inserted.
- `v5`: calls `std::vector<Worker*>::end()` to get the end iterator of the `std::vector`, pointing to the position where the element is currently being inserted.
- `_M_realloc_insert`: an internal function of `std::vector`, used to perform insertion during reallocation. It reallocates a larger block of memory, then copies the old data and the new data into the new memory.

### 5. Direct Insertion Logic

```cpp
v2 = std::forward<Worker *&>(a2);
v7 = *(_QWORD *)(a1 + 8);
v3 = std::forward<Worker *&>(v2);
std::construct_at<Worker *,Worker *&>(v7, v3);
*(_QWORD *)(a1 + 8) += 8LL;
```

- `v2`: uses `std::forward` to forward `a2`, getting the `Worker*` pointer to be inserted.
- `v7`: gets the address of the current end of the `std::vector` (i.e. the insertion position).
- `v3`: processes `v2` through `std::forward` again, yielding the `Worker*` pointer.
- `std::construct_at`: constructs a new `Worker*` at address `v7`, i.e. inserts the new `Worker*` at the end of the `std::vector`.
- `*(_QWORD *)(a1 + 8) += 8LL`: updates the end pointer of the `std::vector` to point to the next free slot.

### 6. Return Value

```cpp
return std::vector<Worker *>::back(a1);
```

- Finally, the function returns the last element of the `std::vector<Worker*>` container (i.e. the element just inserted).
