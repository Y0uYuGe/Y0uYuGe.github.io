# Task
Can be understood as a segment of instructions to be executed

# Task Context
Can be understood as the state of each CPU register corresponding to the execution of that task

# Multitasking

When the number of cores is smaller than the number of tasks to run, the tasks take turns running on the CPU, ensuring that every task appears to be executing at the macro level

# Multitasking System Classification
Cooperative multitasking: the code within a task gives up the CPU and switches to the next task
Preemptive multitasking: the operating system decides when to give up the CPU and switch to the next task
![Image](/images/csdn/2024/csdn-137368860/image-001-ddcfbbf28e.png)
# Cooperative Multitasking


Initialization means setting up the context of each task (the context of each task is saved in memory), such as setting the context's ra (return address) to the task's first instruction

![Image](/images/csdn/2024/csdn-137368860/image-002-9f2f18b52e.png)
When switching to a certain task (the switch_to function)

1. First save the current CPU register state into the original task's context
2. Modify the mscratch register to point to the next task's context (the mscratch register is a special control and status register (CSR) that holds the address of the task's context)
3. Load the next task's context into the current CPU
4. After the ret instruction, the next task begins executing
![Image](/images/csdn/2024/csdn-137368860/image-003-653c72b20e.png)

##   `asm volatile("csrw mscratch, %0" : : "r" (x));`

This assembly code is a special instruction used in the RISC-V architecture; its purpose is to write the value of register `x` into the `mscratch` register.

Let's explain this instruction step by step:

1. `asm volatile("csrw mscratch, %0" : : "r" (x));`
   - `asm`: This is an inline assembly instruction, used to insert assembly code directly into C/C++ code.
   - `volatile`: This keyword tells the compiler not to perform any optimization or reordering on this assembly instruction.
   - `"csrw mscratch, %0"`: This is the assembly instruction template, where:
     - `csrw`: a special RISC-V instruction used to write a register's value into a control and status register (CSR).
     - `mscratch`: the target CSR register to write to, i.e., the `mscratch` register mentioned earlier.
     - `%0`: a placeholder used to reference the input operand below.
   - `: : "r" (x)`: This is the definition of the input operand, where:
     - `"r"`: indicates that this is a read-only input operand. (That is, the operand will not be modified during execution)
     - `(x)`: indicates using the value of register `x` as input.

In summary, the purpose of this instruction is to write the value of register `x` into the `mscratch` register. This kind of operation is typically used to save and restore register state in exception, interrupt, or trap handlers.

##  lw and sw
SW and LW are two important instructions in the RISC-V instruction set, representing Store Word and Load Word respectively. They are used to transfer data between memory and registers.

1. SW (Store Word) instruction:
   - Its purpose is to store data from a register to a specified address in memory.
   - The instruction format is `sw rd, offset(rs1)`, where `rd` is the register to be stored, `offset` is the offset of the memory address, and `rs1` is the base address register.
   - For example, `sw x10, 8(x11)` stores the data in register x10 to memory address `x11 + 8`.

2. LW (Load Word) instruction:
   - Its purpose is to load data from memory into a register.
   - The instruction format is `lw rd, offset(rs1)`, where `rd` is the destination register for the loaded data, `offset` is the offset of the memory address, and `rs1` is the base address register.
   - For example, `lw x12, 4(x13)` loads the data at memory address `x13 + 4` into register x12.

The SW and LW instructions are the two most basic and commonly used instructions in the RISC-V instruction set. They give RISC-V the ability to efficiently transfer data between memory and registers, and are the foundation for building complex computing systems.


## gp, tp, and zero Registers

1. gp (Global Pointer) register:
   - The gp register is used to store the base address of the global data segment.
   - In large programs, global variables and static variables are usually placed in the global data segment.
   - Through the gp register, these global variables can be accessed quickly without computing complex address offsets.
   - The gp register can reduce the number of instructions and improve program performance.

2. tp (Thread Pointer) register:
   - The tp register is used to store the base address of the current thread/task's local storage area.
   - In multithreaded/multitasking systems, each thread/task has its own local storage area, and the tp register is used to quickly access these areas.
   - The tp register can simplify memory access during thread/task switching, improving performance.

3. zero register:
   - The zero register is a special register whose value is always 0.
   - Writing data to the zero register is equivalent to discarding that data.
   - Reading data from the zero register always returns 0.
   - The zero register is very useful when a NOP (No Operation) instruction or a zeroing operation is needed.

These three registers play important roles in the RISC-V architecture, providing RISC-V systems with efficient global data access, thread management, and basic operation support.
