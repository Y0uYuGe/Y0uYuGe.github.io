# WebAssembly

WebAssembly is a portable binary instruction set format that is platform-independent, similar to Java's class file bytecode.

WebAssembly was originally designed to let browsers run code from compiled languages like C. Normally, our C code is compiled and linked directly by compilers like gcc or clang into platform-dependent binary executables, and such platform-dependent binaries cannot be run directly by a browser. If you want a browser to run C code, you need a compiler that can compile C into WebAssembly instructions; the compiled code is in wasm format. Then you can use various wasm runtimes to execute the wasm code, similar to how the JVM virtual machine executes class files.

Since the instruction set and runtime environment are not inherently tied to web scenarios, with later development standalone runtime environments for the WebAssembly instruction set that can run outside the browser appeared, and the uses of WebAssembly became broader.

# Wasmtime
Compared to the browser runtime, wasmtime is a standalone runtime environment that can execute wasm code outside the Web environment. It provides two ways to execute wasm code: a command-line tool and an API.

At startup, the flag is in memory as an environment variable. Here the wasm code is AOT-compiled into an ELF, so it is run with ` --allow-precompiled`
```bash
./wasmtime run --env FLAG="flag{zhiyinnitaimei}" --disable-cache --allow-precompiled ./wtoa
```
