# Side-Channel Attacks
A side-channel attack is a type of security attack that exploits physical information leakage to obtain secret information from cryptographic systems, such as keys. Side-channel attacks usually involve the following aspects:

- Electromagnetic leakage: obtaining information by monitoring the electromagnetic radiation produced by a device.
- Timing analysis: inferring the key by analyzing the execution time of cryptographic operations.
- Power analysis: also known as differential power analysis (DPA), inferring the key by measuring the power consumption changes of a device when processing different data.
- Acoustic leakage: obtaining information by analyzing the sounds emitted by a device.
- Fault analysis: deliberately introducing errors or faults to disrupt the encryption process, thereby obtaining critical information.
- In addition, in practice an attacker may guess the key bit by bit and judge whether each guess is correct by observing changes in side-channel information. For example, if the character guessed by the attacker matches a certain bit of the actual key, the cryptographic device may produce a specific electromagnetic signal, sound, or power consumption change at a particular moment. In this way, the attacker can gradually deduce the complete key.
> A side-channel attack is an unconventional attack method that uses the sounds a computer inadvertently emits to judge its execution state — for example, judging the complexity of the program a computer is running by the loudness of its cooling fan; deciphering what you are typing by eavesdropping on the sound of keystrokes; or monitoring your computer through the different amounts of power consumed by computer components when executing certain programs.

# Related Knowledge
## size_t getpagesize(void)

Function description: returns the size of a page, in bytes. This is the system's page size, which is not necessarily the same as the hardware page size.

Return value: the memory page size.

Additional note: on Intel x86 its return value should be 4096, i.e. 0x1000

Use the getpagesize function to obtain the size of one memory page
## void *mmap(void *addr, size_t length, int prot, int flags, int fd, off_t offset);
[Understanding mmap in depth](https://www.cnblogs.com/binlovetech/p/17712761.html)

> If addr is NULL, then the kernel chooses the (page-aligned)
       address at which to create the mapping; this is the most portable
       method of creating a new mapping.  If addr is not NULL, then the
       kernel takes it as a hint about where to place the mapping; on
       Linux, the kernel will pick a nearby page boundary (but always
       above or equal to the value specified by
       /proc/sys/vm/mmap_min_addr) and attempt to create the mapping
       there.  If another mapping already exists there, the kernel picks
       a new address that may or may not depend on the hint.  The
       address of the new mapping is returned as the result of the call.


> When Linux allocates virtual memory for mmap, it always starts from the page boundary closest to addr, and guarantees that the address is not lower than the value specified by /proc/sys/vm/mmap_min_addr.
We can see that mmap_min_addr = 65536 = 0x10000, so we just determined that the program uses the mmap function to allocate a page of space at 0x10000.


- addr: specifies the starting address of the mapping. It is usually set to NULL to let the system automatically choose a suitable address. If the MAP_FIXED flag is set, a specific address must be provided.
- length: the length of the mapping, i.e., the size of memory to map, in bytes.
- prot: the access permissions of the mapping, which can be a combination of the following values:
PROT_READ: readable
PROT_WRITE: writable
PROT_EXEC: executable
PROT_NONE: not accessible
- flags: the attributes of the mapping, which can be a combination of the following values:
MAP_SHARED: writes to the mapping are written back to the file
MAP_PRIVATE: writes to the mapping are not written back to the file
MAP_FIXED: use the specified mapping start address; if the mapping cannot be successfully established at the specified address, the call fails
fd: the file descriptor, specifying the data source of the mapping. If it is -1, no file is associated.
- offset: the file mapping offset, indicating from which position in the file the mapping starts. Usually set to 0.
- Return value:
On success, returns the starting address of the mapping;
On failure, returns MAP_FAILED (usually (void *)-1).

# Approach
First open the file, read its contents to an accessible location, and then compare the characters of each byte one by one. Since we can only open and read files, to distinguish whether the comparison of each byte is right or wrong, we can use the time interval when receiving.

> If the comparison succeeds, the program enters an infinite loop (we can use the time module to get the difference between timestamps). For example, if the elapsed time exceeds 2 seconds, we have successfully brute-forced one byte of the flag. The reason it exceeds two seconds is that when no exception occurs, a receive operation lasting 3 seconds is set, so after three seconds the interval is definitely greater than 2 seconds; when an exception occurs — that is, the loop was not entered (the comparison failed) — an exception is raised. Combined with the try and except keywords in Python, this allows byte-by-byte brute forcing.
