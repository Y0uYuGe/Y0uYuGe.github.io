# Single-stepping Through Source Code
n/s are both C-language-level breakpoint stepping. s will enter the inside of a C function, but will not enter a function without debugging information (for example, code compiled without -g, because it has no line-number markers for the C code, so it cannot be located; you can run the "set step-mode on" command so that gdb does not skip functions without debugging information, but instead enters their assembly; you can then debug the function using the methods for debugging assembly programs), while n will not.

Put simply, it means executing the source code line by line.

# Single-stepping Through Assembly
ni/si are both assembly-level breakpoint stepping. si will enter the inside of assembly and C functions, while ni will not.

Put simply, it means executing assembly code line by line.


# Summary of si, ni, s, n

Summary: when you need to enter and debug a library function that has no debugging information, using si is the only way.

When entering a function that has debugging information, both si and s can be used, but they are different: si locates to the first statement at the assembly level, while s enters the first statement at the C level.
# Exiting the Function Being Debugged
[Reference link](https://www-zeuthen.desy.de/unix/unixguide/infohtml/gdb/Returning.html)

```c
#include <stdio.h>

int func(void)
{
    int i = 0;

    i += 2;
    i *= 10;

    return i;
}

int main(void)
{
    int a = 0;

    a = func();
    printf("%d\n", a);
    return 0;
}
```

When single-stepping through a function, if you don't want to keep tracing it, there are two ways to exit.

The first is to use the "finish" command, so the function continues executing until it finishes, and then reaches the instruction position corresponding to the return address.

![Image](/images/csdn/2024/csdn-135856178/image-009-81f22bd140.png)
The second is to use the "return" command, so the function does not continue executing the following statements, but returns directly. You can also use the "return expression" command to specify the return value of the function. Still taking the above code as an example:

# Printing Function Stack Frame Information

```c
#include <stdio.h>
int func(int a, int b)
{
	int c = a * b;
	printf("c is %d\n", c);
}

int main(void) 
{
	func(1, 2);
	return 0;
}
```

To make it convenient for users to view the information recorded in a certain stack frame while debugging a program, the gdb debugger provides the frame and backtrace commands.

When debugging with gdb on Linux, it is common to view function stack frame information.

The bt (abbreviation of backtrace) command: view the stack information of the functions above the current function on the stack.

The i frame (abbreviation of info frame) command: view the stack frame information of the function currently being debugged. The stack information viewed this way is more detailed.


![Image](/images/csdn/2024/csdn-135856178/image-014-a1677a303a.png)
It outputs information such as the address of the current function's stack frame, the values of the instruction registers, and the addresses and values of local variables.

# Printing Tail-call Stack Frame Information

```c
#include<stdio.h>
void a(void)
{
        printf("Tail call frame\n");
}

void b(void)
{
        a();
}

void c(void)
{
        b();
}

int main(void)
{
        c();
        return 0;
}
```
When the last instruction of a function is a call to another function, a compiler with optimization options enabled often takes the return value of the last-called function as the caller's return value; this is called a "tail call". # Selecting a Function Stack Frame

```c
#include <stdio.h>

int func1(int a)
{
        return 2 * a;
}

int func2(int a)
{
        int c = 0;
        c = 2 * func1(a);
        return c;
}

int func3(int a)
{
        int c = 0;
        c = 2 * func2(a);
        return c;
}

int main(void)
{
        printf("%d\n", func3(10));
        return 0;
}
```
You can use the "frame n" command to select a function stack frame, where n is the level number. Then, through info frame you can view the selected function stack frame, or directly use frame to view the currently selected stack frame. Only the display format of the information is different.

# Switching Function Stack Frames Up or Down

```c
#include <stdio.h>

int func1(int a)
{
        return 2 * a;
}

int func2(int a)
{
        int c = 0;
        c = 2 * func1(a);
        return c;
}

int func3(int a)
{
        int c = 0;
        c = 2 * func2(a);
        return c;
}

int main(void)
{
        printf("%d\n", func3(10));
        return 0;
}
```

You can use the "up n" or "down n" commands to select a function stack frame upward or downward, where n is the number of levels. Taking the above program as an example:
up increases its frame number by 1, and down decreases the frame number by 1.
![Image](/images/csdn/2024/csdn-135856178/image-021-1f5e7cd73e.png)
The two commands "up-silently n" and "down-silently n" differ from the "up n" and "down n" commands in that after switching the stack frame, no information is printed. Still taking the above program as an example:
