# Problems with the Storage System
Add a Cache layer to alleviate the working speed mismatch between the CPU and main memory

# How Cache Works
After a program is started, its code is taken from secondary storage into memory, and then moved from memory into Cache, so that when the CPU executes the program's code, it can fetch it directly from Cache, which is faster
 ![在这里插入图片描述](/images/csdn/2023/csdn-134613179/image-002-ddb1f850ac.png)

# Principle of Locality
 Spatial locality: information to be used in the near future is adjacent in storage space
 Temporal locality: information to be used in the near future may be information that has already been used
(Here, information refers to data or instructions)
![在这里插入图片描述](/images/csdn/2023/csdn-134613179/image-003-86a58f77c1.png)
# Performance Analysis
Two access methods

 - First:
 Access Cache first; if it misses, then access memory.
 The average access time is greater than the Cache access time and less than the sum of the Cache access time plus the memory access time
 
 - Second
  Access Cache and memory simultaneously
  The average access time is greater than the Cache access time and less than the memory access time

![在这里插入图片描述](/images/csdn/2023/csdn-134613179/image-004-f5eddbbbcb.png)

# Defining What "Local" Means
Main memory is divided into blocks of equal size; when certain data from main memory needs to be placed into Cache, the block containing that data is considered the locality and is placed together into a certain Cache block (it's a copy, not a cut)
