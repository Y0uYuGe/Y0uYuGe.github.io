## The Semaphore Mechanism
wait: the entry-section operation
signal: the exit-section operation
![Image](/images/csdn/2024/csdn-136073106/image-002-8f5a2b2c34.png)
### Integer Semaphores
wait: checks whether the current resources are sufficient; if not, it spins in a loop; if sufficient, the semaphore is decremented by one
signal: increments the semaphore by one

The check and the lock are done in one atomic step, so there is no case where a process switch happens before locking, letting another process pass the check and enter the critical section

![Image](/images/csdn/2024/csdn-136073106/image-003-90d27e7dab.png)
### Record Semaphores
![Image](/images/csdn/2024/csdn-136073106/image-004-1419a3cf99.png)
#### Example
First, process P0 performs wait; the initial value of value is 2![Image](/images/csdn/2024/csdn-136073106/image-005-66c823c458.png)
After wait, value becomes 1, and process P0 starts using the printer resource it obtained. Then the process switches to P1, and P1 is about to execute wait
![Image](/images/csdn/2024/csdn-136073106/image-006-a4786a3ce6.png)
After wait, value becomes 0, and process P1 starts using the printer resource it obtained. Now value is 0 and all resources are allocated; the process then switches to P2, which is ready to execute wait
![Image](/images/csdn/2024/csdn-136073106/image-007-db463b5ee9.png)
After wait, value becomes -1. Since it is less than 0, the resource cannot be used at this time, so the block function is used to suspend process P2 into the semaphore's waiting queue
![Image](/images/csdn/2024/csdn-136073106/image-008-ad030f586f.png)
Since process P2 has entered the blocked state, the CPU switches to serve process P3. After wait the value is -2, which is less than zero, so block is also executed and P3 is appended to the tail of the waiting queue
![Image](/images/csdn/2024/csdn-136073106/image-009-d72cacad08.png)
Next the CPU serves P0. Suppose process P0 has finished using the printer and executes the signal primitive; value is incremented by one. If value is still less than or equal to 0, wakeup is executed to wake the process at the head of the waiting queue. Then, at the next process switch, the CPU switches to P2
![Image](/images/csdn/2024/csdn-136073106/image-010-2f7e7f8e3a.png)
Now P2 can start using the printer resource. After finishing, it executes signal; value is incremented by 1, and the process at the head of the waiting queue is woken up — process P3 changes from the blocked state to the ready state

![Image](/images/csdn/2024/csdn-136073106/image-011-753e1e470a.png)

If the process switches to P1 at this point, P1 executes signal after finishing with the printer; since value is now greater than 0, no wakeup occurs

![Image](/images/csdn/2024/csdn-136073106/image-012-4125edbd2c.png)
Then the process switches to P3; after it finishes using the printer, value is incremented by 1 and no wakeup occurs
![Image](/images/csdn/2024/csdn-136073106/image-013-b5c0b5acd1.png)
####  Summary of Record Semaphores
Self-blocking: voluntarily giving up the right to use the CPU
![Image](/images/csdn/2024/csdn-136073106/image-014-ad489644e0.png)
The record semaphore implements the request and release of system resources through the P operation (wait/request) and the V operation (signal/release). The specific mechanisms of these two operations are as follows:

- Resource request (P operation / Wait operation): When a process needs to use a resource, it performs a P operation to request it. During the P operation, the process checks the value of the semaphore. If the semaphore value is greater than 0, resources are available: the process enters the critical section and decrements the semaphore by 1. If the semaphore value is 0, no resources are available: the process cannot enter the critical section immediately and is instead blocked and placed into the waiting queue until the semaphore value becomes positive.
- Resource release (V operation / Signal operation): When a process has finished using a resource and is about to leave the critical section, it performs a V operation to release the resource. This operation increments the semaphore value by 1, indicating that one more resource is available. At the same time, if other processes are blocked in the waiting queue due to insufficient resources, the system selects one or more of them to unblock, allowing them to continue execution.
## Summary
block: value<0
wakeup: value<=0
