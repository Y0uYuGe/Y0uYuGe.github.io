# Arithmetic Shifts
10010000 shifted right by one bit gives 11001000.

Right shift corresponds to division.
Left shift corresponds to multiplication.
![Image](/images/csdn/2024/csdn-136426367/image-004-829402c60d.png)
There is no arithmetic left shift, because a left shift would shift the sign bit away.
 
 Compilers sometimes optimize multiplication and division instructions into shift instructions.

```c
#include<stdio.h>

int main()
{
    unsigned int a,b,c;
    c=0x87654321;
    a=(c<<16)>>16;
    b=c>>16;
    printf("a: 0x%x\n",a);
    printf("b: 0x%x\n",b);
}
```

```bash
.section .data
number:     .int 0x87654321
lowBits:    .int 0
highBits:   .int 0

.section .text
.globl _start
_start:
    movl number, %eax
    sall $16,%eax
    shrl $16, %eax
    movl %eax, lowBits

    movl number, %eax
    shrl $16, %edx
    movl %edx, highBits

    movl $1, %eax
    int $0x80
```

```bash
.macro set_struct s,a,b
    movl \a,\s

stru:

.section .text
.globl _start
_start:
    nop

.foo:
    movl $0x12345678, %eax
    movl $0x87654321, %edx
    set_struct stru,%eax,%edx
    movl $0, %eax
    movl $0, %edx
    get_struct stru,%eax,%edx
    ret
```


### register
In C, the register keyword is used to tell the compiler that variable a should try to be stored in a CPU register rather than in RAM. In principle, this can make access to and operations on variable a faster, because the data in CPU registers can be processed directly without spending time accessing RAM. However, this suggestion usually has no practical effect on modern optimizing compilers, because compilers usually automatically choose which variables to store in registers.

The above statement declares an unsigned integer variable named a and tries to store it in a register.

Note that the register keyword is only a suggestion, and the compiler can choose to ignore it. In addition, you cannot take the address of a register variable, because it may not exist in memory and thus has no memory address to reference.

However, in modern programming, using the register keyword is now rare; optimizing compilers are smart enough to automatically decide which variables should be stored in registers for the best performance.
###  .macro macro_name [parameter1, parameter2, ...] ; assembly instructions .endm

```bash
.macro macro_name [parameter1, parameter2, ...] ; 汇编指令 .endm
```

- macro_name: this is the name of the macro you define; you use it when calling the macro.
- parameter1, parameter2, ...: these are the parameters passed to the macro. Inside the macro body, you can use a backslash followed by the parameter name (\parameter1, \parameter2, etc.) to reference these parameters.
- All lines between the .macro and .endm directives are regarded as the definition of the macro; when the macro is called, these lines replace the macro call. .macro macro_name [parameter1, parameter2, ...] ;
