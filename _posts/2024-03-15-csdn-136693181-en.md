# ln

```bash
ln [参数] 链接源 链接目标

其中，链接源指的是被链接文件或目录的路径，链接目标指的是所要创建的链接文件的路径。

常用参数： -s 或 --symbolic：创建符号链接（软链接），默认情况下创建的是硬链接。 -f 或 --force：若目标文件或目录已存在，则先删除再创建链接。
```
1. Create a hard link: Suppose there is a file named file.txt in the current directory; use the following command to create a hard link named link.txt:

```bash
ln file.txt link.txt
```

 
2. With this command, we create a hard link link.txt that shares the same inode and data blocks as the original file file.txt. Even if we delete the original file file.txt, link.txt still exists and can continue to access its contents.
Create a symbolic link (soft link): Suppose there is a file named file.txt in the current directory; use the following command to create a symbolic link named link.txt:

```bash
ln -s file.txt link.txt
```

 
With this command, we create a symbolic link link.txt, which is a special type of file containing a path reference to the original file file.txt. If we delete the original file file.txt, link.txt will be unable to access the original file's contents, because it is just a reference to a path.
- Differences between hard links and symbolic links: 
- (1) A hard link shares the same inode and data blocks as the original file; they are treated as the same file in the file system. A symbolic link, on the other hand, is a special type of file that contains a path reference to the original file. 
- (2) Modifications to a hard link and the original file affect each other; the original file's contents can be modified even through the hard link. A symbolic link is just a reference pointing to the original file, and modifying the symbolic link does not affect the original file. 
- (3) If the original file is deleted, the hard link can still be accessed and no data is lost, because the hard link shares the same inode and data blocks as the original file. Deleting the original file, however, causes the symbolic link to be unable to access the original file's contents.

# Offset Between unsorted bin and main_arena
malloc_hook is located 0x10 above main_arena
main_arena+96=unsorted bin
main_arena-0x10=__malloc_hook
__malloc_hook=unsorted bin-0x10-96
# Approach
There are UAF and double free vulnerabilities,
1. First fill up the tcache bin
2. Then free one more chunk into the unsorted bin and leak the libc address through the UAF
3. Then determine the corresponding version, which turns out to be 3.31 (decide which method to use based on the version)
6. Then use the UAF to modify the fd of the chunk that just entered the tcache bin to the address of free_hook,
7. After two mallocs, obtain the chunk and modify the value of free_hook,
8. Finally, set up /bin/sh and then free to getshell
