## The Operating System Kernel
The core functions of the operating system are in the kernel
![在这里插入图片描述](/images/csdn/2024/csdn-135725503/image-002-3eb62c4cf2.png)
For programs categorized by how closely they are tied to hardware
![在这里插入图片描述](/images/csdn/2024/csdn-135725503/image-003-18266ff309.png)
Since work such as process management, memory management, and device management is less connected to hardware, sometimes it is not placed in the kernel.
So some operating systems do not put these functions in the kernel, keeping only the parts most closely in contact with the hardware

Therefore, there are two kernel design approaches at this point

Functions belonging to the kernel need to run in kernel mode; functions not belonging to the kernel run in user mode
![在这里插入图片描述](/images/csdn/2024/csdn-135725503/image-004-f994de8536.png)

##  Performance Differences Between Monolithic Kernels and Microkernels
With a microkernel, process management, storage management, and device management all involve work that requires requesting the kernel, which requires a mode switch

A monolithic kernel only needs two mode switches

# Layered Structure, Modularization, and Exokernel

## Layered Structure
![在这里插入图片描述](/images/csdn/2024/csdn-135725503/image-009-1af514e339.png)

Each layer only uses the interface of the layer below it

Debugging starts from the bottom layer, ensuring that the upper layer has no problems with the interfaces of the layer below, so you only need to focus on debugging the current layer

Easy to extend: you only need to provide the interfaces between layers

Sometimes the bottom layer may need functionality from a higher layer, which conflicts with the rule that higher layers can only call lower layers, so it is difficult to reasonably define the boundaries of each layer

Cross-layer calls are not allowed, so requests need to be passed down layer by layer
![在这里插入图片描述](/images/csdn/2024/csdn-135725503/image-010-5eaeaad558.png)
## Modularization
![在这里插入图片描述](/images/csdn/2024/csdn-135725503/image-011-b85e1fef9f.png)

There are many module calls, so the definition and implementation of interfaces is sometimes not perfect enough to make every module fit exactly

All modules can call each other, so if a problem occurs in one module, the problem may lie in the called module or in the module itself

 Being able to develop in parallel once interfaces are determined means that after the interfaces are defined, the code implementations of each interface can be prepared simultaneously

## Exokernel

Exokernel
The exokernel allocates and reclaims unabstracted (non-virtualized, i.e. physical-address) hardware resources

Programs call some kernel functions of the ordinary kernel through library functions, and can also call some functions of the exokernel

In an ordinary operating system, when a process requests memory space it gets a virtual address space (contiguous), where virtual pages correspond to actual physical page frames, and these physical page frames are actually discrete in memory. The external storage space allocated to a process (usually for storing files) is also a virtual address space (contiguous), and the corresponding physical disk storage space may also be discrete

The exokernel allocates unabstracted hardware resources directly to user processes. When a user process frequently accesses its allocated virtual external storage space randomly, since the actual corresponding physical space is discrete, randomly accessing various locations may require a lot of head movement. With exokernel allocation, the process directly gets a contiguous block of physical external storage space, so when randomly accessing various addresses, the distance the head moves is reduced, thereby improving performance

The exokernel can also allocate contiguous physical memory space, in which case what the user sees is the actual physical memory address space.

The exokernel needs to ensure the safety of hardware resource usage, i.e. a process cannot access the space of other processes, and other processes cannot access this process's space
![在这里插入图片描述](/images/csdn/2024/csdn-135725503/image-015-c0382441a8.png)
 Consistency: the address type requested by each process is different (physical address vs virtual address), which requires different handling for subsequent management, so it is also more complex

With virtual address allocation, when a process accesses its own address space, it needs to consult the page table to convert the virtual address to the actual physical address
