# Timer Classification
Hardware timer: determined by the hardware frequency and the size of the trigger limit; there is only one, with high precision
Software timer: implemented based on the hardware timer; precision is greater than or equal to the hardware timer, but since it is implemented in software (code), there is no upper limit on the number that can be implemented
![Image](/images/csdn/2024/csdn-138226026/image-001-089abe4338.png)
# Timer-Related Classification
One-shot: the timer is set for a specific time; when that time is reached it exits, the timer is destroyed and no longer works
Periodic: the timer only needs to be set once, and will be triggered periodically afterwards

Timeout function: the function executed after the timer times out
Interrupt context: the timeout function is executed in interrupt handling; an interrupt is triggered every time the time changes, so naturally there is an opportunity to execute the timeout function each time, meaning very high real-time performance
Task context: the timeout function executes as a process; after timing out it still needs to be scheduled to execute, so real-time performance is poor

# Software Timer Design
## Initialization
The time structure contains a function pointer, the arguments for calling that function, and the scheduled time
During initialization, each time structure is set to empty
![Image](/images/csdn/2024/csdn-138226026/image-003-b8e4849b6c.png)
## Creation
Find a time structure that has not been set yet and assign values to it
![Image](/images/csdn/2024/csdn-138226026/image-004-60b2938c1f.png)
## Deletion
Find the corresponding time structure and set it to empty
![Image](/images/csdn/2024/csdn-138226026/image-005-8fe219d2a2.png)
## Trigger Flow
A timer interrupt occurs, and then in the timer interrupt handler, the function that checks whether to trigger the software interrupt function is triggered; if it matches the scheduled number of a certain software timer, that software timer's handler is invoked
![Image](/images/csdn/2024/csdn-138226026/image-006-f7e63a149d.png)
## Graphical Illustration
Each hardware timer interrupt triggers a tick change, and then timecheck compares the scheduled numbers of the different timers in the timelist, and decides whether to trigger their handlers
![Image](/images/csdn/2024/csdn-138226026/image-007-764ada1505.png)
# Optimization

- Since timecheck needs to loop through and compare one by one each time, if the ones whose time is coming soon are placed at the front, the number of comparisons can be reduced, so sort by timeout time
- A linked list implements space optimization: if an array is used to store software timers, some unused space may be wasted; with a linked list, space is allocated when needed, which saves space
![Image](/images/csdn/2024/csdn-138226026/image-008-7ec453a65f.png)


To further optimize the number of comparisons, the skip list algorithm, similar to binary search, compares from the upper level down to the lower level.
If it is 20, it first reaches 11 and finds it is less than 26, then goes to the lower level, finds it is greater than 17, reaches 17, finds it is less than 26, jumps to the next level, compares with 20 again, and the comparison succeeds
![Image](/images/csdn/2024/csdn-138226026/image-009-632c8cb1b4.png)
