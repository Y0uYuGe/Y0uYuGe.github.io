# Using #ifndef #define #endif
The purpose of #ifndef #define #endif is to prevent a header file from being included repeatedly.

>  Actually, "being included repeatedly" means a header file is included multiple times within the same cpp file. This mistake is often caused by nested includes, or simply by including it multiple times. For example: suppose file a.h contains #include "c.h", while b.cpp has both #include "a.h" and #include "c.h" — this causes c.h to be included repeatedly.



> Consequences of a header file being included repeatedly:
For some header files, repeated inclusion only increases the compiler's workload and causes no major problems — compilation is just a bit less efficient. But for large projects, low compilation efficiency is quite serious.
Repeated inclusion of some header files can cause errors. For example, if a global variable is defined in a header file (although this approach is not recommended, it is indeed allowed by the C specification), repeated inclusion causes a redefinition, which may produce an error.


```c
    下面给一个#ifndef/#define/#endif的格式：

    #ifndef A_H意思是"if not define a.h"  如果不存在a.h

    接着的语句应该#define A_H 然后相关头文件的内容

    最后一句应该写#endif  A_H 结束过程
```
## Usage format

```c
#ifndef <标识> 
#define <标识> 
....
#endif <标识> 
```
In theory, the <identifier> can be **freely named**, but this "identifier" should be unique for each header file. The naming rule for the identifier is generally: the header file name in all uppercase, with underscores added before and after, and the "." in the file name also turned into an underscore. For example, the identifier corresponding to stdio.h is STDIO_H

```c
例如要编写头文件sys.h，需要在sys.h文件开头写上:
#ifndef SYS_H
#define SYS_H
....
#endif SYS_H
那么当#include"sys.h"时会判断是否sys.h已经被导入了
如果此时是第一次#include"sys.h"，那么会执行#define SYS_H，此时_SYS_H被定义了
当第二次#include"sys.h"，由于此时已经定义了SYS_H，所以不会执行#define SYS_H以及之后的内容
```

#  seccomp
[seccomp study](https://cn-sec.com/archives/1263914.html)

The general usage flow of seccomp

ctx = seccomp_init(SCMP_ACT_ALLOW);

```c
seccomp_init(uint32_t def_action)
```

> def_action is the filter's working mode
> seccomp_init is the initialized filtering state; SCMP_ACT_ALLOW is used here, meaning all syscalls are allowed by default. If the initial state is SCMP_ACT_KILL, it means all syscalls are disallowed by default

seccomp_rule_add(ctx, SCMP_ACT_KILL, SCMP_SYS(execve), 0);

```c
int seccomp_rule_add(scmp_filter_ctx " ctx ", uint32_t " action ",int " syscall ",unsigned int " arg_cnt ", " ... ");
```

>   ctx: the filter defined at initialization
> action: the rule mode, the operation performed after a system call is matched; same type as the filter's def_action at initialization
>syscall: the system call number; you can use SCMP_SYS(function name) instead of the concrete call number
>arg_cnt: the number of argument restriction rules needed. The argument-restriction interface of seccomp_rule_add is defined in seccomp.h.in. It mainly involves the argument-fetching operation SCMP_AX and the comparison operation scmp_compare. Only when all these rules are satisfied can this seccomp_rule_add function execute successfully

>If the system call only needs to be matched regardless of argument contents: then arg_cnt=0. If, after matching the system call, whether to execute action is decided based on argument contents: arg_cnt=N (number of rules), followed by N more arguments

seccomp_load(ctx);

> seccomp_load applies the filter and loads the sandbox rules; if seccomp_load is not called, none of the filters above take effect


## Disabling system calls without argument conditions

```c
  seccomp_rule_add(ctx,SCMP_ACT_KILL,SCMP_SYS(execve),0); //add roles into filter
    seccomp_rule_add(ctx,SCMP_ACT_KILL,SCMP_SYS(write),0); //add roles into filter
```
At this point the write and execve system calls are forbidden, regardless of the arguments of the corresponding functions
## Disabling system calls with argument conditions
When there are restriction rules, the corresponding rules are written using the following macros
```c
/**
 * Specify an argument comparison struct for use in declaring rules
 * @param arg the argument number, starting at 0
 * @param op the comparison operator, e.g. SCMP_CMP_*
 * @param datum_a dependent on comparison
 * @param datum_b dependent on comparison, optional
 */
#define SCMP_CMP(...)		((struct scmp_arg_cmp){__VA_ARGS__})

/**
 * Specify an argument comparison struct for argument 0
 */
#define SCMP_A0(...)		SCMP_CMP(0, __VA_ARGS__)

/**
 * Specify an argument comparison struct for argument 1
 */
#define SCMP_A1(...)		SCMP_CMP(1, __VA_ARGS__)

/**
 * Specify an argument comparison struct for argument 2
 */
#define SCMP_A2(...)		SCMP_CMP(2, __VA_ARGS__)

/**
 * Specify an argument comparison struct for argument 3
 */
#define SCMP_A3(...)		SCMP_CMP(3, __VA_ARGS__)

/**
 * Specify an argument comparison struct for argument 4
 */
#define SCMP_A4(...)		SCMP_CMP(4, __VA_ARGS__)

/**
 * Specify an argument comparison struct for argument 5
 */
#define SCMP_A5(...)		SCMP_CMP(5, __VA_ARGS__)



/**
 * Comparison operators
 */
enum scmp_compare {
	_SCMP_CMP_MIN = 0,
	SCMP_CMP_NE = 1,		/**< not equal */
	SCMP_CMP_LT = 2,		/**< less than */
	SCMP_CMP_LE = 3,		/**< less than or equal */
	SCMP_CMP_EQ = 4,		/**< equal */
	SCMP_CMP_GE = 5,		/**< greater than or equal */
	SCMP_CMP_GT = 6,		/**< greater than */
	SCMP_CMP_MASKED_EQ = 7,		/**< masked equality */
	_SCMP_CMP_MAX,
};

/**
 * Argument datum
 */
typedef uint64_t scmp_datum_t;

/**
 * Argument / Value comparison definition
 */
struct scmp_arg_cmp {
	unsigned int arg;	/**< argument number, starting at 0 */
	enum scmp_compare op;	/**< the comparison op, e.g. SCMP_CMP_* */
	scmp_datum_t datum_a;
	scmp_datum_t datum_b;
};

```

```c
 seccomp_rule_add(ctx,SCMP_ACT_KILL,SCMP_SYS(write),1,SCMP_A0(SCMP_CMP_LE,0x10)); //add roles into filter
    /*read的第0个参数为文件描述符，其小于等于0x10时不能使用*/
 seccomp_rule_add(ctx,SCMP_ACT_KILL,SCMP_SYS(read),2,
                    SCMP_A0(SCMP_CMP_LE,0x10),
                    SCMP_A2(SCMP_CMP_GT,0x8)); //add roles into filter此时read有两天规则，第0个参数需要小于等于0x10，第2个参数需要大于0x8,那么将禁止其使用
seccomp_rule_add(ctx, SCMP_ACT_KILL, SCMP_SYS(write),1,SCMP_A2(SCMP_CMP_EQ,0x10));//第2(从0开始数起)个参数等于0x10 此时如果write函数的第2个参数即写入长度等于0x10将使用失败
```
# prctl

```c
int prctl(int option, unsigned long arg2, unsigned long arg3,
          unsigned long arg4, unsigned long arg5);
```

```c
prctl(PR_SET_NO_NEW_PRIVS,1,0,0,0);
```
When option is PR_SET_NO_NEW_PRIVS(38) and arg2 is 1, no privileges can be gained — that is, you can getshell but cannot obtain root privileges
![Image](/images/csdn/2024/csdn-135430526/image-002-cce7c0096f.png)
When option is PR_SET_SECCOMP(22), the effect is the same as the seccomp above, except the format here is slightly different. It also depends on argument 2
**If arg2 is SECCOMP_MODE_STRICT(1), only the system calls read, write, _exit (not exit_group), and sigreturn are allowed
If arg2 is SECCOMP_MODE_FILTER(2), it is filter mode, where the restrictions on syscalls are passed in through arg3 in BPF (Berkeley Packet Filter) form — a pointer to a struct sock_fprog array**

```c
/*
 *	Try and keep these values and structures similar to BSD, especially
 *	the BPF code definitions which need to match so you can share filters
 */
 
struct sock_filter {	/* Filter block */
	__u16	code;   /* Actual filter code */
	__u8	jt;	/* Jump true 符合jmp条件时跳过的规则数*/
	__u8	jf;	/* Jump false不符合jmp条件时跳过的规则数 */
	__u32	k;      /* Generic multiuse field */
};
struct sock_fprog {	/* Required for SO_ATTACH_FILTER. */
	unsigned short		len;	/* Number of filter blocks */
	struct sock_filter *filter;
};
```

The format in filter can actually be divided into two formats, BPF_STMT and BPF_JUMP. Note that the position of k differs between the macro definition's parameters and the corresponding filter: k is always the fourth in filter, but the second in BPF_JUMP(code, k, jt, jf)
```c
#ifndef BPF_STMT
#define BPF_STMT(code, k) { (unsigned short)(code), 0, 0, k }
#endif
#ifndef BPF_JUMP
#define BPF_JUMP(code, k, jt, jf) { (unsigned short)(code), jt, jf, k }
#endif
```
At this point, the value of code in both formats is obtained by OR-ing various macros together


k can also be one of the following macro definitions
```c
/*
 * All BPF programs must return a 32-bit value.
 * The bottom 16-bits are for optional return data.
 * The upper 16-bits are ordered from least permissive values to most,
 * as a signed value (so 0x8000000 is negative).
 *
 * The ordering ensures that a min_t() over composed return values always
 * selects the least permissive choice.
 */
#define SECCOMP_RET_KILL_PROCESS 0x80000000U /* kill the process */
#define SECCOMP_RET_KILL_THREAD	 0x00000000U /* kill the thread */
#define SECCOMP_RET_KILL	 SECCOMP_RET_KILL_THREAD
#define SECCOMP_RET_TRAP	 0x00030000U /* disallow and force a SIGSYS */
#define SECCOMP_RET_ERRNO	 0x00050000U /* returns an errno */
#define SECCOMP_RET_USER_NOTIF	 0x7fc00000U /* notifies userspace */
#define SECCOMP_RET_TRACE	 0x7ff00000U /* pass to a tracer or disallow */
#define SECCOMP_RET_LOG		 0x7ffc0000U /* allow after logging */
#define SECCOMP_RET_ALLOW	 0x7fff0000U /* allow */

/* Masks for the return value sections. */
#define SECCOMP_RET_ACTION_FULL	0xffff0000U
#define SECCOMP_RET_ACTION	0x7fff0000U
#define SECCOMP_RET_DATA	0x0000ffffU


```
The code below defines some things that may be used when writing seccomp BPF code. From the comments we know that in BPF code we can obtain the system call's: system call number, processor architecture, instruction address, and the values of the 6 arguments. What exactly to fetch is decided by the field k, which is equivalent to the offset into the seccomp_data struct: if k=0, nr (the system call number) is fetched; if k=4, the processor architecture is fetched, and so on.

```c
/**
 * struct seccomp_data - the format the BPF program executes over.
 * @nr: the system call number
 * @arch: indicates system call convention as an AUDIT_ARCH_* value
 *        as defined in <linux/audit.h>.
 * @instruction_pointer: at the time of the system call.
 * @args: up to 6 system call arguments always stored as 64-bit values
 *        regardless of the architecture.
 */
struct seccomp_data {
	int nr;
	__u32 arch;
	__u64 instruction_pointer;
	__u64 args[6];
};
```
## Example
K refers to AUDIT_ARCH_X86_64, defined in /include/uapi/linux/audit.h, where a unique identifier is defined for every architecture; 0xc000003e is the value of AUDIT_ARCH_X86_64. For the entire seccomp code, the only external data that may be needed is seccomp_data.

```c

 0001: 0x15 0x00 0x19 0xc000003e  JMP | JEQ after 0x19, R0 == AUDIT_ARCH_X86_64 
 0002: 0x20 0x00 0x00 0x00000000  LD | ABS | Word, R0 = nr
 0003: 0x35 0x00 0x01 0x40000000  JMP | JGE after 0x01, R0 >= 0x40000000 ?
 0004: 0x15 0x00 0x16 0xffffffff  JMP | JEQ after 0x16, R0 == 0xFFFFFFFF ?
 0005: 0x15 0x15 0x00 0x00000000  JMP | JEQ after 0x15, R0 == 0 ?
 0006: 0x15 0x14 0x00 0x00000001  JMP | JEQ after 0x14, R0 == 1 ?
 0007: 0x15 0x13 0x00 0x00000002  JMP | JEQ after 0x13, R0 == 2 ?
```

```c
 line  CODE  JT   JF      K
=================================
 0000: 0x20 0x00 0x00 0x00000004  LD | ABS | Word, R0 = arch
```
code 0x20 is the result of BDF_LD(0x00)|BDF_ABS(0X20)|BOF_W, which copies a word's value into the accumulator via a fixed offset; here k corresponds to offset 4, and the position at offset 4 of seccomp_data happens to be the arch field
```c
 line  CODE  JT   JF      K
=================================
 0001: 0x15 0x00 0x19 0xc000003e  JMP | JEQ after 0x19, R0 == AUDIT_ARCH_X86_64 
```
Here code 15 is the result of BPF_JMP(0x05)|BPF_JEQ(0x10), which is a jump-if-equal instruction: if equal it jumps to the next instruction, otherwise it jumps to the position of the next instruction plus 0x19, comparing the accumulator against the value of k; the accumulator's value is the arch fetched earlier

# seccomp_export_bpf
[Reference](https://veritas501.github.io/2018_05_05-seccomp%E5%AD%A6%E4%B9%A0%E7%AC%94%E8%AE%B0/#How-to-reverse)
The seccomp_export_bpf function can export the configured seccomp in BPF form

```c
//gcc -g simple_syscall_seccomp.c -o simple_syscall_seccomp -lseccomp
#include <unistd.h>
#include <seccomp.h>
#include <linux/seccomp.h>
#include <fcntl.h>
int main(void){

	scmp_filter_ctx ctx;
	ctx = seccomp_init(SCMP_ACT_ALLOW);
	seccomp_rule_add(ctx, SCMP_ACT_KILL, SCMP_SYS(write),1,SCMP_A2(SCMP_CMP_EQ,0x10));
	seccomp_rule_add(ctx, SCMP_ACT_KILL, SCMP_SYS(execve),0);
	seccomp_load(ctx);

	int fd = open("bpf.out",O_WRONLY);
	seccomp_export_bpf(ctx,fd);
	close(fd);


	char * filename = "/bin/sh";
	char * argv[] = {"/bin/sh",NULL};
	char * envp[] = {NULL};
	write(1,"i will give you a shell\n",24);
	write(1,"1234567812345678",0x10);
	syscall(0x4000003b,filename,argv,envp);//execve
	return 0;
}

```
