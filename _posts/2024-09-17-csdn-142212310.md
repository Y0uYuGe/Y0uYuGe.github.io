To create an AF_PACKET socket, the process must have the CAP_NET_RAW capability in a user namespace, which requires root. If the Linux kernel supports unprivileged user namespaces, this allows a non-root user to create a user namespace. Then, in the new namespace, the process can have the CAP_NET_RAW capability even though it is a non-root user in the global namespace.

## Bypassing KASLR


1. **`dmesg | grep 'Freeing SMP'`**:
    - `dmesg` is a command used to print messages from the kernel ring buffer, usually the logs generated by the kernel during system boot and runtime.
    - `grep 'Freeing SMP'` is used to filter specific content from the `dmesg` output, here looking for log lines containing "Freeing SMP".

4. **KASLR (Kernel Address Space Layout Randomization)**:
    - KASLR is a security technique that prevents attackers from predicting the memory layout by randomizing the memory addresses of the kernel and modules.
    - Because KASLR randomizes kernel addresses, it is sometimes disabled in order to obtain consistent kernel addresses.

5. **Timeliness of Kernel Text Addresses**:
    - The kernel address information obtained through `dmesg` (such as the kernel text address) is valid for a period of time after the system boots.
    - This is because the output of `dmesg` is limited; the kernel ring buffer can only store a fixed number of log lines. When the log lines exceed this limit, old logs are overwritten by new ones. Therefore, log information is not kept permanently.

 `tpacket_rcv` is a function in the Linux kernel used to handle received network packets. It performs the receive operation for incoming packets on AF_PACKET sockets. AF_PACKET sockets allow user-space programs to directly access link-layer frames, and they are commonly used in network sniffing and packet-crafting tools such as tcpdump and Wireshark. Below is the detailed workflow and explanation of the function:

### Function Parameters
- `struct sk_buff *skb`: the incoming packet buffer.
- `struct net_device *dev`: the network device that received the packet.
- `struct packet_type *pt`: packet type information, used to bind to a specific protocol.
- `struct net_device *orig_dev`: the original network device.

### Function Workflow

1. **Preliminary checks and variable initialization**:
   - Check whether the packet type is `PACKET_LOOPBACK`; if so, drop it.
   - Get the socket `sock` and the `packet_sock` structure.
   - Check whether the packet comes from the same network namespace; otherwise drop it.

2. **Handling the packet header**:
   - Process the packet header according to the device type and socket type. If the device has header operations and the socket type is not `SOCK_DGRAM`, push the packet header back into the packet. If the packet type is `PACKET_OUTGOING`, pull the network-layer offset.

3. **Packet filtering**:
   - Run the filter (`run_filter`) to decide whether to accept the packet. If the filter result is zero, drop the packet.

4. **Checksum handling**:
   - Set the status flags according to the packet's checksum state.

5. **Truncating the packet**:
   - Truncate the packet length according to the filter result.

6. **Calculating offsets**:
   - Calculate the MAC and network-layer offsets.

7. **Handling the ring buffer**:
   - Check and handle the frame size of the ring buffer. If needed and the buffer is shared, clone or grab the packet.

8. **Locking the receive queue and processing the receive frame**:
   - Lock the socket's receive queue and get the current receive frame. If this fails, drop the packet and count it.
   - Increment the receive head pointer.

9. **Handling the Virtio network header**:
   - If a Virtio network header is present, extract it from the packet and fill it into the receive buffer.

10. **Copying data**:
    - Copy the packet contents into the receive buffer.

11. **Timestamp handling**:
    - Get the packet's timestamp and set it in the receive buffer header.

12. **Setting header fields**:
    - Set the receive buffer header fields according to the different TPACKET versions.

13. **Setting the socket address**:
    - Fill in the `sockaddr_ll` structure with the packet's link-layer information.

14. **Cache coherency handling**:
    - If the architecture implements dcache page flushing, flush the cache to ensure data consistency.

15. **Setting the status and notifying**:
    - Set the receive buffer status and call `sk_data_ready` to notify user space that new data has arrived.

### Error Handling and Packet Release
- If an error occurs during processing, it jumps to the `drop_n_restore` or `drop_n_account` label for error handling and packet release.

The `tpacket_rcv` function is mainly responsible for receiving and processing network packets, copying data into a buffer accessible from user space, and setting the corresponding header information according to the different TPACKET versions. This function involves operations such as packet filtering, checksum handling, timestamp handling, and cache coherency handling, to ensure that packets can be correctly delivered to user space.

The kernel calls the tpacket_rcv() function to receive packets; whenever the kernel receives a new packet, it is supposed to save it into the ring buffer. The key function is __packet_lookup_frame_in_block(), which computes the starting address in the current ring buffer where data can be received. The main work of this function is:

1.  Check whether the currently active memory block has enough space to hold the packet;

2.  If there is enough space, save the packet into the current memory block and return;

3. If there is not enough space, schedule the next memory block and save the packet into the next memory block.

The general flow is as follows
