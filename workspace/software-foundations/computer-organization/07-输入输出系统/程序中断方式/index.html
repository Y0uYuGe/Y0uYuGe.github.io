概述

中断的基本概念

中断隐指令会修改 PC 的值，使其指向中断服务程序 每条指令执行完毕后，在指令周期末尾检查是否有需要处理的中断信号。如果有，则执行中断服务程序（即中断响应）

CPU 运行程序时执行的 JMP 和 Call 指令仍然属于该程序的进程，而中断与原程序不属于同一个进程。

中断请求的分类

原子操作可以一气呵成地执行某些连续的指令；关中断是指即使有外部中断到来，当前指令也继续执行，因此可以辅助 CPU 执行某些需要连续运行的指令

注意不可屏蔽中断

中断请求标记

每个触发器可以记录一位二进制的 0 或 1 中断请求标记接收来自各个设备的中断请求信号

中断判优 - 实现方式

软件实现是按优先级顺序逐个查询 软件比硬件慢

中断判优 - 优先级设置

掉电属于硬件故障 系统调用属于软中断 高速设备优先于低速设备，可以这样理解：尽快响应它的中断请求，因为它速度快，能干更多的事（类似老板先处理高效率员工的事情，让该员工能做更多事） 输入优先于输出，是因为输入设备会更新接口数据缓冲寄存器中的内容，如果其中断没有被尽快响应（数据没能及时取走，输入设备再次输入时，数据缓冲寄存器会被再次更新），就会丢失输入信息。而输出设备的响应可以慢一些，因为它要等 CPU 把数据放入数据缓冲区后才工作——数据放得晚，它就工作得晚，不会造成数据丢失或其他故障 实时设备：响应必须及时、迅速

中断处理过程 - 中断隐指令

此时保存断点一般是存入栈中，通常是内核栈 排队电路的输出是从各个中断信号中选出的一个信号，它对应一个中断源信号。随后由中断向量地址形成部件生成中断向量地址，存放在中断向量地址处的指令可以跳转到中断处理程序的入口地址（中断向量就是中断处理程序的地址）

为什么要采用中断向量地址的形式？如果由中断向量地址形成部件直接生成中断处理程序的地址，那么当中断处理程序的地址发生变化时，就需要修改中断形成部件的电路结构，才能生成相应修改后的中断处理程序地址，非常麻烦。 采用中断向量地址的形式，如果中断处理程序的地址发生变化，只需要修改中断向量地址处 JMP 指令的操作数即可

计算机组成原理 - 程序中断方式的完整流程

程序中断方式的完整流程

首先，CPU 通过执行 IO 指令启动外部设备，然后外部设备就可以开始做准备工作（准备 CPU 想要的数据或信息）。在外部设备准备期间，CPU 可以继续执行原程序的内容 当 IO 设备完成工作后，会向 CPU 发出中断请求，表示自己的准备工作已完成；此时刚执行完的指令对应 K，中断处理完后返回执行第 K+1 条指令

中断服务程序还包括让 IO 设备恢复工作（比如输出 n 个字符时，如果是逐个字符发起中断，那么中断服务程序还要恢复 IO 设备的工作，或者说继续执行之前的 IO 指令，因为它还没执行完），以及让外设准备下一个数据

总结

程序中断方式的完整流程主要包括以下几个步骤：

  1. 中断源发出中断请求。中断源可以是硬件设备（如键盘、鼠标、定时器等），也可以是软件（如系统调用、异常处理等）。

  2. 判断处理器当前是否允许中断，以及该中断源是否被屏蔽。这是为了防止不必要的中断干扰 CPU 的正常工作。

  3. 优先级排队。如果多个中断同时发生，则根据预先设定的优先级决定先处理哪个中断。

  4. 处理器执行完当前指令，或者如果当前指令无法完成，则立即停止当前程序，保护断点地址和处理器当前状态，转去执行相应的中断服务程序。这就是中断响应阶段，包括保存现场和跳转到中断服务程序的入口地址。

  5. 执行中断服务程序。在这一阶段，CPU 处理接收到的中断，比如执行设备驱动程序、管理用户进程等。

  6. 返回原程序继续执行。中断处理完毕后，CPU 返回原来被中断的地方，继续执行原程序。

INTA 信号送到中断控制器，从而让中断控制器得到中断类型号 不同的中断类型对应不同的中断请求输入信号

首先，中断请求寄存器的各个寄存器连接着各个 IO 设备。当 IO 设备发出中断请求时，经控制逻辑 INT 输出到 CPU 的 INTR 接口。若 CPU 处于开中断状态，则通过 INTA 向中断控制器发回反馈信号。随后经过中断控制器的中断判优以及中断服务寄存器的处理，得到中断向量地址，并通过数据总线将中断类型号传给 CPU
