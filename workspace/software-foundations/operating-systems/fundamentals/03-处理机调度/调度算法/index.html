总结

这些调度算法不关心响应时间，也不区分任务的紧急程度 = 交互性差 如果一个系统不关心响应时间，也不区分任务的紧急程度，导致用户交互性差的原因如下：

  • 用户体验差：如果系统不考虑响应时间，用户可能要等很久才能得到反馈，这会让用户感到挫败和不满
  • 效率低：不区分任务的紧急程度可能导致关键任务被延迟，影响整体工作效率 缺乏优先级管理：系统本应根据任务的重要性和紧急程度合理排序，否则可能导致资源浪费和目标错位
  • 交互的机会很少，自然也会使交互性变得很差

早期的批处理系统是一种自动处理程序和数据的方式：用户提交一批作业后不再干预，系统自动运行

操作系统 - 调度算法（二）（时间片轮转、优先级调度、多级反馈队列调度、多级队列调度）

概述

时间片轮转

分时操作系统是一种让多个用户共享一台计算机资源的操作系统；它以时间片轮转的方式为每个用户提供服务 注意它的调度算法不区分任务的紧急程度

时间片大小为 2

注意默认情况下，新到达的进程先进入就绪队列，离开处理器的进程之后再进入就绪队列 P2 上处理器然后离开处理器；此时 P3 也刚好进入就绪队列 此时 P1 上处理器；在这个时间片内，P4 进入就绪队列 P1 的时间片结束，进入就绪队列 P3 上处理器；它在时间片内主动放弃处理器，此时也会发生调度 P2 上处理器 P4 上处理器运行一个时间片，结束后被放回就绪队列 P1 上处理器，在时间片内完成并主动放弃；此时 P4 上处理器 此时由于就绪队列为空，P4 继续运行一个时间片

时间片大小为 5

如果使用先来先服务

先来先服务（FCFS）算法可能导致进程响应时间增加的原因是缺乏优先级考虑：FCFS 算法在选择进程时，只依据进程到达的顺序，而不考虑进程的优先级或所需的服务时间。这意味着一些需要快速响应的短作业，可能因为排在长作业后面而被延迟

思考

多级反馈队列调度算法

在实际应用中也可能是非抢占式的

公平性：每个进程刚到达时都拥有最高优先级（会被优先处理） 及时响应：每个新到达的进程都拥有最高优先级，会很快得到响应 短作业耗时更少：短作业经过的队列更少，相比长作业，它们总共花费的时间也更短 无需提前估计进程的运行时间：因为它不是根据用户定义的时间来决定谁先执行——一切都统一按照队列的流程来，直接执行，所以用户伪造也没用 灵活调整优先级：例如 I/O 密集型进程在当前级别运行完它的时间后，可以把它放回原来的队列，保持它的优先级

饥饿：源源不断到来的短作业可能导致长作业永远得不到服务

例题

P0 进入一级队列；一级队列的时间片大小只有一个时间片。P1 运行一个时间片后还没结束，于是进入下一级队列 此时 P2 到达一级队列。由于此时一级队列不为空，所以处理一级队列；处理一个时间片后，进入下一级队列，排在队尾 此时一级队列为空，所以给二级队列分配一个时间片；二级队列队首的 P1 出队。此时分配的时间是两个时间片；由于 P1 的运行时间还没有完全结束，所以会被放入三级队列

此时二级队列不为空，所以 P2 出队，P2 运行。运行一个时间片后，P3 进入一级队列。此时由于一级队列不为空，P2 进程被 P1 抢占，然后 P3 上处理器运行 P3 运行一个时间片后结束，被换出内存；然后二级队列队首的 P2 继续运行，总共运行两个时间片后完成 此时一级队列和二级队列都为空，所以三级队列中的进程上处理器运行。此时分配的是四个时间片；P1 运行四个时间片后，还需要一个时间片才能完成

由于此时 P1 已经处于最低级别，不能再降到更低一级的队列，只能放回原队列的队尾，等待之后再被调度 然后 P1 只需要用掉它四个时间片中的一个就能完成

总结

多级队列调度算法

进程创建后，会根据其分类插入某个队列中

交互型进程需要及时响应，所以它的优先级高于批处理进程 固定优先级：只要高优先级队列不为空，就先运行高优先级队列；这会导致一个问题，如果系统进程队列里一直有内容，交互型进程就永远得不到响应 时间片划分：把每个时间片划分成多份，分别给每个队列中的某个进程执行，这样在一个时间片内，每种进程都能被响应一次

注意这里每种队列采用的调度方式也不同；以下是一个例子（每个队列也可以采用不同的调度算法） 系统进程队列中仍然有许多不同优先级的进程；此时系统进程队列采用优先级调度，所以优先级更高的进程仍会被选中运行 交互队列采用时间片轮转调度，以保证每个进程都能在一定时间内得到响应 批处理队列：先来先服务，因为不关心响应时间
