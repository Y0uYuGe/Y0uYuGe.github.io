Protobuf 基本使用

这个 protobuf 消息定义（.proto 文件）定义了一个名为 Devicemsg 的消息类型，使用的是 proto2 语法。proto2 是 Google 的 Protocol Buffers（Protobuf）序列化框架的一个版本，主要用于跨平台的数据交换。下面详细解释 Devicemsg 消息结构中的各个字段：

syntax = "proto2";

这一行指定该 .proto 文件使用 protocol buffers 语言的 proto2 版本。Protocol Buffers 支持两个主要的语法版本：proto2 和 proto3，二者在一些行为和特性上有所不同。

message Devicemsg {

这里定义了一个名为 Devicemsg 的消息类型。消息是一组具名字段的集合，用于封装一个数据结构。

required sint64 actionid = 1;

actionid 是一个 sint64 类型的必填字段，字段编号为 1。在 proto2 中，required 关键字表示在任何消息实例中都必须为该字段赋值。sint64 是一种变长整数类型，用于存储有符号 64 位整数，采用变长字节编码（Varint）以节省空间，尤其适合高效存储负数。

required sint64 msgid = 2;

msgid 同样是一个 sint64 类型的必填字段，字段编号为 2，用于存储消息的唯一标识符或其他相关信息。

required sint64 msgsize = 3;

msgsize 字段同样是 sint64 类型的必填字段，字段编号为 3，可能用于表示 msgcontent 字段的字节大小，帮助接收方预先分配缓冲区。

required string msgcontent = 4;

msgcontent 是最后一个必填字段，类型为 string，字段编号为 4。在 protobuf 中，string 类型用于存储变长的文本数据，采用 UTF-8 编码。

如何使用

要使用这个消息类型，需要按照以下步骤进行：

  1. 生成代码：使用 protoc 编译器根据 .proto 文件生成对应语言的源代码。例如，如果你的项目是 C++ 项目，可以运行以下命令生成 C++ 代码：
protoc --cpp_out=. Devicemsg.proto

执行这条正确的命令后，如果 Devicemsg.proto 文件中定义了合法的 protobuf 消息格式，protoc 编译器会执行以下操作：

  1. 解析：首先，protoc 会解析 Devicemsg.proto 文件的内容。该文件包含你定义的所有消息类型及其字段、枚举类型等。

  2. 代码生成：然后，它会根据这些定义自动生成 C++ 源代码文件。通常，对于 .proto 文件中定义的每个消息类型，都会生成对应的 .pb.cc（实现文件）和 .pb.h（头文件）。此外，还会为所有 .proto 文件一并生成 google/protobuf/message.h 等依赖所需的头文件。

  3. 输出位置：由于你使用了 . 作为输出目录，生成的 C++ 源文件会放在当前目录下。如果没有指定输出目录，生成的文件名会基于 .proto 文件的名字；例如，如果 Devicemsg.proto 定义了一个 DeviceMessage 消息类型，你可能会得到两个文件：Devicemsg.pb.cc 和 Devicemsg.pb.h。

  4. 包含头文件：在你的 C++ 源文件中包含生成的头文件，例如 Devicemsg.pb.h。

  5. 创建并操作消息对象：你可以像创建普通类实例一样创建 Devicemsg 对象，设置其字段值，然后对数据进行序列化或反序列化。

    #include "Devicemsg.pb.h"

int main() {
  Devicemsg msg;
  
  msg.set_actionid(12345);
  msg.set_msgid(67890);
  msg.set_msgsize(123); // 假设msgcontent的长度
  msg.set_msgcontent("Hello, this is the message content!");

  // 序列化到字符串
  std::string serialized;
  if (!msg.SerializeToString(&serialized)) {
    std::cerr << "Serialization failed." << std::endl;
    return -1;
  }

  // 反序列化（示例未展示）
  // ...
}

这样，Devicemsg 消息就可以方便地在网络间或进程间传递，保证数据的一致性和效率。

.pb.cc（实现文件）和 .pb.h（头文件）

https://www.cnblogs.com/JmpCliff/articles/17595397.html

.pb.cc（实现文件）和 .pb.h（头文件）是由 Google Protocol Buffers（protobuf）编译器生成的 C++ 源代码文件，用于对你定义的协议消息进行序列化和反序列化。下面详细介绍这两个文件通常包含的内容：

.pb.h（头文件）

  • 消息类型定义：包含你所定义消息类型的 C++ 类声明。该类通常继承自 google::protobuf::Message。类中包含你定义的所有字段的访问器（getter 和 setter），例如 set_field_name() 和 field_name()，以及其他一些用于操作消息实例的方法。

  • 枚举类型：如果你的 .proto 文件定义了枚举类型，这些枚举也会被转换为 C++ 枚举并在头文件中声明。

  • 序列化与反序列化方法声明：提供将消息对象转换为字节流（序列化）以及从字节流恢复消息对象（反序列化）的方法声明，例如 SerializeToString()、ParseFromString() 等。

  • 默认实例：可能会提供一个默认的静态消息实例，用于快速访问消息的默认值。

  • 静态成员函数和变量：用于消息类型标识（例如 .descriptor()）、大小计算等。

.pb.cc（实现文件）

  • 消息类型实现：包含上述头文件中声明的消息类的实现代码，包括构造函数、析构函数、序列化与反序列化逻辑的具体实现以及其他内部处理函数。

  • 枚举类型实现：如果有的话，定义枚举类型成员及相关函数的实现。

  • 描述符初始化：包含 protocol buffer 描述符（Descriptor、EnumDescriptor 等）的创建和注册代码，这些描述符用于运行时反射，使得可以动态获取消息结构信息。

  • 静态变量初始化：实现文件还负责初始化静态变量，这些变量通常与消息类型的元数据相关。

总之，.pb.h 文件提供了用户直接交互的接口，而 .pb.cc 实现了这些接口背后的具体逻辑，包括内存管理、数据转换等。二者结合，使你可以在 C++ 项目中方便地使用 protobuf 定义的数据结构，进行高效的序列化和反序列化操作。

struct  Devicemsg
{
  ProtobufCMessage base;	//占24个字节，固定数据存放关键信息
  int64_t actionid;
  int64_t msgidx;
  int64_t msgsize;
  ProtobufCBinaryData msgcontent;
};

struct ProtobufCMessage {
	/** The descriptor for this message type. */
	const ProtobufCMessageDescriptor	*descriptor;
	/** The number of elements in `unknown_fields`. */
	unsigned				n_unknown_fields;  8个字节
	/** The fields that weren't recognized by the parser. */
	ProtobufCMessageUnknownField		*unknown_fields;
};

struct ProtobufCBinaryData {
	size_t	len;        /**< Number of bytes in the `data` field. */ 8个字节
	uint8_t	*data;      /**< Data bytes. */ 被当做8个字节
};

前十六个字节给了base，用来存放一些关键信息

bytes类型，转化为c语言结构时会变成一个结构体，里面存放长度和内容指针。IDA由于没有内置相关结构信息，将其当做八字节数组进行解析，因此会产生一个有5个记录的错觉，实际上后两个参数是同一个记录内置的两条记录。

打包解题

protoc --python_out=. devicemsg.proto
之后在exp中将其import进去，利用其中的devicemsg()函数（取决于定义的message的名字）创建类型，利用SerializeToString()函数生成字节流。

1. 定义 .proto 文件

创建一个 .proto 文件来定义你的数据结构。例如，创建一个 person.proto 文件：

syntax = "proto3";

package tutorial;

message Person {
  string name = 1;
  int32 id = 2;
  string email = 3;
}

message AddressBook {
  repeated Person people = 1;
}

2. 生成 Python 代码

使用 protoc 编译器根据 .proto 文件生成 Python 代码：

protoc --python_out=. person.proto

这会在当前目录下生成一个 person_pb2.py 文件，其中包含用于序列化和反序列化 protobuf 消息的 Python 类。

3. 使用生成的 Python 代码

现在你可以在 Python 程序中使用这些类来序列化和反序列化数据：

import person_pb2

# 创建一个Person对象
person = person_pb2.Person()
person.id = 1234
person.name = "John Doe"
person.email = "jdoe@example.com"

# 序列化到字节串
data = person.SerializeToString()

# 反序列化回Person对象
new_person = person_pb2.Person()
new_person.ParseFromString(data)

print("Name:", new_person.name)
print("Id:", new_person.id)
print("Email:", new_person.email)

这样，你就可以在 Python 应用中方便地使用 protobuf 进行高效的结构化数据处理。
