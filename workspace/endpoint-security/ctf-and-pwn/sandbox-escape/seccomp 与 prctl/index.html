它可以禁用某些系统调用，只允许某些系统调用

#ifndef #define #endif 的使用

#ifndef #define #endif 的作用是防止头文件被重复包含。

其实“被重复包含”是指一个头文件在同一个 cpp 文件中被包含了多次。这种错误常常是由于嵌套包含造成的，或者干脆就是包含了多次。比如：a.h 文件中有 #include "c.h"，而 b.cpp 中同时有 #include "a.h" 和 #include "c.h"，这就会导致 c.h 被重复包含。

头文件被重复包含的后果： 有些头文件被重复包含只会增加编译器的工作量，不会引起大问题，只是编译效率低一些。但对于大工程来说，编译效率低是件很严重的事。 有些头文件被重复包含会引起错误。比如在头文件中定义了全局变量（虽然不推荐这种做法，但 C 规范确实允许），重复包含会导致重复定义，可能会报错。

    下面给一个#ifndef/#define/#endif的格式：

    #ifndef A_H意思是"if not define a.h"  如果不存在a.h

    接着的语句应该#define A_H 然后相关头文件的内容

    最后一句应该写#endif  A_H 结束过程

使用格式

#ifndef <标识> 
#define <标识> 
....
#endif <标识>

理论上 <标识> 可以自由命名，但每个头文件的这个“标识”应该是唯一的。标识的命名规则一般是：头文件名全部大写，前后加下划线，并把文件名中的“.”也变成下划线。比如 stdio.h 对应的标识就是 STDIO_H

例如要编写头文件sys.h，需要在sys.h文件开头写上:
#ifndef SYS_H
#define SYS_H
....
#endif SYS_H
那么当#include"sys.h"时会判断是否sys.h已经被导入了
如果此时是第一次#include"sys.h"，那么会执行#define SYS_H，此时_SYS_H被定义了
当第二次#include"sys.h"，由于此时已经定义了SYS_H，所以不会执行#define SYS_H以及之后的内容

seccomp

seccomp 学习

seccomp 的一般使用流程

ctx = seccomp_init(SCMP_ACT_ALLOW);

seccomp_init(uint32_t def_action)

def_action 是过滤器的工作模式 seccomp_init 是初始化的过滤状态，这里用的是 SCMP_ACT_ALLOW，表示默认允许所有 syscall。如果初始状态是 SCMP_ACT_KILL，则表示默认不允许所有 syscall

seccomp_rule_add(ctx, SCMP_ACT_KILL, SCMP_SYS(execve), 0);

int seccomp_rule_add(scmp_filter_ctx " ctx ", uint32_t " action ",int " syscall ",unsigned int " arg_cnt ", " ... ");

ctx：初始化时定义的过滤器 action：规则模式，即匹配到系统调用后执行的操作，与初始化时过滤器的 def_action 类型相同 syscall：系统调用号，可以用 SCMP_SYS(函数名) 代替具体的调用号 arg_cnt：需要的参数限制规则数量。seccomp_rule_add 的参数限制接口定义在 seccomp.h.in 中，主要涉及取参数操作 SCMP_AX 和比较操作 scmp_compare。只有这些规则全部满足时，这个 seccomp_rule_add 函数才会执行成功

如果只需匹配系统调用而不管参数内容：则 arg_cnt=0。如果匹配到系统调用后，还要根据参数内容决定是否执行 action：arg_cnt=N（规则数），后面再跟 N 个参数

seccomp_load(ctx);

seccomp_load 应用过滤器，加载沙箱规则；如果不调用 seccomp_load，上面的所有过滤器都不会生效

无参数条件地禁用系统调用

  seccomp_rule_add(ctx,SCMP_ACT_KILL,SCMP_SYS(execve),0); //add roles into filter

prctl

int prctl(int option, unsigned long arg2, unsigned long arg3,
          unsigned long arg4, unsigned long arg5);

prctl(PR_SET_NO_NEW_PRIVS,1,0,0,0);

当 option 为 PR_SET_NO_NEW_PRIVS(38) 且 arg2 为 1 时，无法获得任何权限，也就是说可以 getshell，但无法获得 root 权限 当 option 为 PR_SET_SECCOMP(22) 时，效果与上面的 seccomp 相同，只是这里的格式略有不同，同样取决于参数 2 如果 arg2 为 SECCOMP_MODE_STRICT(1)，则只允许 read、write、_exit（不是 exit_group）和 sigreturn 这几个系统调用 如果 arg2 为 SECCOMP_MODE_FILTER(2)，则为过滤模式，对 syscall 的限制通过 arg3 以 BPF（Berkeley Packet Filter）的形式传入，即一个指向 struct sock_fprog 数组的指针

/*
 *	Try and keep these values and structures similar to BSD, especially
 *	the BPF code definitions which need to match so you can share filters
 */
 
struct sock_filter {	/* Filter block */
	__u16	code;   /* Actual filter code */
	__u8	jt;	/* Jump true 符合jmp条件时跳过的规则数*/
	__u8	jf;	/* Jump false不符合jmp条件时跳过的规则数 */
	__u32	k;      /* Generic multiuse field */
};
struct sock_fprog {	/* Required for SO_ATTACH_FILTER. */
	unsigned short		len;	/* Number of filter blocks */
	struct sock_filter *filter;
};

filter 中的格式其实可以分为 BPF_STMT 和 BPF_JUMP 两种。注意 k 在宏定义参数中的位置与在对应 filter 中的位置不同：k 在 filter 中总是第四个，但在 BPF_JUMP(code, k, jt, jf) 中是第二个

#ifndef BPF_STMT
#define BPF_STMT(code, k) { (unsigned short)(code), 0, 0, k }
#endif
#ifndef BPF_JUMP
#define BPF_JUMP(code, k, jt, jf) { (unsigned short)(code), jt, jf, k }
#endif

此时两种格式中 code 的值都是由各种宏相或得到的

/*
 * All BPF programs must return a 32-bit value.
 * The bottom 16-bits are for optional return data.
 * The upper 16-bits are ordered from least permissive values to most,
 * as a signed value (so 0x8000000 is negative).
 *
 * The ordering ensures that a min_t() over composed return values always
 * selects the least permissive choice.
 */
#define SECCOMP_RET_KILL_PROCESS 0x80000000U /* kill the process */
#define SECCOMP_RET_KILL_THREAD	 0x00000000U /* kill the thread */
#define SECCOMP_RET_KILL	 SECCOMP_RET_KILL_THREAD
#define SECCOMP_RET_TRAP	 0x00030000U /* disallow and force a SIGSYS */
#define SECCOMP_RET_ERRNO	 0x00050000U /* returns an errno */
#define SECCOMP_RET_USER_NOTIF	 0x7fc00000U /* notifies userspace */
#define SECCOMP_RET_TRACE	 0x7ff00000U /* pass to a tracer or disallow */
#define SECCOMP_RET_LOG		 0x7ffc0000U /* allow after logging */
#define SECCOMP_RET_ALLOW	 0x7fff0000U /* allow */

/* Masks for the return value sections. */
#define SECCOMP_RET_ACTION_FULL	0xffff0000U
#define SECCOMP_RET_ACTION	0x7fff0000U
#define SECCOMP_RET_DATA	0x0000ffffU

下面的代码定义了编写 seccomp BPF 代码时可能用到的一些内容。从注释可知，在 BPF 代码中我们可以获取系统调用的：系统调用号、处理器架构、指令地址以及 6 个参数的值。具体取哪个由字段 k 决定，它相当于 seccomp_data 结构体中的偏移：k=0 时取的是 nr（系统调用号），k=4 时取的是处理器架构，以此类推。

/**
 * struct seccomp_data - the format the BPF program executes over.
 * @nr: the system call number
 * @arch: indicates system call convention as an AUDIT_ARCH_* value
 *        as defined in <linux/audit.h>.
 * @instruction_pointer: at the time of the system call.
 * @args: up to 6 system call arguments always stored as 64-bit values
 *        regardless of the architecture.
 */
struct seccomp_data {
	int nr;
	__u32 arch;
	__u64 instruction_pointer;
	__u64 args[6];
};

#include <unistd.h>
#include <seccomp.h>
#include <linux/seccomp.h>
#include <fcntl.h>
int main(void){

	scmp_filter_ctx ctx;
	ctx = seccomp_init(SCMP_ACT_ALLOW);
	seccomp_rule_add(ctx, SCMP_ACT_KILL, SCMP_SYS(write),1,SCMP_A2(SCMP_CMP_EQ,0x10));
	seccomp_rule_add(ctx, SCMP_ACT_KILL, SCMP_SYS(execve),0);
	seccomp_load(ctx);

	seccomp_export_bpf(ctx,fd);
	close(fd);


	char * filename = "/bin/sh";
	char * argv[] = {"/bin/sh",NULL};
	char * envp[] = {NULL};
	write(1,"i will give you a shell\n",24);
	write(1,"1234567812345678",0x10);
	syscall(0x4000003b,filename,argv,envp);//execve
	return 0;
}

对应的 prctl 函数

第一行禁用特权 第二行根据定义的 BPF 建立沙箱

检查

保护全开 查看沙箱规则 首先检查架构，如果不是 ARCH_X86_64 则禁止该系统调用。然后取出系统调用的第二个参数复制给 X，再获取系统调用号。接着判断系统调用号是否与 read、write、fstat、lseek 相同，相同则允许执行。如果都不相同，则判断是否等于 mmap，若是，则判断系统调用的第二个参数是否为奇数，为奇数则禁止，否则允许。如果系统调用号与 mmap 不同，则判断是否等于 mprotect，若是，同样判断第二个参数是否为奇数，奇数禁止，否则允许。如果系统调用号与 mprotect 不同，则判断系统调用号是否等于系统调用的第二个参数，相等则允许该系统调用。否则判断系统调用号是否等于 brk、exit、exit_group，相等则允许，都不相同则禁止该系统调用

思路

注意数组与 var_8 之间还有八个字节，var_8 对应的下标为 201

首先，由于 main 结尾的 ret 指令会返回到 libc_start_main+241 的位置，我们可以用 show 越界显示该地址，对应的数组下标为 203。这样就泄露了 libc 基址，进而得到各种 gadget 的地址 由于我们的目标是读取 flag 文件的内容，所以需要 open 函数，然后 read，再 write。调用 open 系统调用需要 rdx=rax 才能成功 由于要先把文件内容读入内存再通过 write 输出，我们还需要知道内存中的某个位置。此时发现栈上存在一个栈地址，对应数组下标 205。该栈地址减去返回地址得到 0xE0，因此对应的下标为 231 将这样得到的栈地址减去 231*8 即得到数组的起始地址，然后在该位置输入 open 的第一个参数，即 ./flag。注意由于此时函数输入的是整数，输入的字节会以逆序放入内存，而 open 调用时参数是字符串，会从低地址到高地址逐字节转换。所以需要逆序输入 ./flag 的字节，即按 galf/. 的字节输入。

接下来构造 ROP 链即可：首先 open(数组起始地址, 0, 2)，rax=2。这里构造的 rdx 对函数没有作用，只是为了让第二个参数等于 rax 的值，从而能成功调用系统调用。

然后 read(上一步 open 的返回值即 rax 的值, 栈上某区域的地址, 要写入的输入长度)，rax=0。这里需要先把 rax 的值传给 rdi，再将 rax 置为 0。 此时找不到 mov rdi, rax; ret; ，每个 gadget 后面都跟着跳转。我们需要控制跳转目标，使最终能回到 ROP 链。为此需要事先控制 rcx：如果 rcx 中是 pop ; ret gadget 的地址，就仍然可以返回到 mov rdi, rax; call rcx 之后的 gadget（因为 call 会把返回地址压栈，pop 之后 ret 正好落到 mov rdi, rax; call rcx 后面的 gadget 上）。所以需要事先在栈上准备好 pop ; ret gadget 的地址，然后先执行 pop rcx; ret，使 rcx 变为 pop ; ret gadget 的地址。另外两个参数比较容易控制 最后 write(1, read 写入的地址, 输出长度)，rax=1。这里只需修改 rax 和 rdi，rsi 和 rdx 保持不变（与 read 的 rsi、rdx 相同）。最终输出 flag

    r.recvuntil("Here it is: ")

    menu()
    return ret
