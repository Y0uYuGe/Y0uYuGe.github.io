Linux 信号处理

  1. 发生中断或异常时，内核会向相关进程发送信号。
  2. 随后系统切换到内核态，内核执行 setup_fram() 函数，设置用户栈。setup_frame 的主要工作是将保存所有寄存器值及其他重要信息的数据结构压入用户栈（具体内容因架构而异），同时压入信号处理函数的返回地址，即 sigruturn() 的地址。
  3. 接着执行 hand_signal，跳转到用户态运行信号处理函数。
  4. 信号处理函数在用户态执行完毕后，由于返回地址被设为 sigreturn() 系统调用的地址，系统会再次陷入内核，执行 sigreturn()。该系统调用主要负责从先前压入栈中的数据恢复寄存器值及相关内容。系统调用结束后，程序恢复执行。

思路

通过溢出构造 ROP 链：程序没有动态链接库，自身的 gadget 也少得可怜。gadget 不足时，要使用 ret2syscall，就需要让系统调用参数 rax 为 59、rdi 为 /bin/sh 的地址，rsi 和 rdx 为零。
但程序中没有相关的 pop gadget，因此无法通过 ROP 完成系统调用。这时可以使用 SROP，因为 sigreturn 系统调用会执行一系列 pop 指令，让我们有机会设置 execve 的参数。

  1. 首先，rax 很容易设置，设为 execve 的系统调用号即可。
  2. 其次，rdi 必须是 /bin/sh 的地址；程序中找不到 /bin/sh，因此需要把它输入到栈上，再获取它在栈上的地址。
  3. 然后是 rsi 和 rdx，也很简单，都设为 0。

那么，如何输入 /bin/sh 并获取它的地址？
首先需要获得栈上输入区域的起始地址，然后在下一次输入中写入 /bin/sh，再调用 execve 系统调用。

  1. 先让 write 函数输出栈基址。
    write 对应的系统调用要求 rax 为 1、rdi 为 1、rsi 为栈基址，rdx 大于 8。修改 rax 的唯一办法是利用 read 执行后将输入长度存入 rax 的行为。因此，只输入一个字节，且让返回地址从 0x4000B3 开始，最终 write 就会输出栈基址。需要提前布置好返回地址，这样第二次执行 read 时，输入一个字节，修改返回地址的一个字节后，地址就恰好变为 0x4000b3。
  2. 随后 write 输出 rsp 的值。由于此时只能输出，因此返回地址必须在第一次输入时就布置好。获得 rsp 后，就可以将其用于输入函数，输入相应的 sigframe，同时把返回地址设为系统调用地址。由于要进入 sigreturn，read 的输入长度必须等于 15，因此还要等待两次输入。一次输入发送 sigfram 和 /bin/sh，并将返回地址设为再次输入的位置；下一次只输入系统调用地址以及不影响 sigfram 的另外七个字节。这样就会先调用 sigreturn，再调用 execve。

即将执行第一次 ret 时的栈

可以看到，栈内容中包含一个栈上的地址，因此可以泄露栈地址，再把 rsp 设置到泄露出的栈位置。

执行 write 函数时

第一次输入两个 0x4000b0 地址；第二次输入一个字节，将返回地址改为 0x4000b3。

将 rsp 改为泄露出的栈地址

constants.SYS_read 是 read 的系统调用号常量。
write 执行后，程序还会接受一次输入。这次输入先把返回地址改为 0x4000b0，使程序能够再次输入，同时写入为下一次输入预留的返回地址和 sigfram。

接下来的一次输入将返回地址改为系统调用地址，输入字节数为 15，从而触发 sigreturn 系统调用，修改相应寄存器。

此时，rip 为系统调用地址，rsp 为泄露出的栈地址，其他参数则是输入函数的参数。

sigreturn 返回后，执行 rip 指向的输入函数。

输入 /bin/sh 并调用 sigreturn

最后输入 /bin/sh，构造 sigfram，同时将返回地址设为输入函数。
然后输入系统调用地址和 7 个空字节，触发 sigreturn 调用。返回后，rip 指向系统调用；由于 rax 是 execve 的系统调用号，因此可以 getshell。

系统调用回顾

系统调用与普通库函数调用很相似，但系统调用由操作系统内核提供，在内核态运行；普通库函数调用则由函数库或用户提供，在用户态运行。

int execve(const char *filename, char *const argv[], char *const envp[]);

filename 指定要运行的程序文件名；argv 和 envp 分别指定程序的运行参数和环境变量。
